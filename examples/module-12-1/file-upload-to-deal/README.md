# Загрузка файла с формы сайта на Диск и привязка к сделке CRM

Публичная форма на сайте: клиент выбирает файл (например, скан документа) и
ID сделки. Файл сохраняется на «Диске» приложения (архив с правами и
версионированием) и одновременно появляется в таймлайне сделки, чтобы
менеджер увидел его сразу в карточке.

## Файлы

- `crest.php` — минимальный REST-клиент (вебхук-режим)
- `form.php` — публичная HTML-форма загрузки
- `handler.php` — обработчик: валидация, загрузка на Диск, привязка к CRM

## Установка

1. В `crest.php` укажите входящий вебхук `C_REST_WEB_HOOK_URL` с правами
   `disk`, `crm`.
2. Создайте на Диске приложения папку для входящих документов и подставьте
   её ID в `handler.php` → `APP_FOLDER_ID`. Узнать ID папки можно так:
   ```php
   $storage = CRest::call('disk.storage.getforapp');
   $root    = CRest::call('disk.folder.getchildren', ['id' => $storage['result']['ROOT_OBJECT_ID']]);
   // или создать новую подпапку:
   $folder = CRest::call('disk.folder.addsubfolder', [
       'id'   => $storage['result']['ROOT_OBJECT_ID'],
       'data' => ['NAME' => 'Входящие документы с сайта'],
   ]);
   ```
3. Разместите `form.php` и `handler.php` на публичном сервере, откройте
   `form.php` в браузере.

## Почему файл грузится дважды

«Диск» (`disk.folder.*`) и таймлайн CRM (`crm.timeline.comment.add`) —
разные хранилища. REST не даёт метода «прикрепить уже существующий файл
Диска к таймлайну по ID» без повторной передачи содержимого, поэтому:

- копия на Диске — для архива: права доступа, версии, можно шарить ссылкой
  даже после удаления сделки;
- копия в таймлайне — чтобы файл сразу был виден в карточке сделки без
  перехода на Диск.

Если нужна только видимость в карточке сделки без отдельного архива —
достаточно одного вызова `crm.timeline.comment.add` с полем `FILES`
(см. пример в `topics/module-12-1.md`).

## Ключевые моменты для собеседования

- `disk.folder.uploadfile` принимает `fileContent` как `[имя, base64]`.
- Лимит на `fileContent` через REST — на практике безопасно до ~15-20 МБ,
  для больших файлов нужен другой путь загрузки (см. теорию 12.1).
- Перед загрузкой всегда проверяется существование сделки
  (`crm.deal.get`), чтобы не плодить файлы без привязки.
- При ошибке привязки к таймлайну файл на Диске не теряется — его ID
  возвращается в сообщении об ошибке для ручной донастройки.
