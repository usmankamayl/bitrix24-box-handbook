# Дедупликация лидов при импорте из CSV

Импорт лидов из `leads.csv` (формат `name;phone;email`) с двойной проверкой
дублей — внутри самого файла и в существующем CRM — и батчированной отправкой
`crm.lead.add` (до 50 команд в одном `batch`-запросе, что считается одним
запросом с точки зрения rate limit).

## Файлы

- `crest.php` — минимальный REST-клиент (вебхук-режим)
- `import.php` — скрипт импорта (консольный, `php import.php leads.csv`)

## Установка

1. Создайте входящий вебхук с правами `crm`, укажите его в `crest.php`.
2. Подготовьте `leads.csv` в формате `Имя;+79991234567;test@mail.ru` (разделитель — `;`).
3. Запустите `php import.php leads.csv`.

## Ключевые моменты для собеседования

- **`crm.duplicate.findbycomm` — тот же механизм, что использует штатный контроль дублей в интерфейсе.** Он сам нормализует телефон (`8 (999)`, `+7 999`, `9991234567` — всё один номер), поэтому не нужно писать свой нормализатор *для запроса* (нормализация внутри скрипта нужна только для сравнения строк внутри CSV).
- **Проверка дублей в CRM отдельно от дублей внутри файла** — кандидат, который проверяет только CSV, пропускает ситуацию "этот лид уже есть в базе с прошлого импорта".
- **`batch` — один запрос с точки зрения rate limit**, даже если внутри 50 команд. 10 000 лидов импортируются ~200 батчами, а не 10 000 отдельных вызовов.
- **`PHONE` — массив коммуникаций**, а не строка: `[{VALUE, VALUE_TYPE}]`. Новички часто слать `PHONE => '...'` и получают лид без телефона.
