# Отчёт по закрытым сделкам менеджеров за месяц

Сводный отчёт "менеджер — количество и сумма успешно закрытых сделок за
период" через `crm.deal.list` с фильтрами по семантике стадии и диапазону
`CLOSEDATE`, с автопагинацией и batch-получением имён менеджеров.

## Файлы

- `crest.php` — минимальный REST-клиент (вебхук-режим)
- `report.php` — скрипт отчёта (консольный, `php report.php [from] [to]`)

## Установка и запуск

1. Создайте входящий вебхук с правами `crm` и `user`, укажите его в `crest.php`.
2. Запустите `php report.php` — отчёт за текущий месяц; или `php report.php 2026-10-01 2026-11-01` — за произвольный период.

## Ключевые моменты для собеседования

- **`STAGE_SEMANTIC_ID = 'S'`, а не список `STAGE_ID`.** Если добавят новую воронку или переименуют стадию — отчёт не сломается, в отличие от жёстко зашитого `STAGE_ID = 'WON'` или `'C2:WON'`.
- **`'start' => -1` — автопагинация** в новом REST API. Bitrix24 сам итерирует страницы; писать цикл по `next` в новом коде не нужно.
- **Группировка делается на PHP, а не в запросе.** `crm.deal.list` не поддерживает SQL-агрегацию (`GROUP BY`), поэтому суммирование выполняется в цикле по выборке.
- **Имена менеджеров — одним batch `user.get`**, а не N отдельных запросов. При 50 менеджерах это 1 запрос вместо 50.
- **Для большого объёма (сотни тысяч сделок) `crm.deal.list` не подходит** — на собеседовании стоит сказать это честно и предложить либо BI-коннектор, либо прямой запрос к реплике БД (коробка), либо собственную агрегирующую таблицу, пополняемую обработчиком `OnAfterCrmDealUpdate`.

Подробный теоретический разбор — в `topics/module-13-4.md`, задача 2.
