# Задача 1. Трассировка запроса и цифры — решение

## Задание

Снять фазы запроса на живой коробке, доказать, что `OnAfterEpilog` не влияет на
HTML, и показать, что при выключенной буферизации `SetPageProperty()` после
шапки перестаёт работать.

## Файлы

Готовый инструмент — в `../../request-trace/`:

```
local/php_interface/init.php    → /local/php_interface/init.php
local/php_interface/trace.php   → /local/php_interface/trace.php
local/trace-page.php            → /trace-page.php
```

Отдельного кода эта задача не требует: решение — это инструмент плюс два
эксперимента ниже.

## Как запустить

1. Скопировать три файла, открыть `/trace-page.php?bx_trace=Y` под администратором.
2. Внизу страницы — таблица фаз: `BX_STATE`, время от старта, дельта, память.
3. Открыть `/upload/bx_trace_last.log` — там `OnAfterEpilog`.

## Что должно получиться

| Фаза | `BX_STATE` | Комментарий |
|---|---|---|
| `init.php` | `PB` | пролог ещё идёт, `$USER` может быть не восстановлен |
| `OnBeforeProlog` | `PB` | в старых сборках строки не будет — это нормально |
| `OnProlog` | `PB` | вызывается внутри `CMain::PrologActions()` |
| `OnEpilog` | `EB` | буфер открыт |
| `OnBeforeEndBufferContent` | `EB` | перед сборкой отложенных колбэков |
| `OnEndBufferContent` | `EB` | здесь правится HTML |
| `OnAfterEpilog` | `EV` | только файл лога, в HTML не попадёт |

Ориентиры по числам (демо-коробка, страница через шаблон): пролог — единицы
миллисекунд на пустой странице и десятки на странице с компонентами; доля
пролога в общем времени 30–70 % в зависимости от веса контента. Абсолютные
цифры у тебя будут свои — важны **дельты между фазами**, а не сами значения.

## Эксперимент 1: `OnAfterEpilog` не меняет HTML

Добавить в обработчик `OnAfterEpilog` строку:

```php
AddEventHandler('main', 'OnAfterEpilog', static function (): void {
    echo '<!-- AFTER_EPILOG_MARK -->';
});
```

Открыть страницу и поискать в исходнике `AFTER_EPILOG_MARK`. Его **нет**: ответ
уже отдан (`echo $r` в эпилоге выполнен), а `echo` после этого уходит в пустоту
или в закрытый буфер. Событие при этом сработало — видно по файлу лога.

Вывод: править HTML можно только в `OnEndBufferContent` (или раньше, в
`OnEpilog`, пока буфер не сброшен), но не в `OnAfterEpilog`.

## Эксперимент 2: выключение буферизации ломает page properties

1. Настройки модуля `main` → «Буферизация вывода» (`buffer_content`) → `N`.
2. Открыть `/trace-page.php` (без `bx_trace`), посмотреть исходник `<head>`.
3. Вернуть `Y`, открыть снова.

| Режим | `<meta name="description">` |
|---|---|
| `buffer_content = Y` | содержит текст из `SetPageProperty('description', ...)` |
| `buffer_content = N` | пустой или отсутствует |

Причина: при `Y` `ShowMeta()` регистрирует отложенный колбэк, который считается
в конце запроса, — поэтому `SetPageProperty()`, вызванный после шапки, успевает.
При `N` `AddBufferContent()` печатает сразу: `<head>` уже собран, и позднее
свойство ни на что не влияет.

Побочный эффект, который стоит увидеть: при `N` перестают работать и
`SetTitle()` после шапки, и `header()` после вывода.

## Edge cases

- **Композит включён** — страница может отдаваться из кеша до пролога: в таблице
  будет только `OnEndBufferContent` или вообще ничего. Это не ошибка
  инструмента, а другой путь запроса.
- **Кеш компонентов** — второй запрос покажет меньше времени в теле страницы,
  но пролог останется тем же: он не кешируется.
- **`OnBeforeProlog` отсутствует** — в части сборок событие не объявлено;
  обработчик просто не вызовется.
- **Не админ** — таблица не появится: права проверяются внутри
  `OnEndBufferContent`.

## Что здесь важно понять, а не скопировать

- Порядок фаз и то, что `BX_STATE` — это реальные состояния, а не метки «на глаз».
- Отложенный вывод: `<head>` собирается в конце, поэтому `SetTitle()` после
  шапки работает — но только пока включена буферизация.
- `OnAfterEpilog` — про побочные эффекты, не про контент.
