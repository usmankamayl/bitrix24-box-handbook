# Задача 3. Страница сделки: 404, свойства, безопасный редирект — решение

## Задание

`/deal.php`: публичная страница через шаблон сайта; корректный `404` для
несуществующей/чужой сделки, свойства страницы, хлебные крошки, безопасный
`?backurl=`.

## Файлы

```
deal.php  →  /deal.php   (корень сайта)
```

## Как проверить

```bash
# 200 + правильные <title> и <meta name="description">
curl -s -i "http://box.local/deal.php?id=1" | head -20
curl -s "http://box.local/deal.php?id=1" | grep -E '<title>|name="description"|name="robots"'

# 404 — нет такой сделки
curl -s -I "http://box.local/deal.php?id=999999" | head -1
curl -s "http://box.local/deal.php?id=999999" | grep -E '<title>|name="robots"'

# 404 — id не число
curl -s -I "http://box.local/deal.php?id=abc" | head -1

# Редирект не уводит на чужой хост
curl -s -I "http://box.local/deal.php?id=1&backurl=//evil.com" | grep -i location
curl -s -I "http://box.local/deal.php?id=1&backurl=/\evil.com" | grep -i location
curl -s -I "http://box.local/deal.php?id=1&backurl=https://evil.com" | grep -i location

# Разрешённый редирект
curl -s -I "http://box.local/deal.php?id=1&backurl=/crm/deal/" | grep -iE 'HTTP/|location'
```

Ожидаемо: на все три «злых» `backurl` — **нет** заголовка `Location` (страница
отдаётся как обычно), на `/crm/deal/` — `302` и `Location: /crm/deal/`.

## Почему решение такое

- **`404` до шапки.** `CHTTP::SetStatus()` должен выполниться до вывода: он
  посылает заголовок и запоминает статус, а композитный сайт кеширует только
  ответы `200` (`Page::isCacheable()` смотрит `CHTTP::GetLastStatus()`).
  `ERROR_404` в актуальном ядре никто не проверяет — это наследие старого
  HTML-кеша; ставить можно, полагаться нельзя.
- **Шаблон для 404 отдаётся.** Это осознанно: пользователь видит нормальную
  страницу с навигацией, а не белый экран. Плохо другое — отдавать `200`.
- **`SetTitle()` и `SetPageProperty()` после шапки.** Работает из-за отложенного
  вывода: `<title>` и `<meta>` собираются при сбросе буфера в `FinalActions()`.
  Ломается только `RestartBuffer()` — он чистит отложенные колбэки (см. задачу 1).
- **`robots = noindex, nofollow`** на 404: страница-ошибка не должна попадать в
  индекс, иначе поисковик заменит ею нормальные URL.
- **`ctype_digit`, а не `(int)`.** `(int)'12abc'` даёт `12` — тихо превращает
  мусор в валидный ID. `ctype_digit` требует, чтобы строка была числом целиком.
- **`404` вместо `403`** для чужой сделки: `403` — оракул существования.
- **Редирект после шапки.** До пролога не загружены `$APPLICATION`, `CHTTP` и
  `LocalRedirect()` — это часть ядра. Заголовки при этом ещё не ушли: вывод
  буферизован.

## Почему белый список, а не «проверка на http»

Векторы open redirect, которые проходят наивные проверки:

| Вход | Что делает наивная проверка | Почему опасно |
|---|---|---|
| `//evil.com` | «не начинается с http — значит локальный» | protocol-relative URL: браузер уходит на `evil.com` |
| `/\evil.com` | «начинается со слеша — локальный» | браузеры нормализуют `\` в `/` → `//evil.com` |
| `https://evil.com` | отсекается по `http` | — |
| `/%0d%0aLocation:%20https://evil.com` | «локальный путь» | внедрение заголовка в старых сборках |
| `/crm/../..//evil.com` | «начинается с `/crm/`» | нормализация пути ломает префикс |

Поэтому проверка идёт от **разрешённого**, а не от запрещённого: только
относительный путь, только из списка префиксов, только после отсечения
управляющих символов и `//`. Всё остальное — молча на главную (в решении —
просто не редиректим).

`LocalRedirect()` при `$skip_security_check = false` тоже имеет внутренние
проверки [проверить в своей версии], но полагаться на них как на единственную
защиту нельзя: whitelist остаётся обязательным.

## Альтернативы и когда они лучше

| Вариант | Когда лучше | Цена |
|---|---|---|
| Белый список префиксов (выбрано) | известный набор разделов | надо поддерживать список |
| Разрешить только «свой хост» через `parse_url` + `$_SERVER['HTTP_HOST']` | много разделов, динамические URL | сложнее, легко ошибиться с портом/поддоменами |
| Хранить `backurl` в сессии, а в URL передавать только ключ | максимально безопасно | лишний шаг, нужен жизненный цикл ключа |
| Не редиректить вообще | формы/действия | хуже UX |

## Edge cases

**Покрыто:** несуществующий ID, нечисловой ID, массивы вместо строк
(`?id[]=1`, `?backurl[]=x`), чужая сделка, «злые» `backurl`,
`backurl` на разрешённый раздел, 404 без записи в HTML-кеш.

**Не покрыто (осознанно):**

- **Композитный сайт**: 404 не кешируется (статус не 200), но если статус не
  выставлен — закешируется как обычная страница `200`. Проверять с включённым
  композитом: это и есть тест «статус реально уходит».
- **`backurl` с якорем** (`/crm/#tab`) — проходит, это нормально.
- **Локализация** заголовков — текст захардкожен, в проде через `GetMessage()`.
- **SEO-canonical** для страницы — не реализован; для публичных сущностей нужен.

## Что здесь важно понять, а не скопировать

- `404` — это не «страница не нашлась», а решение: HTTP-код + `robots: noindex`.
- Свойства страницы работают после шапки только благодаря буферу.
- Безопасный редирект строится белым списком; чёрный список обходится всегда.
