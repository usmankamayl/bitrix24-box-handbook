# Антипаттерн: AJAX через `header.php`

Файл: `local/ajax/deal-status-bad.php` → `/local/ajax/deal-status-bad.php`.

Задача та же, что в `../ajax-endpoint/`: вернуть статус сделки. Реализация —
типовая ошибка новичка и, к сожалению, частая в legacy-проектах.

## Разбор: ошибка → причина → последствие

| № | Ошибка | Причина | Последствие |
|---|---|---|---|
| 1 | `require header.php` в JSON-эндпоинте | «так же делают страницы» | в ответе HTML-шапка и подвал, `json_decode` у клиента падает; полный рендер шаблона и меню на каждый AJAX |
| 2 | `define('NOT_CHECK_PERMISSIONS', true)` после пролога | непонимание, что константы читаются в прологе | не работает вообще; а если перенести в начало — отключает проверки прав ядра, и доступ держится только на честном слове |
| 3 | `$_GET['deal_id']` без валидации | «PHP сам разберётся» | warning при отсутствии параметра, `(int)`-приведение отсутствует, в запрос уходит произвольная строка; на legacy-API это прямой SQL injection |
| 4 | нет `$USER->IsAuthorized()` и `check_bitrix_sessid()` | «эндпоинт внутренний» | IDOR: любой знающий URL читает чужие сделки; CSRF: сторонний сайт может дёрнуть метод от имени пользователя |
| 5 | нет проверки `$deal` на `false` | забыли | warning в лог, клиент получает `{"title":null}` вместо 404 |
| 6 | нет `Content-Type: application/json` | «и так работает» | браузер и часть клиентов трактуют ответ как HTML; ошибки парсинга на фронте |
| 7 | вывод до `header()` | шаблон напечатан первым | `CHTTP::SetStatus()` и `LocalRedirect()` уже не работают: «headers already sent» |
| 8 | `die()` вместо `FinalActions()` | «так короче» | эпилог не выполняется: почтовые события остаются в `b_event` и уходят позже (задержка, не потеря), БД не закрывается штатно |

## Что должно быть вместо этого

Смотри `../ajax-endpoint/local/ajax/deal-status.php` — тот же контракт, но без
шаблона, с проверкой метода, авторизации, `sessid`, валидацией, кодами 401/403/404/405
и `FinalActions()` с последующим `exit`.

## Как убедиться, что дефект реален

```bash
curl -i "http://box.local/local/ajax/deal-status-bad.php?deal_id=1"
```

В ответе будет `<!DOCTYPE html>` и JSON где-то в середине, `HTTP/1.1 200` даже для
несуществующей сделки. Сравни с ответом эталонного эндпоинта — разница видна
в первых трёх строках.
