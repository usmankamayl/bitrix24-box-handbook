# Проверка подписи входящего вебхука и разграничение прав

Обработчик привилегированного действия «Экспорт карточки сделки» (контакт +
сумма сделки), вызываемого кнопкой-размещением из интерфейса CRM. Доступ
проверяется на двух независимых уровнях: подлинность запроса и права
конкретного пользователя.

## Файлы

- `crest.php` — минимальный REST-клиент (вебхук-режим)
- `access_control.php` — проверка `application_token` и роли пользователя
  (`user.access`)
- `export_handler.php` — сам обработчик экспорта

## Установка

1. В `crest.php` укажите входящий вебхук `C_REST_WEB_HOOK_URL` с правами
   `crm`, `user`.
2. В `export_handler.php` подставьте реальный `APPLICATION_TOKEN` (из
   настроек вебхука/приложения на портале) и коды групп в
   `ALLOWED_GROUP_CODES`, которым разрешён экспорт.
3. Подключите `export_handler.php` как обработчик размещения
   (placement, см. модуль 9.2) на кнопку в карточке сделки.

## Почему две проверки, а не одна

- **`application_token`** отвечает на вопрос «этот HTTP-запрос реально
  от Bitrix24?». Без него любой, кто узнал URL обработчика, мог бы
  дёргать его напрямую, подделав `deal_id` и `user_id`.
- **Проверка роли (`user.access`)** отвечает на другой вопрос: «а ИМЕННО
  этому пользователю разрешено это действие?». Запрос может быть абсолютно
  подлинным (реальный пользователь кликнул кнопку в интерфейсе Bitrix24),
  но у рядового менеджера может не быть прав на выгрузку чувствительных
  данных — это бизнес-уровень, а не вопрос подлинности запроса.

Обе проверки обязательны и независимы: подлинность запроса не заменяет
проверку прав, а проверка прав бессмысленна, если сам запрос подделан.

## Ключевые моменты для собеседования

- `hash_equals()` вместо `===` для сравнения токенов — защита от
  timing-атаки.
- `user.access` возвращает список кодов доступа пользователя (`G2`, `G5`
  и т.п.) — ровно то же, что используется при настройке прав на разделы.
- Все отказы в доступе логируются (`security.log`) — для расследования
  попыток несанкционированного доступа.
- Принцип наименьших привилегий применяется дважды: у вебхука —
  минимальный набор методов REST, у пользователя — минимальный набор
  действий в интерфейсе.
