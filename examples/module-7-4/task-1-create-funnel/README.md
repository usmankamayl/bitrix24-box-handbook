# Задача 1: Создание воронки с кастомными стадиями

## 📋 Описание

Создание новой воронки продаж "VIP-клиенты" с 6 пользовательскими стадиями, настройка цветов и семантики для каждой стадии.

## 🎯 Цель

Научиться:
- Создавать новые воронки через REST API
- Добавлять кастомные стадии с уникальными ID
- Настраивать цвета и семантику стадий
- Создавать сделки в новой воронке

## 🏗️ Структура воронки

### Стадии процесса (process):

1. **Первичный контакт** (`FIRST_CONTACT`)
   - Цвет: #2FC6F6 (синий)
   - Знакомство с VIP-клиентом

2. **Анализ потребностей** (`NEEDS_ANALYSIS`)
   - Цвет: #9B59B6 (фиолетовый)
   - Глубокий анализ бизнес-потребностей

3. **Персональное предложение** (`PERSONAL_OFFER`)
   - Цвет: #FF6B00 (оранжевый)
   - Индивидуальное коммерческое предложение

4. **Согласование условий** (`NEGOTIATION`)
   - Цвет: #FFA900 (желтый)
   - Переговоры и согласование особых условий

### Финальные стадии:

5. **Контракт подписан** (`CONTRACT_SIGNED`)
   - Цвет: #06D800 (зеленый)
   - Семантика: success
   - Успешное завершение

6. **Отказ** (`DECLINED`)
   - Цвет: #FF5752 (красный)
   - Семантика: failure
   - Клиент отказался

## 🔍 Ключевые моменты

### 1. Формат ENTITY_ID

```php
'ENTITY_ID' => "DEAL_STAGE_{$categoryId}"
```

- Для воронки 0: `DEAL_STAGE_0`
- Для воронки 1: `DEAL_STAGE_1`
- Для воронки 2: `DEAL_STAGE_2`

### 2. Формат ID стадии

```php
$stageId = "C{$categoryId}:{$statusId}";
```

Примеры:
- `C2:FIRST_CONTACT` — стадия в воронке 2
- `C2:CONTRACT_SIGNED` — финальная стадия в воронке 2

### 3. Семантика стадий

```php
'SEMANTICS' => 'process'  // Рабочая стадия
'SEMANTICS' => 'success'  // Успешное завершение
'SEMANTICS' => 'failure'  // Провал
```

### 4. Цветовая схема

Используйте HEX-цвета для визуального разделения стадий:
- **Синий/Голубой** (#2FC6F6) — начальные стадии
- **Фиолетовый** (#9B59B6) — аналитика
- **Оранжевый** (#FF6B00) — активные действия
- **Желтый** (#FFA900) — переговоры
- **Зеленый** (#06D800) — успех
- **Красный** (#FF5752) — провал

## 📊 Проверка в Bitrix24

После выполнения скрипта:

1. Откройте **CRM → Сделки**
2. В верхней части найдите выбор воронки
3. Выберите **VIP-клиенты**
4. Увидите тестовую сделку на стадии "Первичный контакт"
5. Можете перетаскивать сделку между стадиями в канбан-режиме

## 🎓 Что вы изучите

### API методы:

- `crm.dealcategory.add` — создание воронки
- `crm.dealcategory.get` — получение информации о воронке
- `crm.dealcategory.stage.add` — добавление стадии
- `crm.dealcategory.stage.list` — список стадий воронки
- `crm.deal.add` — создание сделки в воронке

### Концепции:

- **CATEGORY_ID** — идентификатор воронки
- **STATUS_ID** — идентификатор стадии (без префикса)
- **STAGE_ID** — полный ID стадии (с префиксом воронки)
- **SEMANTICS** — тип стадии (process/success/failure)

## ⚠️ Важные замечания

1. **Уникальность STATUS_ID**: Внутри одной воронки не может быть двух стадий с одинаковым `STATUS_ID`

2. **Финальные стадии**: Рекомендуется всегда иметь минимум одну стадию с семантикой `success` и одну с `failure`

3. **Сортировка**: Используйте шаг 10 (10, 20, 30...), чтобы было место для вставки новых стадий

4. **ENTITY_ID**: Формат строгий — `DEAL_STAGE_{CATEGORY_ID}`

5. **Удаление воронки**: При удалении все сделки переместятся в воронку по умолчанию!

## 🔧 Расширение функционала

### Добавление новой стадии

```php
CRest::call('crm.dealcategory.stage.add', [
    'fields' => [
        'ENTITY_ID' => 'DEAL_STAGE_2',
        'STATUS_ID' => 'NEW_STAGE',
        'NAME' => 'Новая стадия',
        'SORT' => 35, // Между 30 и 40
        'COLOR' => '#3498DB',
        'SEMANTICS' => 'process'
    ]
]);
```

### Изменение цвета стадии

```php
CRest::call('crm.dealcategory.stage.update', [
    'id' => 'C2:FIRST_CONTACT',
    'fields' => [
        'COLOR' => '#1ABC9C' // Новый цвет
    ]
]);
```

### Переименование стадии

```php
CRest::call('crm.dealcategory.stage.update', [
    'id' => 'C2:NEEDS_ANALYSIS',
    'fields' => [
        'NAME' => 'Детальный анализ требований'
    ]
]);
```

## 🐛 Возможные ошибки

### Ошибка: "Stage with this STATUS_ID already exists"

**Причина**: Стадия с таким `STATUS_ID` уже существует в воронке

**Решение**: Используйте другой `STATUS_ID` или удалите существующую стадию

### Ошибка: "Invalid ENTITY_ID format"

**Причина**: Неверный формат `ENTITY_ID`

**Решение**: Используйте формат `DEAL_STAGE_{CATEGORY_ID}`, например `DEAL_STAGE_2`

### Ошибка: "Category not found"

**Причина**: Воронка с указанным ID не существует

**Решение**: Проверьте существование воронки через `crm.dealcategory.list`
