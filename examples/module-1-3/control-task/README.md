# Контрольное задание. Найти дефекты в агенте очереди

**Задание.** В `broken.php` — рабочий на вид агент разбора очереди писем.
Найдите в нём шесть поведенческих дефектов: каждый проявится в проде, но не
при первом запуске на тестовой таблице. Дефекты в коде не помечены.

Порядок: прочитать `broken.php` → сформулировать «что именно случится и когда»
→ сверить с разбором ниже → посмотреть `fixed.php`.

## Файлы

```
install.sql            ->  выполнить в БД инсталляции
ControlQueueTable.php  ->  /local/php_interface/classes/Agents/ControlQueueTable.php
broken.php             ->  /local/tools/practice-1.3-control/QueueControlAgent.php (дефектная версия)
fixed.php              ->  то же место вместо broken.php (эталон)
check.php              ->  /local/tools/practice-1.3-control/check.php
```

Один и тот же класс в двух файлах — специально: разница только в дефектах.
Поэтому `check.php` подключает один из них по аргументу.

```bash
mysql -u root -p b24 < install.sql
cp -r control-task <DOCUMENT_ROOT>/local/tools/practice-1.3-control/
php -f <DOCUMENT_ROOT>/local/tools/practice-1.3-control/check.php broken
php -f <DOCUMENT_ROOT>/local/tools/practice-1.3-control/check.php fixed
```

## Дефект 1. Имя агента собирает вспомогательный метод

```php
return self::getAgentName();          // в execute()
private static function getAgentName(): string { return __METHOD__ . '();'; }
```

`__METHOD__` внутри `getAgentName()` — это
`MyCompany\Agents\QueueControlAgent::getAgentName`. Ядро записывает эту строку в
`b_agent.NAME` и выполняет её. Следующий запуск вызывает **геттер имени**, тот
возвращает то же самое, и так каждый раз.

**Последствие:** `LAST_EXEC` обновляется, ошибок в журнале нет, письма не
отправляются никогда. Дефект невидим по логам — виден только по `NAME` в
`b_agent` и по тому, что работа не делается.
**Условие:** всегда; заметно со второго запуска.
**Исправление:** `AGENT_NAME` — константа, `execute()` возвращает её; имя
рабочей точки входа строит сам рабочий метод (`return '\\' . __METHOD__ . '();'`).

## Дефект 2. `return;` при пустой очереди

```php
if ($rows === []) {
    return;
}
```

**Последствие:** ядро трактует пустой результат как «агент больше не нужен» и
удаляет запись из `b_agent`. Первый же запуск на пустой очереди — и агент
исчез. Второй сценарий того же дефекта — `return;` внутри `catch`.
**Условие:** пустая очередь (типичное состояние сразу после установки) или
любая пойманная ошибка.
**Исправление:** `return self::AGENT_NAME;` в любом исходе, включая
исключения; сам `execute()` оборачивает работу в `try/catch (\Throwable)`.

## Дефект 3. Нет ограничения объёма

`getList()` без `limit`, цикл по всем строкам, без бюджета времени.

**Последствие:** на 20 000 строк агент работает минуты. На хитах это время
ждёт посетитель, а параллельный запрос получает таймаут; на cron — наложение
процессов и рост нагрузки на БД.
**Условие:** очередь выросла после сбоя рассылки или импорта.
**Исправление:** `BATCH_SIZE` + `MAX_RUNTIME_SECONDS`, остаток — следующим
запуском.

## Дефект 4. `catch (\Exception)` вместо `\Throwable`

**Последствие:** `TypeError`, `Error`, `DivisionByZeroError` не ловятся —
исключение уходит наружу, агент завершается аварийно, строка остаётся в
промежуточном состоянии, а расписание не пересчитано.
**Условие:** неверный тип в данных из внешнего источника (`null` вместо
строки, массив вместо скаляра) — то есть в реальной эксплуатации рано или
поздно.
**Исправление:** `catch (\Throwable $error)`; в `catch` фиксировать ошибку и
переводить строку в `new`/`error`, а не бросать её как есть.

## Дефект 5. `sent` ставится до отправки

```php
ControlQueueTable::update($id, ['STATUS' => 'sent']);
try { Event::send([...]); } catch (...) { ... }
```

**Последствие:** падение процесса между `update` и `Event::send()` (или
исключение, которое не ловится — см. дефект 4) оставляет строку в `sent` без
письма. Повторной попытки не будет: выборка берёт только `new`.
**Условие:** любая ошибка отправки или обрыв процесса.
**Исправление:** статус `processing` на время работы, `sent` — только после
успешного `Event::send()`.

## Дефект 6. Результат отправки не проверяется, попытки не считаются

`Event::send()` не бросает исключение на неуспех: в новых сборках он возвращает
объект результата (`AddResult`), в старых — ID или `false`, когда шаблона нет
или подстановка полей не удалась. В `broken.php` возврат игнорируется,
`ATTEMPTS` не инкрементируется, а в `catch` стоит `sleep(30)`.

**Последствие:** «успешно обработанные» письма не отправлены; при постоянной
ошибке — бесконечный цикл `new → попытка → new` с 30-секундными паузами внутри
запроса (на хитах это ровно то время, которое ждёт посетитель), при этом ни
счётчика, ни перехода в `error`.
**Условие:** отсутствующий шаблон (частый случай после переноса сайта),
недоступный SMTP.
**Исправление:** проверять `$eventId`, увеличивать `ATTEMPTS` при захвате
строки, `MAX_ATTEMPTS` + статус `error` + backoff вместо `sleep()`, а паузу
делать только вне HTTP-запроса.

## Что показывает прогон

```
php check.php broken

Режим: broken
До прогона: new=3

execute() вернул: 'MyCompany\\Agents\\QueueControlAgent::getAgentName();'
Время прогона: 0.01 с

После прогона: sent=3

Строки очереди:
  ID   EMAIL                  STATUS     ATTEMPTS  LAST_ERROR
  1    user1@example.com      sent       0
  2    user2@example.com      sent       0
  3    user3@example.com      sent       0

На что смотреть:
  - execute() вернул не имя агента: следующий запуск вызовет не ту точку входа
  - все строки стали sent, хотя успешность отправки не проверялась
  - ATTEMPTS остался 0: число попыток не считается
```

```
php check.php fixed

Режим: fixed
До прогона: new=3

execute() вернул: '\\MyCompany\\Agents\\QueueControlAgent::execute();'
Время прогона: 0.01 с
```

Дальше состояние зависит от наличия шаблона `CONTROL_QUEUE_MESSAGE`: с
шаблоном строки уходят в `sent` с `ATTEMPTS = 1`; без шаблона — в `new` с
`ATTEMPTS = 1` и текстом ошибки в `LAST_ERROR`. Оба варианта — правильные:
агент не врёт о результате и не падает.

## Что важно понять

1. Дефекты этого задания не ломают первый запуск на подготовленных данных —
   они ломают эксплуатацию: пустую очередь, большой бэклог, отсутствующий
   шаблон, чужой процесс.
2. Самое дорогое — дефект 1: он не оставляет следов ни в журнале, ни в
   мониторинге. Проверка одна: посмотреть `NAME` в `b_agent` после первого
   запуска.
3. `Event::send()` не бросает исключение на неуспех: `try/catch` не заменяет
   проверку результата, а объект результата всегда truthy — нужен `isSuccess()`.
