# Пробник механики агентов

**Зачем.** Утверждения вида «у `AddAgent()` нет `IS_CRON`», «изменение интервала
не двигает `NEXT_EXEC`», «имя агента из `__METHOD__` ломает расписание»
проверяются на живой сборке, а не запоминаются. Пробник печатает фактическое
состояние `b_agent` и поведение API.

## Что нужно

```
probe.php        ->  /local/tools/practice-1.3-probe.php
ProbeAgents.php  ->  рядом, /local/tools/ProbeAgents.php
```

`probe.php` подключает `ProbeAgents.php` из своей папки, поэтому оба файла
кладутся в один каталог. Автозагрузка проекта не требуется.

## Запуск

```bash
php -f <DOCUMENT_ROOT>/local/tools/practice-1.3-probe.php
```

Скрипт работает только из CLI. `CheckAgents()` он **не вызывает** — тот
выполняет все наступившие агенты инсталляции, включая чужие. Пробник
регистрирует свои записи с префиксом `PROBE-1.3-` и снимает их в конце.

## Что смотреть

| Секция | Что проверяется | Правильный вывод |
|---|---|---|
| 1 | подпись `CAgent::AddAgent()` через `ReflectionMethod` | 9 обязательных/необязательных параметров + `user_id`, `existError`; `IS_CRON` отсутствует |
| 2 | `method_exists()` по девяти методам `CAgent` | `AddAgent`, `GetList`, `GetById`, `Update`, `Delete`, `RemoveAgent`, `RemoveModuleAgents`, `CheckAgents`, `ExecuteAgents` — «есть» |
| 3 | регистрация того же имени дважды с `existError=false` | строка одна (или две — тогда видно, что `AddAgent` не дедуплицирует и поиск обязателен) |
| 4 | `Update(['AGENT_INTERVAL' => 7200])` | `NEXT_EXEC` не изменился → ближайший запуск задаётся явно |
| 5 | `nextNameBad()` против `nextNameGood()` | «плохое» имя указывает на сам геттер и при повторе возвращает себя же → `work()` не выполняется |
| 6 | прямой вызов `ProbeAgents::work()` | `LAST_EXEC` не изменился → это не запуск агента |
| 7 | уборка | «осталось: 0» |

## Ожидаемый вид вывода

```
Пробник агентов Bitrix
SM_VERSION: 24.x.x
Версия main: 24.x.x

1. Подпись CAgent::AddAgent()
  статический: да
  параметров:  10
   1. $name = по умолчанию
   2. $module = по умолчанию
   ...
  10. $existError = по умолчанию

  Вывод: аргумента IS_CRON нет. Девятый параметр — user_id,
  десятый — existError (выдавать ли ошибку при дублировании).
```

```
5. Дефект «имя агента строит вспомогательный метод»
  nextNameGood() -> \MyCompany\Agents\ProbeAgents::work('good');
  nextNameBad()  -> MyCompany\Agents\ProbeAgents::nextNameBad();
  повторный вызов nextNameBad() -> MyCompany\Agents\ProbeAgents::nextNameBad();
  строки совпадают: да
```

## Как читать расхождения

- **Секция 3 показала две строки.** `AddAgent()` не проверяет дубликат по
  `NAME`; регистрация должна начинаться с поиска (`GetList` + точное
  сравнение). Это и есть причина, по которой установщики пишут проверку
  вручную.
- **Секция 4 показала изменившийся `NEXT_EXEC`.** Значит, в вашей сборке
  `Update()` пересчитывает расписание. Вывод для кода тот же: **не
  рассчитывайте на это** — задавайте `NEXT_EXEC` явно, иначе поведение
  зависит от версии.
- **`CheckAgents()` на этой инсталляции не запускался.** Если нужен сквозной
  прогон, используйте cron-скрипт из `docs/module-1-3.md` §9.3, а не
  `CheckAgents()` в браузере под администратором.

## Границы

- Пробник меняет `b_agent` (регистрирует и удаляет свои записи). На рабочей
  инсталляции запускайте только с пониманием этого.
- `SM_VERSION` и версия `main` печатаются как есть: пробник не «подставляет»
  ожидаемую версию.
- Логика `IS_PERIOD` здесь не измеряется сквозным прогоном: для этого нужен
  агент, у которого наступило время, и вызов проверки агентов. Формулы
  (`next_exec += interval` для `Y`, `время окончания + interval` для `N`)
  даны в теории со ссылкой на официальную документацию.
