# Модуль 1.3: Агенты и cron — практика

Теория — `docs/module-1-3.md`. Папки самодостаточны: у каждой свой
`install.sql`, классы и страница регистрации агента. Пути внутри README
повторяют реальные (`/local/php_interface/...`, `/local/tools/...`).

| Папка | Тема | Что показывает | Куда копировать |
|---|---|---|---|
| `practice-1-log-cleanup/` | задача 1: очистка устаревших записей | порционная выборка, бюджет времени, `flock`, идемпотентность, JSONL-отчёт | классы → `/local/php_interface/classes/Agents/`, скрипты → `/local/tools/practice-1-log-cleanup/` |
| `practice-2-email-queue/` | задача 2: очередь писем | статусы, атомарный захват, `ATTEMPTS` + backoff, восстановление зависших, `UNIQUE(DEDUP_KEY)` | то же, каталог `/local/tools/practice-2-email-queue/` |
| `practice-3-api-sync/` | задача 3: синхронизация с API | тайм-ауты, проверка статуса и JSON, пагинация, контрольная точка в транзакции, upsert по `EXTERNAL_ID` | то же + `demo-api.php` как подставной провайдер |
| `task-agent-probe/` | проверка механики | подпись `AddAgent()`, наличие методов `CAgent`, дубль регистрации, `Update` интервала vs `NEXT_EXEC`, дефект `__METHOD__`, прямой вызов vs запуск | `probe.php` и `ProbeAgents.php` → `/local/tools/` |
| `control-task/` | контрольное задание | шесть дефектов агента очереди, эталон `fixed.php`, разбор | `/local/tools/practice-1.3-control/` |
| `example-file-log-cleanup/` | дополнительно | тот же набор требований на файловой системе: `lstat`, симлинки, повторная проверка метаданных, `flock` | `/local/php_interface/...` + `/local/tools/clean-old-logs/` |

Порядок прохождения: пробник → практика 1 → 2 → 3 → контрольное задание.
Дополнительный сценарий — после практики 1, если тема файлов тоже интересна.

## Общие правила набора

- **Агент всегда возвращает собственное имя.** Ни `return;`, ни исключение
  наружу. Ошибка внутри — в отчёт и в журнал, но запись агента остаётся.
- **Имя агента — константа класса.** Строка, которую ядро хранит в
  `b_agent.NAME`, собирается в одном месте; никаких `__METHOD__ . '();'` из
  вспомогательных методов (разбор дефекта — `control-task/`).
- **Объём работы за запуск ограничен** двумя числами: количество записей и
  бюджет времени. Агент может работать внутри HTTP-запроса посетителя.
- **Регистрация идемпотентна:** поиск по точному `NAME` перед `AddAgent()`.
  Аргумент `existError` не заменяет проверку.
- **Автозагрузка — часть решения, а не мелочь.** Регистрация в
  `Loader::registerAutoLoadClasses()` в `/local/php_interface/init.php` или
  PSR-4 из `/local/composer.json`; `check.php`/`probe.php` умеют работать и без
  неё, чтобы папка запускалась в том виде, в каком лежит.
- **Демо ≠ прод.** Отчёты лежат в `/local/var/agents/*.jsonl` без ротации,
  блокировка `flock` не работает между серверами, а `sent` в очереди означает
  «передано в почтовую подсистему», а не «доставлено». Границы перечислены в
  README каждой папки.
- Только Box-специфики здесь нет: набор работает и на «1С-Битрикс:
  Управление сайтом», и на коробочном Bitrix24. В облаке нет ни доступа к
  файлам, ни своих таблиц — эти примеры туда не переносятся.
