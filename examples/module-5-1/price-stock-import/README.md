# Кейс 2: Ночной импорт цен и остатков из CSV

## Что решает

Реальная задача из любого крупного каталога: раз в ночь из 1С/внешней ERP приходит CSV с ценами и остатками на 50–500 тысяч SKU. Нужно:

- не класть сайт во время импорта;
- не потерять весь импорт из-за одной «кривой» строки;
- не запустить два импорта параллельно, если первый ещё не закончился;
- получить внятный отчёт: что обновилось, что упало и почему.

## Ключевые приёмы (на что обратить внимание на собеседовании)

1. **Построчное чтение, не `file()`/`array`.** `fgetcsv()` в цикле — файл на 500k строк не укладывается в память, если грузить его целиком.

2. **Батчи + транзакция с откатом на построчную обработку.** Основной путь — одна транзакция на 500 строк (быстро). Если транзакция падает — не роняем весь батч, а откатываем и прогоняем эти же строки по одной с отдельной транзакцией на каждую, чтобы изолировать проблемную запись. Это компромисс между скоростью и отказоустойчивостью, который часто спрашивают на собеседовании: *«как бы вы импортировали большой файл, чтобы одна плохая строка не всё сломала»*.

3. **Идемпотентность (upsert).** Повторный запуск с тем же файлом не плодит дубли цен/остатков — ищем существующую запись по `(PRODUCT_ID, CATALOG_GROUP_ID)` / `(PRODUCT_ID, STORE_ID)` и обновляем, а не всегда `add()`.

4. **Лок от параллельного запуска.** Простая реализация через `Option` модуля с TTL — если агент завис, лок протухнет сам через `LOCK_TTL`, а не останется висеть навечно (частая ошибка — лок без TTL, который приходится снимать руками).

5. **Явный отчёт об ошибках, а не «тихий» пропуск.** Каждая проблемная строка попадает в отдельный `errors_*.log` с номером строки и причиной — на реальном проекте это то, что отдаёт поддержке/интегратору 1С.

## Пример отчёта по `data/sample_prices.csv`

При запуске на демо-файле (без реальной БД это просто иллюстрация потока):

```
processed=5 updated=2 skipped=0 errors=3
  line 4: Товар с XML_ID 'SKU-00124' не найден           (нет в тестовой БД)
  line 5: Некорректная цена                               ("не_число")
  line 6: Склад с XML_ID 'STORE-UNKNOWN' не найден
```

## Как использовать

1. Скопировать `lib/` и `import_agent.php` в `/local/php_interface/import/`.
2. Зарегистрировать агента (один раз, например в `init.php` при первом деплое):

```php
\CAgent::AddAgent(
    '\BitrixCourse\PriceImport\ImportAgent::run();',
    'bitrix_course',
    'N',
    3600 * 8,
    '',
    'Y',
    ConvertTimeStamp(strtotime('03:00:00') + CTimeZone::GetOffset(), 'FULL')
);
```

3. Положить CSV в `/upload/import/prices_stock.csv` (или поменять путь в `import_agent.php`).
4. Завести коды типов цен (`b_catalog_group.NAME`) и XML_ID складов (`b_catalog_store.XML_ID`), совпадающие с данными в CSV.

## Возможные вопросы на собеседовании по этому коду

- Почему откат батча не делает retry всего батча ещё раз целиком? *(одна и та же проблемная строка снова всё обрушит — нужна именно построчная изоляция)*
- Что если упадёт PHP-процесс посреди импорта? *(лок протухнет по TTL через час, недообработанные записи просто останутся со старыми значениями — импорт идемпотентен, следующий ночной запуск их досчитает)*
- Как распараллелить импорт на несколько воркеров? *(шардировать CSV по диапазону XML_ID или номеру строки, каждому воркеру — свой файл/диапазон и свой лок-ключ)*
