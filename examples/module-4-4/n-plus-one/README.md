# Задача 1: Оптимизация N+1

## Что показывает

Четыре подхода к загрузке заказов с пользователями:

| Подход | Запросов | Когда использовать |
|--------|----------|-------------------|
| N+1 | 101 на 100 заказов | ❌ Никогда |
| BatchLoad | 2 | Сложные связи, внешние API |
| Runtime | 1 | Нужны поля связи в фильтре/сортировке |
| with() | 2 | Коллекции 1:N |

## Senior-инсайты

1. **`select => 'USER_NAME' => 'USER.NAME'`** — поля связанной таблицы доступны для фильтрации `filter => ['USER.ACTIVE' => 'Y']` и сортировки.

2. **BatchLoad не проигрывает** — 2 запроса почти всегда быстрее 1 сложного JOIN, если связанная таблица большая или есть кастомная логика.

3. **`fetchObject()` vs `fetchAll()`** — `fetchObject` возвращает `EntityObject` с методами `fill()`, `get()` — удобнее для связей.
