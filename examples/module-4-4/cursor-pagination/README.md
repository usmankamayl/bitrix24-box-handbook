# Задача 2: Курсорная пагинация vs OFFSET

## Проблема

```
LIMIT 100000, 20   ← страница 5000
```
Читает 100020 строк, отбрасывает 100000, отдаёт 20. На 1 млн записей — сканирование всей таблицы.

## Решение

```
WHERE id > 99980 LIMIT 20   ← курсор
```
Читает ровно 20 строк через индекс.

## Что в файле

- `OffsetPaginator` — классическая пагинация (для сравнения)
- `CursorPaginator` — курсорная с `>ID`
- `iterateAll()` — генератор для обхода всей таблицы (экспорт, импорт)
- `ApiCursorPaginator` — REST-формат с base64-курсором

## Ограничения курсорной пагинации

- Нет перехода на страницу N (только "вперёд/назад")
- Требует стабильной сортировки (ID или уникальная колонка)
- Сложный курсор для сортировки по нескольким полям

## Когда что использовать

| Сценарий | Решение |
|----------|---------|
| Админка, "страница 5 из 20" | OFFSET |
| Бесконечный скролл | Cursor |
| Экспорт 1 млн записей | iterateAll (cursor) |
| API для мобильного приложения | Cursor |
