# Контрольное задание: пять дефектов компонента

`broken/` — компонент с пятью дефектами. `fixed/` — эталон. Задание: найти все
пять, сформулировать по схеме «ошибка → причина → последствие → исправление»,
затем сравнить с разбором ниже.

Порядок работы: прочитать `broken/class.php` целиком, выписать подозрительные
места, затем `broken/template.php`. Только после этого — разбор.

## Разбор

### 1. Выборка до `startResultCache()`

```php
$rsElement = CIBlockElement::GetList(...);   // выполняется всегда
while ($row = $rsElement->GetNext(false, false)) { ... }
$this->arResult['ITEMS'] = $items;
...
if ($this->startResultCache()) { ... }
```

**Причина.** Порядок операций перепутан: данные получаются до проверки кеша.
**Последствие.** На каждом хите выполняется запрос к БД, итерирование и
`GetPageNavStringEx()`. Кешируется только вывод шаблона и HTML. Нагрузка от
этого компонента равна нагрузке без кеша — при этом кеш ещё и занимает место.
**Исправление.** Внутри `if (startResultCache())` остаётся только получение
данных и `includeComponentTemplate()`; до него — параметры, навигация и ключ.

### 2. `abortResultCache()` на пустом результате

```php
if (empty($this->arResult['ITEMS'])) {
    $this->abortResultCache();
}
```

**Причина.** Пустой список считается «ошибкой», хотя это корректный результат.
**Последствие.** Пока в инфоблоке нет активных элементов, каждый посетитель
выполняет выборку. `abortResultCache()` вообще не про пустоту: он отменяет
запись кеша, начатую `startResultCache()`.
**Исправление.** Пустой массив кешируется как есть; `abortResultCache()` —
только в `catch` и при ненайденном обязательном объекте (инфоблок, раздел).

### 3. Номер страницы вне ключа кеша

```php
$page = (int)($_GET['PAGEN_1'] ?? 1);   // прочитали
$this->arResult['PAGE'] = $page;         // и записали в результат
$this->startResultCache();               // но в ключ не положили
```

**Причина.** `$_GET` не входит в ключ кеша: ядро строит его из сайта, языка,
шаблона сайта, имени компонента, имени шаблона и **только** `$arParams`.
**Последствие.** HTML первой страницы отдаётся как вторая, третья и все
остальные; навигация ведёт на те же элементы. Классическая жалоба «пагинация
не работает».
**Исправление.** `CDBResult::GetNavParams($navStartParams)` до
`startResultCache()` и передача результата вторым аргументом:
`$this->startResultCache(false, [$navData])`.

### 4. `setResultCacheKeys()` после `includeComponentTemplate()`

```php
$this->includeComponentTemplate();
$this->setResultCacheKeys(['ITEMS_COUNT']);
```

**Причина.** Урезание `$arResult` до перечисленных ключей и запись кеша
происходят внутри `showComponentTemplate()` → `endResultCache()`, то есть уже
внутри `includeComponentTemplate()`. Вызов после неё меняет флаг, который
больше никто не читает.
**Последствие.** В кеш попадает весь `$arResult` вместе со всеми элементами:
файл кеша раздувается, данные, нужные только шаблону, живут до истечения TTL.
`component_epilog.php` получает `$arResult` без ограничений, и в нём легко
случайно использовать устаревшие поля.
**Исправление.** `setResultCacheKeys()` — до `includeComponentTemplate()`,
и только те ключи, которые реально нужны после шаблона.

### 5. Неэкранированный вывод

```php
<a href="<?= $item['DETAIL_PAGE_URL'] ?>"><?= $item['NAME'] ?></a>
<div class="news-sidebar__text"><?= $item['PREVIEW_TEXT'] ?></div>
```

**Причина.** `GetNext(false, false)` отдаёт значения без HTML-подготовки, а
шаблон выводит их как есть.
**Последствие.** XSS: имя элемента с `<script>` исполняется на странице. Права
на редактирование инфоблока есть у контент-менеджера, но это не делает его
ввод безопасным; `PREVIEW_TEXT` типа HTML — тем более.
**Исправление.** `htmlspecialcharsbx()` в шаблоне для всех значений из БД,
включая URL. Если HTML из инфоблока нужно рендерить — это отдельное решение:
очистка (`CBXSanitizer`) и явно описанный контракт доверия.

## Критерии приёмки

- названы все пять дефектов и их механизм (не «так не пишут»);
- названо, что в ключ кеша входит автоматически, а что нет;
- назван момент урезания `$arResult` и что из этого следует для
  `component_epilog.php`;
- после переноса `fixed/` в `/local/components/study/news.sidebar/` компонент
  проходит проверки:

| Проверка | Ожидание |
|---|---|
| Двойное открытие страницы | второй запрос не выполняет выборку |
| `?PAGEN_1=2` | вторая страница, свой кеш |
| Деактивировать все элементы | пустой блок, кеш создан |
| Первый элемент после пустоты | блок обновился (тег инфоблока) |
| Элемент с `<b>имя</b>` в названии | тег виден как текст |
