# Кейс 1: Кастомный компонент списка заказов

## Что решает

Штатный `sale.personal.order.list` не всегда подходит — нужен другой фильтр, кеш, кастомные поля. Наследуем `CBitrixPersonalOrderListComponent` — получаем все обработки авторизации/параметров бесплатно, добавляем своё.

## Ключевые приёмы

1. **Наследование вместо копипасты.** `extends CBitrixPersonalOrderListComponent` — используем родительские `onPrepareComponentParams`, `checkAuthorization` и т.д., переопределяем только `executeComponent`.

2. **Авторизация — до запросов.** `!$USER->IsAuthorized()` → `LocalRedirect` с `backurl`. Не показываем "пустой список" анониму.

3. **Кеш по ключу (user + status + page).** Без кеша список из 1000 заказов с фильтрами — тяжёлый запрос на каждый хит. TTL 5 мин — баланс между актуальностью и нагрузкой.

4. **`PageNavigation` вместо ручной `LIMIT/OFFSET`.** Стандартная пагинация с `?page=N` и `navStart()`.

5. **`formatOrderForTemplate` — адаптер.** Шаблон работает с массивами, не с объектами `Order`. Это изолирует шаблон от API D7 — можно менять структуру ответа без правки шаблона.

6. **Статусы как массив, не хардкод в шаблоне.** `getStatusList()` — одно место для правок, легко потом вынести в `Option`.

7. **`CAN_CANCEL`/`CAN_REPEAT` — флаги бизнес-логики.** Не просто "есть заказ", а "заказ можно отменить/повторить" — учитываем статус, оплату, отмену.

8. **`Controllerable`** — для поддержки `BX.ajax.runComponentAction`. Если AJAX не нужен — можно убрать.

## Установка

1. Скопировать в `/local/components/acme/order.list/`.
2. На странице: `$APPLICATION->IncludeComponent('acme:order.list', '', [...])`.

## Тестирование

- Аноним → редирект на `/auth/`.
- Фильтр `?status=P` → только оплаченные.
- Пагинация при >10 заказах.
- Кеш: два запроса подряд → один SQL.
