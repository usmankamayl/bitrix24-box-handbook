# Автоматическое планирование встречи при создании сделки

При срабатывании события `onCrmDealAdd` в календаре ответственного за
сделку автоматически создаётся ознакомительная встреча на ближайший
рабочий день, 10:00–10:30, с напоминанием за 15 минут.

## Файлы

- `crest.php` — минимальный REST-клиент (вебхук-режим)
- `install.php` — подписка на событие через `event.bind` (запускается **один раз**)
- `handler.php` — endpoint, который Битрикс24 вызывает при создании сделки

## Установка

1. В `crest.php` укажите входящий вебхук `C_REST_WEB_HOOK_URL` с правами
   `crm`, `calendar`.
2. В `handler.php` подставьте `APPLICATION_TOKEN` — его можно посмотреть
   на странице настроек исходящего вебхука/приложения на портале.
3. В `install.php` впишите реальный публичный URL `handler.php`.
4. Откройте `install.php` в браузере → подписка на `onCrmDealAdd` оформлена.

## Как это работает

1. Сделка создаётся → Bitrix24 шлёт POST на `handler.php` с
   `auth[application_token]` и `data[FIELDS][ID]`.
2. Обработчик проверяет токен (`hash_equals`), сразу отвечает `200 OK`
   (`fastcgi_finish_request`), дальше работает в фоне.
3. Получает сделку (`crm.deal.get`) → находит ответственного
   (`ASSIGNED_BY_ID`).
4. Считает ближайший рабочий день (пропускает сб/вс).
5. Создаёт событие `calendar.event.add` с `is_meeting = Y` и
   `attendees = [responsibleId]` — ответственный получает уведомление.

## Ключевые моменты для собеседования

- Проверка `application_token` обязательна — без неё обработчик уязвим
  к подделке события извне (см. теорию 12.3).
- `event.bind` с `auth_type = 0` — подписка от имени приложения/вебхука,
  а не конкретного пользователя.
- `from`/`to` в `calendar.event.add` передаются в локальном времени
  владельца календаря (`ownerId`), не в UTC.
- Ответ `200 OK` отправляется до начала «тяжёлой» работы — событийные
  хуки Bitrix24 ограничены по времени ожидания ответа.
