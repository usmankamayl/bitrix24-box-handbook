# Задача 1: Логирование действий пользователей

## Описание

Реализация системы логирования всех попыток входа пользователей (успешных и неуспешных), а также выходов из системы.

## Что делает решение

- Записывает в лог-файл все успешные входы пользователей
- Записывает все неудачные попытки входа с указанием причины
- Записывает выходы пользователей из системы
- Сохраняет IP-адрес и User Agent для каждого действия
- Автоматически ротирует логи при достижении 5 МБ
- Хранит последние 5 бэкапов логов

## Структура файлов

```
user-login-logger/
├── init.php          # Основной файл с обработчиками событий
└── README.md         # Эта инструкция
```

## Установка

### Шаг 1: Скопируйте файлы

Скопируйте папку `user-login-logger` в `/local/examples/`:

```
/local/examples/user-login-logger/
```

### Шаг 2: Подключите обработчики

Добавьте в файл `/local/php_interface/init.php`:

```php
<?php
// Подключаем логирование входов пользователей
require_once $_SERVER['DOCUMENT_ROOT'] . '/local/examples/user-login-logger/init.php';
```

### Шаг 3: Создайте директорию для логов (опционально)

Директория создастся автоматически при первой записи, но можно создать вручную:

```bash
mkdir /local/logs
chmod 755 /local/logs
```

## Использование

После установки система автоматически начнёт логировать:

```
[2024-01-15 14:30:00] LOGOUT | User ID: 123 | Login: admin | IP: 192.168.1.100
```

## Какие события используются

### 1. OnAfterUserLogin
**Модуль:** main  
**Когда срабатывает:** После успешного входа пользователя  
**Параметры:** Массив с данными пользователя

### 2. OnUserLoginFail
**Модуль:** main  
**Когда срабатывает:** При неудачной попытке входа  
**Параметры:** 
- `$login` — введённый логин
- `$password` — введённый пароль (не записываем!)
- `$strError` — текст ошибки

### 3. OnUserLogout
**Модуль:** main  
**Когда срабатывает:** При выходе пользователя  
**Параметры:** ID пользователя

## Безопасность

### ✅ Что реализовано

1. **Не логируем пароли** — даже при неудачной попытке входа
2. **Получаем реальный IP** — учитываем прокси через заголовки X-Forwarded-For
3. **Валидация IP** — проверяем корректность IP через `filter_var()`
4. **Ротация логов** — предотвращаем переполнение диска
5. **Права доступа** — логи создаются с правами 0755

### ⚠️ Рекомендации

1. **Ограничьте доступ к логам:**
```bash
chmod 600 /local/logs/user_login.log
```

2. **Не храните логи в веб-доступной директории**  
   Путь `/local/logs/` недоступен через браузер — это правильно.

3. **Регулярно архивируйте старые логи:**
```bash
tar -czf user_login_archive_$(date +%Y%m%d).tar.gz /local/logs/*.bak
```

## Расширение функциональности

### Отправка уведомлений при подозрительной активности

Добавьте в метод `onLoginFail()`:

```php
public static function onLoginFail($login, $password, $strError)
{
    // Существующий код...
    self::writeLog($message);
    
    // Проверяем количество неудачных попыток за последние 5 минут
    $failedAttempts = self::countRecentFailedAttempts();
    
    if ($failedAttempts > 5) {
        // Отправляем уведомление администратору
        \CEvent::Send(
            'SECURITY_ALERT',
            's1',
            [
                'IP' => self::getUserIP(),
                'ATTEMPTS' => $failedAttempts
            ]
        );
    }
}
```

## Типичные проблемы

### Логи не создаются

**Причина:** Нет прав на создание директории  
**Решение:**
```bash
mkdir -p /local/logs
chmod 755 /local/logs
```

### События не срабатывают

**Причина:** Файл не подключён в init.php  
**Решение:** Проверьте, что путь в require_once правильный

### IP определяется неверно

**Причина:** Сайт за прокси/балансировщиком  
**Решение:** Убедитесь, что прокси передаёт заголовок X-Forwarded-For
