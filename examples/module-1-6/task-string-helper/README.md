# String Helper — утилиты для работы со строками

## Что делает

`MyCompany\Helpers\StringHelper` — набор статических методов для типовых строковых операций в контентных Bitrix-проектах:

- **Транслитерация** кириллицы → латиница (`transliterate`)
- **Генерация slug/ЧПУ** из названия (`generateCode`) с ограничением длины и fallback
- **Уникальный slug** с проверкой занятости (`generateUniqueCode`) — типовой сценарий для `CODE` элементов инфоблока
- **Обрезка текста** без разрыва слов (`truncate`)
- **Очистка ввода** для хранения (`sanitize`) — убирает теги, управляющие символы, лишние пробелы
- **Экранирование вывода** для HTML (`escape`) — отдельный метод, чтобы не путать с sanitize
- **Склонение существительных** после числительных (`plural`) — «1 товар / 2 товара / 5 товаров»

## Бизнес-задача

Повседневные операции контентного проекта: формирование ЧПУ для каталога и новостей, безопасное сохранение данных из форм, генерация превью-текстов, склонение слов в интерфейсе. Переносимая библиотека, не привязанная к модулю.

## Установка

1. Скопировать `StringHelper.php` → `/local/php_interface/classes/Helpers/StringHelper.php`
2. Подключить автозагрузку — код из `init.php` добавить в `/local/php_interface/init.php`

### Варианты автозагрузки

- **`registerAutoLoadClasses`** — явная карта класс → файл (вариант этой задачи). Ключ — имя класса, регистр не важен; значение — путь, регистр **важен**. Просто, но нужно перечислять каждый класс.
- **Composer PSR-4** — `MyCompany\` → `local/php_interface/classes/`. Масштабируется, не требует перечисления классов. Рекомендуется для реальных проектов.

`Loader::registerNamespace()` для этой задачи **не подходит**: загрузчик приводит
путь к нижнему регистру и искал бы `classes/helpers/stringhelper.php`. На
Windows такой путь находится, на Linux — нет. Composer PSR-4 единственный, кто
ищет файл по имени класса без изменения регистра (см. `../task-composer/`).

## Что сдать

- Вывод страницы: транслитерация, slug, обрезка по лимиту, `plural`.
- `print_r(spl_autoload_functions())` — `Loader::autoLoad()` в стеке.
- `grep -rn "StringHelper" local/` — класс не подключён ни одним `require`,
  только регистрация в `init.php` и страница вызовов.
- Ответ: почему ключ карты можно писать в любом регистре, а путь — нельзя.

## Ключевые изменения относительно исходной версии

- `sanitize` и `escape` разделены: sanitize — для записи в БД (убирает теги/управляющие символы, **не** экранирует), escape — для вывода в шаблон
- `generateCode` валидирует результат: ограничение длины, обрезка по дефису, fallback при пустом результате
- Добавлен `generateUniqueCode` — уникальный CODE для инфоблока с проверкой коллизий
- `plural` — склонение существительных для русскоязычных интерфейсов

## Ограничения

- `sanitize()` вырезает разметку при записи — это осознанный компромисс учебного
  примера. В реальном проекте, где пользователь может присылать HTML, нужен
  санитайзер с белым списком тегов, а `strip_tags()` не является защитой от XSS.
- `sanitizeForOutput()` — удобство для шаблона, а не замена контекстному
  экранированию: для атрибутов, JS и URL нужны свои методы.
- `generateUniqueCode()` не атомарен: между проверкой и вставкой код может
  занять параллельный запрос. Гарантия уникальности — уникальный индекс в БД,
  а не проверка перед вставкой.
