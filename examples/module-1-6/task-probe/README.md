# Задача 2. Диагностика автозагрузки

## Запуск

```bash
cp probe.php /path/to/site/autoload-probe.php
```

Открыть `https://site.local/autoload-probe.php`. Скрипт ничего не пишет и
ничего не меняет — только читает состояние.

## Что смотреть

| Блок | Что доказывает |
|---|---|
| 1. Пути | `Loader::getDocumentRoot()` и `$_SERVER['DOCUMENT_ROOT']` должны совпадать; иначе относительные пути в `require` ведут не туда |
| 2. Стек | порядок загрузчиков; `Loader::autoLoad` есть всегда, `Composer\Autoload\ClassLoader` — только после подключения `vendor/autoload.php` |
| 3. Резолвинг | `declared` (без автозагрузки) против `resolved` (с автозагрузкой) |
| 4. Цена промаха | во сколько раз `class_exists($c)` дороже `class_exists($c, false)` |
| 5. Регистр ФС | «ДА» означает, что ловушка регистра у вас локально не воспроизводится — и это худший вариант: баг найдёт прод |
| 6. Модуль | класс из `lib/` виден без `includeModule`, но модуль не инициализирован |

## Что сдать

1. Скриншот или текст вывода целиком.
2. Строку с `declared=no resolved=yes` — это и есть автозагрузка в действии.
3. Числа из блока 4 и объяснение, почему в цикле на 1000 элементов нельзя
   писать `class_exists()` без второго аргумента.

## Частые ошибки при запуске

- Запуск через CLI (`php autoload-probe.php`) — нет `$_SERVER['DOCUMENT_ROOT']`,
  пролог не подключён. Скрипт для браузера.
- Страница открыта по `file://` — `header.php` не найдётся.
