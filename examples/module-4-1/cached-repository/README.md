# Задача 1: CachedRepository — тегированный кеш + защита от stampede

## Что реализовано

| Файл | Что делает |
|------|-----------|
| `ProductRepository.php` | Паттерн репозитория с тегированным кешем, версионированием ключей, шардированием директорий |
| `StampedeProtectedCache.php` | Два алгоритма защиты от cache stampede: stale-while-revalidate с lock и XFetch (probabilistic early expiration) |
| `ProductCacheInvalidator.php` | Обработчики событий для автоинвалидации |
| `examples.php` | Примеры использования |

## Senior-фичи

1. **Cache versioning** — `CACHE_VERSION` в ключе. При деплое ломающих изменений инкрементируем константу, старые ключи умирают сами (не нужна очистка memcached).

2. **Шардирование директорий** — `substr($productId, -2)` создаёт 100 подпапок, файловый кеш не сваливается в одну директорию с 50к файлами.

3. **Правильная работа с тегами**:
   - `startTagCache()` ДО запроса — если запрос упадёт, `abortTagCache()` не сохранит мусорные теги
   - Теги регистрируются на все связанные сущности (товар, раздел, инфоблок, ценовая группа)
   - При изменении товара сбрасываются все страницы пагинации, где он показан

4. **НЕ кешируем отсутствие данных** — если `loadProductFromDb` вернул `null`, `abortDataCache()` и `abortTagCache()`. Иначе "фантомные 404" при восстановлении.

## Проблемы, которые это решает

**Без тегов:**
```
Закешировали товар на день → изменили цену → кеш не сбросится до завтра
или придётся сбрасывать весь кеш (медленно, тяжело)
```

**Без stampede-защиты:**
```
Кеш истёк → 200 запросов → 200 запросов к БД → 500 ошибок
```

## Как использовать

```php
$repo = new ProductRepository();

// Просто чтение
$product = $repo->getById(123);

// С защитой от stampede
$cache = new StampedeProtectedCache();
$product = $cache->remember('prod_123', '/shop/products', 3600,
    fn() => loadProduct(123));

// С XFetch (плавное обновление)
$product = $cache->rememberXFetch('prod_123', '/shop/products', 3600,
    fn() => loadProduct(123));
```

## Вопросы на собеседовании

- "Как сбросить кеш товара, когда он изменился?" → тег `iblock_element_123`
- "Как не уронить БД при массовом истечении кеша?" → mutex, stale-while-revalidate, XFetch
- "Как обновить структуру кеша при деплое без полного сброса?" → версионирование ключа
- "Что если товар отображается на 50 страницах пагинации?" → регистрируем тег `iblock_element_*` для каждого элемента в списке
