# Задача 2: Компонент с продвинутым кешированием

## Что показывает

Senior-подход к кешированию в компоненте:

1. **`CACHE_GROUPS => 'Y'`** — обязательно при персонализированном контенте (см. `isEditor()` в `class.php`). Без неё админ увидит кеш гостя.

2. **Дополнительные ключи кеша** — `startResultCache(time, [params], dir)`:
   ```php
   $this->startResultCache(
       3600,
       [$this->arParams['SECTION_ID'], $_GET['PAGEN_1'] ?? 1],
       '/articles.list/' . $this->arParams['IBLOCK_ID']
   );
   ```

3. **`abortResultCache()`** при пустом результате — не кешируем "пустую" страницу при сбое БД.

4. **Теги** через `$this->registerTag()` — автоинвалидация при изменении элементов.

5. **Ловушка с персонализированным шаблоном** — см. `template.php`. Всё внутри шаблона попадает в кеш. Имя пользователя, корзина — нельзя выводить напрямую. Используй frame (Composite) или deferred AJAX.

## Вопросы на собеседовании

- "Как сделать, чтобы кеш компонента учитывал права пользователя?" → `CACHE_GROUPS => 'Y'`
- "Что будет, если в кешированном шаблоне вывести `$USER->GetFullName()`?" → имя первого посетителя увидят все
- "Как компонент сбрасывает кеш при изменении элемента?" → `registerTag('iblock_element_' . $id)` + обработчик в `CIBlockElement::Update`

## Файлы

- `class.php` — логика компонента
- `.description.php` — описание для визредактора
- `.parameters.php` — параметры
- `templates/.default/template.php` — шаблон
