# Примеры к подразделу 1.1 — структура платформы и основы D7

Шесть задач подраздела, по каталогу на задачу. Каждый каталог самодостаточен:
`README.md` с процедурой и разбором + рабочий код.

| Задача | Каталог | Что показывает | Куда копировать на коробке |
|---|---|---|---|
| 1. Разведка проекта | `task-probe/` | служебная страница `probe.php`: версия ядра, фактический `init.php`, `.settings.php`, свои модули и переопределения, следы правок в `/bitrix/`, обработчики событий. Только чтение, доступ — админ | `/local/tools/probe.php` |
| 2. Свой модуль | `task-module-orders/` | модуль `mycompany.orders` целиком: установщик, `install.sql`, `OrderTable` с `Reference` на `UserTable`, `init.php` с автозагрузкой и подпиской на `main:OnPageStart`, демо-страница с POST + `sessid` | `/local/modules/mycompany.orders/`, `/local/php_interface/init.php`, `/orders-demo.php` |
| 2. Свой модуль (минимум) | `task-module-skeleton/` | минимальный каркас модуля `mycompany.hello`: структура, этапы установщика, автозагрузка `lib/`, `include.php` — без демо-страницы и ORM | `/local/modules/mycompany.hello/` |
| 3. Копия вместо правки ядра | `task-template-copy/` | шаблон `bitrix:main.feedback` внутри `/local/templates/...`: `template.php`, `result_modifier.php`, языковой файл. Плюс процедура поиска фактического шаблона и цена копии | `/local/templates/<шаблон>/components/bitrix/main.feedback/feedback-custom/` |
| 4. Legacy → D7 | `task-legacy-to-d7/` | исходник-антипаттерн, эталон страницы (пролог/эпилог, `Request`, лимит, экранирование) и вариант на ORM с честным списком того, что при этом меняется | `/local/pages/catalog-search.php` + правило в `urlrewrite.php` |
| 5. Code review | `task-code-review/` | код «как пришёл» (`review.php`), восемь дефектов с классификацией «безопасность / производительность / поддерживаемость» и эталон (`fixed.php`) | `/local/pages/report.php` |
| 6. Свой чек-лист | `task-checklist/` | чек-лист «первый день» в виде скрипта `first-day.sh`: 10 пунктов, каждый — команда или файл, а не «посмотреть» | запускается с сервера, в проект не копируется |

## Правила, общие для всех примеров

- **Ничего не правим в `/bitrix/`.** Всё, что копируется на сайт, идёт в `/local/`
  (кроме демо-страницы `orders-demo.php` в корне — она вне `/local/` намеренно,
  чтобы показать разницу между «кодом проекта» и «точкой входа»).
- **Задача 4 — не «переписать всё на D7».** `CIBlockElement::GetList()` остаётся
  в `after/catalog-search.php`, потому что у `ElementTable` другой контракт: нет
  свойств, другой формат `%NAME`, нет `DETAIL_PAGE_URL`. Это разобрано в README
  каталога и в `after/catalog-search-orm.php`.
- **Задача 5 — не «починить заменой на D7».** Восемь дефектов там про права,
  экранирование, лимит, запись в публичный `/upload/` и валидацию, а не про
  поколение API.
- **Только Box.** Всем примерам нужен файловый доступ и `/local/`; на облаке
  Bitrix24 запустить нельзя. Задача 1 вообще имеет смысл только на коробке.

Каталог `task-module-orders/` содержит `local/logs/.htaccess` — лог визитов
лежит под DOCUMENT_ROOT, поэтому закрыт от HTTP отдельно.
