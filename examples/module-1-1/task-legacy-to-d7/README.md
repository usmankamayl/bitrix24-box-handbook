# Task Legacy → D7 — переписать, не изменив поведения

**Задача 4.** Есть скрипт, который ищет элементы инфоблока по подстроке имени и
печатает ссылки. Он «работает», но это не страница Bitrix, а скрипт: без
шаблона, без валидации, без предела выборки и без экранирования. Нужно привести
его в вид рабочей страницы и при этом **не сломать поведение**.

```
before/legacy-search.php    исходник (антипаттерн, оставлен как есть)
after/catalog-search.php    эталон: страница, Request, лимит, экранирование, legacy-выборка
after/catalog-search-orm.php то же на ORM — и честный список того, что при этом меняется
```

Куда копировать: `after/catalog-search.php` → `/local/pages/catalog-search.php`,
URL — через `urlrewrite.php`.

## Что конкретно исправлено

| # | Было | Стало | Почему |
|---|---|---|---|
| 1 | `prolog_before.php` и всё | `prolog_before.php` → проверка модуля → `prolog.php` → … → `epilog.php` | без `prolog.php` нет шаблона сайта: `SetTitle` никуда не выводится, `header.php` не подключён, страница — голый HTML |
| 2 | `CModule::IncludeModule('iblock')` без проверки | `Loader::includeModule()` в `if` | на редакции без модуля — фатал; на 24.x `CModule` не нужен |
| 3 | `$_GET['q']` | `Context::getCurrent()->getRequest()->getQuery('q')` + `is_string()` | без `isset` — warning; `q[]=x` даёт массив и `Array to string conversion` в фильтре |
| 4 | значения без нормализации | `trim`, обрезка до 100 символов | длинная строка в `LIKE` — лишняя нагрузка, обход ограничений по длине URL |
| 5 | `false` вместо `nTopCount` | `['nTopCount' => 10]` | полный обход инфоблока на каждый хит: время и память линейны по каталогу, а выводится всё равно 10 ссылок |
| 6 | `echo $el['NAME']` | `htmlspecialcharsbx()` на тексте, `htmlspecialcharsbx()` на href | XSS: имя элемента вводят контент-менеджеры и поставщики; экранирование — при выводе, не при сохранении |
| 7 | `/catalog/<ID>/` | `DETAIL_PAGE_URL` или `/catalog/<CODE>/` | ссылка по ID работает только если так настроен ЧПУ; `DETAIL_PAGE_URL` учитывает настройки инфоблока |
| 8 | пустой `q` → LIKE `%%` | `$query === ''` → «введите запрос» | пустой LIKE — полный обход всей таблицы; на большом каталоге это худший запрос из всех |

`%NAME` оставлен как есть: это оператор подстроки, ядро само оборачивает
значение в `%%`. `%=NAME` — другой оператор (значение как есть), и «улучшение»
до него меняет семантику: поиск станет точным совпадением.

## Что осталось legacy и почему (обязательная часть ответа)

Три места, где замена на D7 изменила бы поведение:

1. **`CIBlockElement::GetList()` → `ElementTable`.**
   В select нельзя запросить `PROPERTY_*` — свойства живут в отдельной таблице и
   требуют join (`ElementPropertyTable`/`PropertyIndex`). Каталог почти всегда
   выводит цены и картинки — то есть свойства. Плюс формат LIKE другой.
2. **`DETAIL_PAGE_URL`.** Это вычисляемое ядром поле: оно собирается из шаблона
   URL инфоблока, с учётом `SECTION_CODE`, даты и `iblock`-настроек. ORM его не
   знает вообще. Замена на `'/catalog/' . $CODE . '/'` — это уже не «то же
   поведение», а новая логика ссылок, и она разойдётся с настройками инфоблока.
3. **Права и активность.** `CIBlockElement::GetList()` учитывает настройки
   инфоблока и активности (в зависимости от параметров), ORM — «сырая» выборка
   из таблицы: `ACTIVE` надо фильтровать руками, права не проверяются, элементы
   неактивных разделов попадут в выдачу.

Четвёртое, менее очевидное: `IBLOCK_ID => 5` — константа в коде. ORM-класс
`ElementTable` тоже работает по `IBLOCK_ID`, но при переходе на «правильный»
ORM инфоблока (`\Bitrix\Iblock\Elements\ElementCatalogTable`) фактический
`IBLOCK_ID` берётся из кода инфоблока. Это удобнее, но привязывает код к
символьному коду инфоблока, а он на разных стендах разный. `[проверить]` в
своей версии: есть ли в сборке сгенерированный класс `Element<Code>Table` —
он появляется не во всех версиях и зависит от настроек модуля.

## Как сравнить поведение

Одинаковые входные данные на обеих версиях:

| Запрос | Ожидание |
|---|---|
| `q` не задан | «Введите запрос», ни одного SQL-запроса к элементам |
| `q=стол` | тот же список ссылок, что в антипаттерне, но не длиннее 10 |
| `q=` (пустая строка) | как «не задан» |
| `q[]=1` | «Введите запрос» / пустой результат, **без** warning в логе |
| `q=<script>alert(1)</script>` | текст на странице, скрипт не выполняется |
| `q=абвгд…` (200 символов) | обрезка до 100, результат по первым 100 |
| `q=%` | пустой результат (в legacy `%` — шаблон LIKE, и это ловушка) |

В ORM-варианте `q=%` даст **все** элементы: там шаблон собирается вручную, и
`%` из значения работает подстановкой. Это не баг примера, а разница контрактов
— `[проверить]` на своей версии, экранируется ли `%` в значении при операторе
`%`.

## Альтернативы и когда они лучше

| Вариант | Когда лучше | Цена |
|---|---|---|
| `CIBlockElement::GetList` + `nTopCount` (этот пример) | выдача как в каталоге: свойства, ЧПУ, права | legacy-API в новом коде, но других путей нет |
| `ElementTable` (ORM) | поиск по «тонким» полям, сервис без вывода | нет свойств и `DETAIL_PAGE_URL`, руками `ACTIVE` |
| `\Bitrix\Iblock\Elements\Element<Code>Table` | нужны и свойства (через `.PROPERTY_*` в select), и ORM | класс зависит от символьного кода инфоблока; `[проверить]` наличие |
| `bitrix:search.title` / `search.page` | нужен полнотекстовый поиск с индексом и морфологией | отдельный индекс, свои настройки; по NAME не ищет так, как ждут |
| `bitrix:catalog.section` с `arrFilter` | это страница каталога, а не поиск | тяжелее; для «10 ссылок» избыточно |

Для «поиска по каталогу» на реальном проекте почти всегда выбирают последний
или предпоследний вариант: поиск по `NAME` через `LIKE '%…%'` не использует
индекс и на 100k+ элементов начинает мешать.

## Что здесь важно понять, а не скопировать

1. **Точка входа — это `prolog_before` + `prolog` + `epilog`.** Один
   `prolog_before` даёт страницу без шаблона: работает, но это не Bitrix-страница.
2. **Экранирование делается на выводе** и только на выводе. `htmlspecialcharsbx`
   в фильтре — ошибка, в шаблоне — обязателен.
3. **`nTopCount` — не оптимизация, а корректность:** без него скрипт выбирает
   всю таблицу, чтобы вывести 10 строк, и падает по `memory_limit` на каталоге.
4. **D7 не цель, а инструмент.** Переписать всё на ORM — значит потерять
   свойства и ЧПУ. Хороший ответ на ревью: «здесь D7 нельзя, вот три причины».

## Ограничения примера

- `IBLOCK_ID = 5` — заглушка; на своём сайте подставьте реальный ID или
  символьный код.
- Нет пагинации: для поиска «первые 10» — нормально, для каталога — нет.
- Нет кеша: поисковые запросы кешировать бессмысленно (уникальные ключи), а
  общий кеш на `LIKE` только раздует `managed_cache`.
- Нет проверки прав на инфоблок: в БУС выдача публичная, но если инфоблок
  закрыт для групп — нужен `CIBlockElement::GetList` с проверкой прав или
  `\Bitrix\Iblock\IblockSiteTable`-фильтр по сайту.
