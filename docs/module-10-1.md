# Модуль 10.1: Интеграция телефонии (Bitrix24 REST API)

## Теория

### Что такое интеграция телефонии в Bitrix24

**Интеграция телефонии** — это связь телефонной системы (АТС) с CRM Bitrix24. Цель: чтобы звонки отображались в интерфейсе, прикреплялись к лидам/контактам/сделкам, записи разговоров сохранялись, а менеджер видел карточку клиента при входящем звонке.

---

### Два подхода к телефонии

#### 1. Встроенная телефония (VoxImplant)

Bitrix24 имеет собственную телефонию на базе VoxImplant — номер арендуется прямо в портале, звонки идут через Bitrix24.

**Особенности:**
- Телефония "из коробки" — ничего интегрировать не нужно
- Звонки, записи, статистика — встроены в интерфейс
- Для программного управления есть методы `voximplant.*`
- Тарификация через Bitrix24

**Методы `voximplant.*`:**
- `voximplant.info.get` — информация о линии
- `voximplant.user.get` — пользователи телефонии
- `voximplant.sip.get` / `voximplant.sip.create` — управление SIP-аккаунтами
- `voximplant.statistic.get` — статистика звонков
- `voximplant.call.start` — инициировать исходящий звонок

#### 2. SIP-коннектор

Подключение **внешней офисной АТС** (Asterisk, 3CX, Avaya и т.д.) к Bitrix24 через SIP-протокол.

**Особенности:**
- Покупается "SIP-коннектор" (платно, поминутно или абонемент)
- Входящие звонки приходят на АТС → АТС форвардит в Bitrix24
- Исходящие из Bitrix24 идут через АТС
- Ограничение: 60 минут бесплатно в день, дальше платно

#### 3. REST-телефония (telephony.externalcall.*)

Интеграция сторонней АТС с Bitrix24 через REST API **без SIP-коннектора**. АТС сама звонит, а в Bitrix24 отправляются только события и метаданные.

**Именно этот подход — основа модуля.**

**Когда использовать:**
- Облачные АТС (Zadarma, Mango Office, OnlinePBX, UIS, Телфин)
- Своя виртуальная АТС
- Звонки через мобильное приложение / мессенджеры
- Когда не нужна SIP-телефония, но нужны звонки в CRM

---

### Основные методы REST-телефонии

#### telephony.externalcall.register — регистрация звонка

Регистрирует звонок в Bitrix24. Вызывается в момент начала звонка.

```php
CRest::call('telephony.externalcall.register', [
    'USER_PHONE_INNER' => '100',          // Внутренний номер сотрудника
    'USER_ID' => 1,                     // ID пользователя Bitrix24
    'PHONE_NUMBER' => '+79991234567',   // Номер клиента
    'CALL_START_DATE' => '2026-11-02 15:30:00',
    'TYPE' => 2,                        // 1 — исходящий, 2 — входящий
    'CRM_CREATE' => 1,                  // Создать лид, если контакт не найден
    'CRM_SOURCE' => 'CALL',             // Источник лида
    'SHOW' => 1,                        // Показать карточку звонка (deprecated — используй .show)
]);
```

**Что возвращает:**
```json
{
    "result": {
        "CALL_ID": "externalcall.abc123",
        "CRM_CREATED_LEAD": 42,
        "CRM_ENTITY_TYPE": "LEAD",
        "CRM_ENTITY_ID": 42,
        "CRM_ACTIVITY_ID": 1234
    }
}
```

**Ключевые моменты:**
- `CALL_ID` — ID звонка, нужен для всех последующих методов
- `CRM_ENTITY_TYPE/ID` — к какому объекту привязан звонок
- `CRM_CREATE` — автоматически создать лид, если номер не найден в CRM

#### telephony.externalcall.show — показ карточки звонка

Открывает всплывающую карточку звонка у пользователя.

```php
CRest::call('telephony.externalcall.show', [
    'CALL_ID' => 'externalcall.abc123',
    'USER_ID' => 1
]);
```

**Когда вызывать:** обычно сразу после `register`, либо через 3–5 секунд (когда звонок дошёл до менеджера).

#### telephony.externalcall.attachrecord — прикрепление записи

Прикрепляет файл записи разговора к звонку.

```php
CRest::call('telephony.externalcall.attachrecord', [
    'CALL_ID' => 'externalcall.abc123',
    'FILENAME' => 'call_2026-11-02.mp3',
    'FILE_CONTENT' => base64_encode($fileContent)  // Файл в base64
]);
```

**Или через URL** (Bitrix сам скачает файл):

```php
CRest::call('telephony.externalcall.attachrecord', [
    'CALL_ID' => 'externalcall.abc123',
    'FILENAME' => 'call.mp3',
    'RECORD_URL' => 'https://your-ats.com/records/call_123.mp3'
]);
```

**Важно:** запись прикрепляется ПОСЛЕ `finish`, иначе CALL_ID не будет валидным.

#### telephony.externalcall.finish — завершение звонка

Завершает звонок, сохраняет его в историю CRM.

```php
CRest::call('telephony.externalcall.finish', [
    'CALL_ID' => 'externalcall.abc123',
    'USER_ID' => 1,
    'USER_PHONE_INNER' => '100',
    'DURATION' => 120,                  // Длительность в секундах
    'STATUS_CODE' => 200,               // 200 — успешный, 304 — пропущенный, и т.д.
    'ADD_TO_CHAT' => 1,                 // Добавить в бизнес-чат
    'VOTE' => 5,                        // Оценка звонка (1-5)
    'COMMENT' => 'Обсудили договор',
]);
```

**STATUS_CODE (коды SIP):**
- `200` — успешный звонок
- `304` — пропущенный
- `486` — занято
- `503` — недоступен
- `603` — отклонён

#### telephony.externalcall.get.fields

Возвращает список полей для методов телефонии — полезно для отладки.

### События телефонии

#### onExternalCallStart

Срабатывает в момент старта звонка. Позволяет приложению отреагировать на звонок.

**Параметры события:**
```php
[
    'event' => 'ONEXTERNALCALLSTART',
    'data' => [
        'PHONE_NUMBER' => '+79991234567',
        'CALL_ID' => 'externalcall.abc123',
        'USER_ID' => 1,
        'TYPE' => 2,
    ]
]
```

**Использование:** кастомная логика при входящем звонке — например, автоматический поиск клиента в собственной БД и показ доп. информации.

#### onExternalCallBackStart

Срабатывает при исходящем звонке через обратный звонок (callback).

### Типичный флоу интеграции со сторонней АТС

```
Клиент звонит на номер компании
         ↓
АТС принимает звонок
         ↓
АТС делает HTTP-запрос на твой скрипт: index.php?phone=+7999...&ext=100
         ↓
Скрипт вызывает telephony.externalcall.register
         ↓
Получает CALL_ID, сохраняет в БД
         ↓
Вызывает telephony.externalcall.show → у менеджера всплывает карточка
         ↓
Менеджер разговаривает с клиентом
         ↓
Звонок завершён → АТС делает запрос на finish.php?call_id=...&duration=120
         ↓
Скрипт вызывает telephony.externalcall.finish
         ↓
Если есть запись → telephony.externalcall.attachrecord
         ↓
Звонок появляется в CRM (в лиде/контакте — история, в активности — запись)
```

**Схема на портале:**

```
┌──────────┐         ┌──────────────┐         ┌────────────┐
│   АТС    │────────→│ Твой скрипт  │────────→│  Bitrix24  │
│ (звонок) │  HTTP   │ (webhook)    │  REST   │   (CRM)    │
└──────────┘         └──────────────┘         └────────────┘
                              │
                              ↓
                        Лог в БД
                     (call_id → статус)
```

---

### Структура данных звонка

**Входящие параметры от АТС** (обычно):
- `phone` / `caller` — номер звонящего
- `ext` / `inner` — внутренний номер сотрудника
- `call_id` — ID звонка на стороне АТС
- `type` — входящий/исходящий
- `duration` — длительность (при finish)
- `record_url` — ссылка на запись

**Что сохраняем в своей БД:**
- `external_call_id` — CALL_ID из Bitrix24
- `ats_call_id` — ID звонка в АТС
- `phone` — номер клиента
- `user_id` — ID сотрудника
- `status` — new / finished / failed
- `record_url` — ссылка на запись

## Вопросы для собеседования

### Q1: Какие способы подключения телефонии к Bitrix24 существуют?

**Ответ:**
1. **Встроенная телефония** — номер арендуется в Bitrix24 (на базе VoxImplant), работает из коробки
2. **SIP-коннектор** — подключение офисной АТС к Bitrix24 по SIP-протоколу, платная опция
3. **REST-телефония** — интеграция сторонней АТС через REST API: АТС звонит сама, в Bitrix24 передаются только метаданные звонка (методы `telephony.externalcall.*`)

---

### Q2: Опиши флоу регистрации входящего звонка через REST.

**Ответ:**
1. АТС получает входящий звонок и делает HTTP-запрос на твой сервер
2. Скрипт вызывает `telephony.externalcall.register` с номером клиента, внутренним номером сотрудника и типом звонка
3. Bitrix24 возвращает `CALL_ID` и ID созданного лида/контакта
4. Вызывается `telephony.externalcall.show` — у менеджера всплывает карточка звонка
5. По завершении — `telephony.externalcall.finish` с длительностью и статусом
6. Затем `telephony.externalcall.attachrecord` — прикрепление записи разговора

---

### Q3: Чем отличается register от finish?

**Ответ:**
- `register` — вызывается в момент СТАРТА звонка. Создаёт запись звонка в Bitrix24, привязывает к лиду/контакту, возвращает `CALL_ID`
- `finish` — вызывается ПОСЛЕ окончания. Завершает звонок, записывает длительность и статус (пропущенный/успешный), сохраняет звонок в историю CRM

Без `finish` звонок "зависнет" и не попадёт в историю корректно.

---

### Q4: Как прикрепить запись разговора к звонку?

**Ответ:**
Метод `telephony.externalcall.attachrecord`. Два способа передать файл:
- `FILE_CONTENT` — содержимое файла в base64
- `RECORD_URL` — URL, откуда Bitrix24 сам скачает файл

**Важно:** вызывается ПОСЛЕ `finish`, т.к. только тогда звонок полностью создан. Нужен валидный `CALL_ID`.

---

### Q5: Что такое CALL_ID и где он используется?

**Ответ:**
`CALL_ID` — уникальный идентификатор звонка в Bitrix24, который возвращает `telephony.externalcall.register`. Используется во всех последующих методах:
- `telephony.externalcall.show` — показать карточку
- `telephony.externalcall.finish` — завершить звонок
- `telephony.externalcall.attachrecord` — прикрепить запись

Его нужно сохранять в своей БД вместе с ID звонка на стороне АТС, чтобы потом корректно завершить звонок.

---

### Q6: Что делает параметр CRM_CREATE при регистрации звонка?

**Ответ:**
`CRM_CREATE=1` — если номер телефона не найден в CRM (ни в лидах, ни в контактах, ни в компаниях), Bitrix24 автоматически создаст новый лид с этим номером. Если `CRM_CREATE=0` — звонок будет "непривязанным", появится в списке звонков, но не в истории клиента.

---

### Q7: Как уведомить конкретного сотрудника о входящем звонке?

**Ответ:**
При регистрации звонка указывается `USER_ID` или `USER_PHONE_INNER` (внутренний номер). Метод `telephony.externalcall.show` с параметром `USER_ID` показывает карточку звонка именно этому пользователю — у него в интерфейсе Bitrix24 появится всплывающее окно с данными клиента.

---

### Q8: Что произойдёт, если не вызвать finish после register?

**Ответ:**
Звонок останется "активным" в Bitrix24 и не попадёт корректно в историю CRM:
- В карточке клиента не будет записи о звонке
- В статистике телефонии он будет "незавершённым"
- Запись разговора прикрепить нельзя (`attachrecord` требует `CALL_ID` завершённого звонка)

Поэтому `finish` обязателен — даже если звонок был пропущен.

## Частые ошибки

### Ошибка 1: attachrecord вызывается до finish

**Причина:** Попытка прикрепить запись к звонку, который ещё не завершён — `CALL_ID` в этот момент недействителен для attachrecord.

**Решение:** Строгий порядок: `register` → `show` → (разговор) → `finish` → `attachrecord`.

### Ошибка 2: Звонок не появляется в истории лида

**Причина:** `CRM_CREATE=0` и номер не найден в CRM — звонок "повис" без привязки.

**Решение:** Установить `CRM_CREATE=1` для автосоздания лида, либо заранее найти `CRM_ENTITY_ID` через `crm.duplicate.findbycomm` и передать его в `register`.

### Ошибка 3: CALL_ID не сохраняется между запросами

**Причина:** АТС делает два отдельных HTTP-запроса (start и finish), но скрипт не сохранил `CALL_ID` — невозможно вызвать `finish`.

**Решение:** Сохранять `CALL_ID` (из Bitrix24) в БД вместе с ID звонка на стороне АТС. При finish-запросе искать `CALL_ID` по `ats_call_id`.

### Ошибка 4: Карточка звонка не всплывает у менеджера

**Причины:**
- Неверный `USER_ID` / `USER_PHONE_INNER` — внутренний номер не совпадает с настройками пользователя
- Сотрудник не залогинен в портал
- `show` вызван до `register` (или с неверным `CALL_ID`)

**Решение:** Проверить что у пользователя в настройках телефонии указан внутренний номер; вызывать `show` после `register`.

### Ошибка 5: Запись разговора не загружается по URL

**Причина:** URL записи недоступен извне (например, внутренний адрес АТС, требует авторизации, истёк срок действия).

**Решение:** Убедиться что `RECORD_URL` публично доступен, либо передать файл через `FILE_CONTENT` (base64).

### Ошибка 6: Неправильный тип звонка (TYPE)

**Причина:** Перепутаны значения — `1` это исходящий, `2` входящий. Ошибка приводит к тому, что входящий звонок отображается как исходящий.

**Решение:** Входящий = `2`, исходящий = `1`. Проверять значение из АТС.
