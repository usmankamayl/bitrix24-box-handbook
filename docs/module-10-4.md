# Модуль 10.4: Задачи и проекты (tasks.task.*) в Bitrix24

## Теория

### Структура задач в Bitrix24

**Задача (Task)** — базовая единица работы. Состоит из:

- **Основные поля:** `TITLE`, `DESCRIPTION`, `RESPONSIBLE_ID` (исполнитель), `CREATED_BY` (постановщик), `DEADLINE`, `STATUS`
- **Участники:**
  - `RESPONSIBLE_ID` — исполнитель (1 человек)
  - `ACCOMPLICES` — соисполнители (массив ID)
  - `AUDITORS` — наблюдатели (массив ID)
  - `CREATED_BY` — постановщик
- **Группа/проект:** `GROUP_ID` — ID группы (sonet_group), к которой привязана задача
- **Родительская задача:** `PARENT_TASK_ID` — для подзадач
- **Привязка к CRM:** `UF_CRM_TASK` — массив вида `['D_123', 'C_456', 'L_789']` (Deal, Contact, Lead, Company)
- **Теги:** `TAGS` — массив строк
- **Чек-лист:** отдельные элементы через `task.checklistitem.*`
- **Файлы:** `UF_TASK_WEBDAV_FILES` — массив вида `['n123', 'n456']` (ID из disk.file)

---

### Иерархия: Группа → Проект → Задача → Подзадача → Чек-лист

```
sonet_group (Рабочая группа)
    └── tasks.scrum.* (Скрам-проект внутри группы)
        └── tasks.task (Задача)
            └── task.checklistitem (Пункт чек-листа)
            └── task.commentitem (Комментарий)
            └── task.elapseditem (Учёт времени)
            └── Подзадача (PARENT_TASK_ID)
```

### Основные методы `tasks.task.*`

| Метод | Назначение |
|-------|------------|
| `tasks.task.add` | Создать задачу |
| `tasks.task.get` | Получить задачу по ID |
| `tasks.task.list` | Список задач с фильтрами |
| `tasks.task.update` | Обновить задачу |
| `tasks.task.delete` | Удалить задачу |
| `tasks.task.delegate` | Делегировать другому исполнителю |
| `tasks.task.complete` | Завершить задачу |
| `tasks.task.start` | Взять в работу |
| `tasks.task.approve` | Одобрить (для задач с контролем) |
| `tasks.task.disapprove` | Отклонить (вернуть на доработку) |
| `tasks.task.renew` | Возобновить |
| `tasks.task.pause` | Приостановить |
| `tasks.task.defer` | Отложить |
| `tasks.task.counters.get` | Счётчики задач пользователя |

### Создание задачи (`tasks.task.add`)

```php
$result = CRest::call('tasks.task.add', [
    'fields' => [
        'TITLE' => 'Подготовить отчёт за Q3',
        'DESCRIPTION' => 'Собрать данные по продажам и подготовить презентацию',
        'RESPONSIBLE_ID' => 15,        // ID исполнителя
        'CREATED_BY' => 1,             // ID постановщика
        'DEADLINE' => '2026-11-15T18:00:00+03:00',
        'GROUP_ID' => 5,               // Проект/группа
        'ACCOMPLICES' => [7, 9],       // Соисполнители
        'AUDITORS' => [3],             // Наблюдатели
        'TAGS' => ['отчёт', 'Q3'],     // Теги
        'UF_CRM_TASK' => ['D_123'],    // Привязка к сделке ID=123
        'PRIORITY' => 2,               // 0-низкий, 1-средний, 2-высокий
        'ALLOW_TIME_TRACKING' => 'Y',  // Учёт времени
        'TASK_CONTROL' => 'Y',         // Контроль постановщиком
        'PARENT_TASK_ID' => 0,         // 0 = корневая задача
    ]
]);

$taskId = $result['result']['task']['id'];
```

### Список задач (`tasks.task.list`)

```php
$result = CRest::call('tasks.task.list', [
    'filter' => [
        'RESPONSIBLE_ID' => 15,        // Исполнитель
        '<DEADLINE' => '2026-11-02',   // Просроченные (дедлайн раньше сегодня)
        '!STATUS' => [5, 6],           // Не завершённые и не отклонённые
        'GROUP_ID' => 5,               // Из конкретного проекта
    ],
    'select' => ['ID', 'TITLE', 'DEADLINE', 'STATUS', 'RESPONSIBLE_ID'],
    'order' => ['DEADLINE' => 'asc'],
    'start' => 0,  // Пагинация (0, 50, 100...)
]);
```

**Операторы фильтра:**
- `=`, `!=` — равно / не равно (по умолчанию `=`)
- `>`, `<`, `>=`, `<=` — сравнение (для дат и чисел)
- `!` — отрицание (например `'!STATUS' => 5`)
- `%` — LIKE поиск
- `><` — между двумя значениями (массив)

---

### Статусы задач

| ID | Код | Название | Переходы |
|----|-----|----------|----------|
| 1 | `STATUS_NEW` | Новая | → 2, 6 |
| 2 | `STATUS_PENDING` | Ждёт выполнения | → 3, 5, 6, 7 |
| 3 | `STATUS_IN_PROGRESS` | В работе | → 4, 5, 6, 7 |
| 4 | `STATUS_SUPPOSEDLY_COMPLETED` | Условно завершена (ждёт контроля) | → 5, 3 |
| 5 | `STATUS_COMPLETED` | Завершена | → 2 (возобновить) |
| 6 | `STATUS_DEFERRED` | Отложена | → 2, 3 |
| 7 | `STATUS_DECLINED` | Отклонена | → 2 |

**Жизненный цикл задачи с контролем (`TASK_CONTROL = 'Y'`):**

```
Постановщик создаёт → Новая (1)
        ↓
Исполнитель нажимает "В работу" → В работе (3)
        ↓
Исполнитель нажимает "Завершить" → Условно завершена (4)
        ↓
Постановщик проверяет:
  - "Принять" → Завершена (5)
  - "Вернуть" → В работе (3)
```

**Методы переходов:**
```php
// Взять в работу
CRest::call('tasks.task.start', ['taskId' => 100]);

// Завершить (если нет контроля → сразу статус 5, если есть → 4)
CRest::call('tasks.task.complete', ['taskId' => 100]);

// Одобрить (только постановщик, из статуса 4 → 5)
CRest::call('tasks.task.approve', ['taskId' => 100]);

// Отклонить (из 4 → 3)
CRest::call('tasks.task.disapprove', ['taskId' => 100]);
```

### Чек-листы (`task.checklistitem.*`)

Чек-лист — список подзадач внутри задачи. Каждый пункт можно отметить выполненным.

```php
// Добавить пункт
CRest::call('task.checklistitem.add', [
    'TASK_ID' => 100,
    'FIELDS' => [
        'TITLE' => 'Согласовать с юристами',
        'IS_COMPLETE' => 'N',
        'SORT_INDEX' => 1,
    ]
]);

// Список пунктов задачи
CRest::call('task.checklistitem.getlist', [
    'TASK_ID' => 100,
    'ORDER' => ['SORT_INDEX' => 'asc']
]);

// Отметить выполненным
CRest::call('task.checklistitem.complete', [
    'TASK_ID' => 100,
    'ITEM_ID' => 55
]);

// Обновить
CRest::call('task.checklistitem.update', [
    'TASK_ID' => 100,
    'ITEM_ID' => 55,
    'FIELDS' => ['TITLE' => 'Новый текст']
]);
```

### Учёт времени (`task.elapseditem.*`)

Если у задачи включён `ALLOW_TIME_TRACKING`, можно логировать затраченное время.

```php
        'COMMENT_TEXT' => 'Анализ данных',
        'CREATED_DATE' => '2026-11-01 14:00:00',
    ]

// Список записей

    'TASKID' => 100
]);
```

### Проекты и Скрам

**Группа (sonet_group)** — контейнер для задач. У каждой задачи `GROUP_ID` ссылается на группу.

```php
// Создать группу
CRest::call('sonet_group.create', [
    'NAME' => 'Проект Alpha',
    'DESCRIPTION' => 'Разработка нового продукта',
    'VISIBLE' => 'Y',
    'OPENED' => 'N',  // Закрытая группа
    'INITIATE_PERMS' => 'K',  // K - только владелец, E - все участники
]);
```

**Скрам (tasks.scrum.\*)** — гибкая методология внутри группы:

```php
// Список спринтов
CRest::call('tasks.scrum.sprint.list', [
    'filter' => ['GROUP_ID' => 5]
]);

// Создать спринт
CRest::call('tasks.scrum.sprint.add', [
    'fields' => [
        'GROUP_ID' => 5,
        'NAME' => 'Спринт 3',
        'DATE_START' => '2026-11-03',
        'DATE_END' => '2026-11-17',
    ]
]);
```

**Стадии канбана (`task.stages.*`):**

```php
// Получить стадии канбана для группы
CRest::call('task.stages.get', [
    'ENTITY_ID' => 5,    // GROUP_ID
    'ENTITY_TYPE' => 'G' // G = группа, U = пользователь
]);

// Переместить задачу на другую стадию
CRest::call('task.stages.movetask', [
    'ID' => 100,        // ID задачи
    'STAGE_ID' => 12,   // ID стадии
]);
```

### Привязка к CRM (`UF_CRM_TASK`)

Поле `UF_CRM_TASK` привязывает задачу к сущностям CRM. Формат — массив строк:

| Префикс | Сущность | Пример |
|---------|----------|--------|
| `D_` | Сделка | `D_123` |
| `C_` | Контакт | `C_456` |
| `CO_` | Компания | `CO_789` |
| `L_` | Лид | `L_321` |

```php
'UF_CRM_TASK' => ['D_123', 'C_456']  // Привязана к сделке 123 и контакту 456
```

Задачи с привязкой отображаются на вкладке "Задачи" в карточке сделки/контакта.

---

### Права доступа

Доступ к задаче определяется ролью пользователя:

| Роль | Поле | Права |
|------|------|-------|
| Постановщик | `CREATED_BY` | Полный доступ: редактировать, удалять, контролировать |
| Исполнитель | `RESPONSIBLE_ID` | Менять статус, писать комментарии, логировать время |
| Соисполнитель | `ACCOMPLICES` | Как исполнитель, но не может менять статус задачи |
| Наблюдатель | `AUDITORS` | Только чтение + комментарии |
| Начальник | (иерархия подразделений) | Видит задачи подчинённых |
| Администратор | — | Полный доступ ко всем задачам |

**Проверка доступа:**

```php
// Получить список разрешённых действий для текущего пользователя
CRest::call('task.item.getmanifest', []);

// Проверить конкретное право
CRest::call('task.item.isactionallowed', [
    'TASK_ID' => 100,
    'ACTION' => 'ACTION_TASK_EDIT'  // или ACTION_TASK_COMPLETE, ACTION_TASK_DELETE
]);
```

### Пагинация при больших объёмах

`tasks.task.list` возвращает максимум 50 записей за запрос. Для больших выборок — цикл по `start` или `batch`:

```php
$allTasks = [];
$start = 0;

do {
    $res = CRest::call('tasks.task.list', [
        'filter' => ['GROUP_ID' => 5],
        'select' => ['ID', 'TITLE'],
        'start' => $start,
    ]);
    $tasks = $res['result']['tasks'] ?? [];
    $allTasks = array_merge($allTasks, $tasks);
    $start += 50;
} while (count($tasks) === 50);
```

Или через `batch` — до 50 команд за один HTTP-запрос:

```php
$cmds = [];
for ($i = 0; $i < 5; $i++) {
    $cmds['page' . $i] = 'tasks.task.list?' . http_build_query([
        'filter' => ['GROUP_ID' => 5],
        'start' => $i * 50,
    ]);
}
CRest::call('batch', ['cmd' => $cmds]);
```

## Вопросы для собеседования

### Q1: Чем отличается исполнитель, соисполнитель и наблюдатель?

**Ответ:**
- **Исполнитель (`RESPONSIBLE_ID`)** — один человек, отвечает за выполнение, может менять статус задачи.
- **Соисполнитель (`ACCOMPLICES`)** — массив пользователей, участвуют в работе, пишут комментарии, логируют время, но **не могут** менять статус задачи.
- **Наблюдатель (`AUDITORS`)** — массив пользователей, следят за ходом, только читают и комментируют, не участвуют в работе.

---

### Q2: Какие статусы задачи есть в Bitrix24 и как они переходят?

**Ответ:**
7 статусов:
1. Новая → 2. Ждёт выполнения → 3. В работе → 4. Условно завершена (при `TASK_CONTROL`) → 5. Завершена. Также 6. Отложена, 7. Отклонена.

`tasks.task.complete` переводит в статус 5 (без контроля) или 4 (с контролем). `tasks.task.approve` из 4 → 5, `disapprove` из 4 → 3.

---

### Q3: Как привязать задачу к сделке?

**Ответ:**
Через поле `UF_CRM_TASK` — массив строк вида `'D_123'`:

```php
'UF_CRM_TASK' => ['D_123', 'C_456']
```

Префиксы: `D_` — сделка, `C_` — контакт, `CO_` — компания, `L_` — лид. Задача появится на вкладке "Задачи" в карточке CRM-сущности.

---

### Q4: Что такое условно завершённая задача (статус 4)?

**Ответ:**
Статус, который появляется только если у задачи включён параметр `TASK_CONTROL = 'Y'`. Исполнитель нажимает "Завершить" → задача уходит постановщику на проверку в статусе 4. Постановщик либо одобряет (`approve` → статус 5), либо возвращает на доработку (`disapprove` → статус 3).

---

### Q5: Как получить просроченные задачи отдела?

**Ответ:**
Через `tasks.task.list` с фильтром по `DEADLINE` и `STATUS`:

```php
CRest::call('tasks.task.list', [
    'filter' => [
        '<DEADLINE' => date('Y-m-d'),   // Дедлайн раньше сегодня
        '!STATUS' => [5, 6, 7],          // Не завершённые
        'RESPONSIBLE_ID' => [15, 16, 17], // Сотрудники отдела
    ],
]);
```

---

### Q6: Чем `tasks.task.delegate` отличается от `tasks.task.update` с новым `RESPONSIBLE_ID`?

**Ответ:**
- **`delegate`** — корректный способ: записывает в историю делегирование, отправляет уведомления старому и новому исполнителю, проверяет права.
- **`update`** с `RESPONSIBLE_ID` — техническая замена поля, история делегирования не создаётся, уведомления могут не отправиться.

Всегда используй `delegate` для передачи задачи.

---

### Q7: Как реализовать учёт времени по задаче?

**Ответ:**
1. При создании задачи установить `ALLOW_TIME_TRACKING = 'Y'` и `TIME_ESTIMATE` (оценка в секундах).
2. Использовать `task.elapseditem.add` для добавления записей времени (`MINUTES`, `COMMENT_TEXT`, `USER_ID`).
3. Получать итог через `task.elapseditem.getlist` или поле `TIME_SPENT_IN_LOGS` в задаче.

---

### Q8: Как работает канбан для задач и что такое `task.stages`?

**Ответ:**
Канбан — визуальная доска со стадиями (колонками). Каждая стадия — запись в `task.stages`, привязанная к группе (`ENTITY_TYPE = 'G'`) или пользователю (`'U'` — планёрка "Мои задачи").

Методы:
- `task.stages.get` — список стадий
- `task.stages.add` — создать колонку
- `task.stages.movetask` — переместить задачу между колонками

Стадия задачи хранится в поле `STAGE_ID`.

---

### Q9: Какие способы массового создания задач есть?

**Ответ:**
1. **`batch`** — до 50 команд `tasks.task.add` за один HTTP-запрос.
2. **`tasks.task.add` в цикле** — медленнее, но проще для отладки.
3. **`task.item.userfield.set` + импорт** — для миграций из внешних систем.
4. **REST + очередь** — для тысяч задач (асинхронно через cron).

При больших объёмах обязательно `batch` — иначе упираешься в лимит ~2 запросов/сек.

## Частые ошибки

### Ошибка 1: `UF_CRM_TASK` передают как строку `'D_123'`, а не массив

**Проблема:** `'UF_CRM_TASK' => 'D_123'` — Bitrix не привязывает задачу.

**Решение:** Всегда массив: `'UF_CRM_TASK' => ['D_123']`

---

### Ошибка 2: Фильтр по статусу не работает

**Проблема:** `'STATUS' => 'completed'` — статусы в API это числа (1–7), а не строки.

**Решение:**
```php
'!STATUS' => [5, 6, 7]   // исключить завершённые/отложенные/отклонённые
// или
'STATUS' => 3            // только "в работе"
```

---

### Ошибка 3: `DEADLINE` в неправильном формате

**Проблема:** `'DEADLINE' => '15.11.2026'` — Bitrix не парсит, дедлайн не устанавливается.

**Решение:** ISO 8601: `'DEADLINE' => '2026-11-15T18:00:00+03:00'` или `'2026-11-15 18:00:00'`

---

### Ошибка 4: Путают `taskId` и `task_id` в параметрах методов

**Проблема:** `tasks.task.complete` ждёт `taskId` (camelCase), `task.checklistitem.add` ждёт `TASK_ID` (UPPER_CASE). Перепутал → ошибка.

**Решение:** Смотреть документацию конкретного метода. `tasks.task.*` — `taskId`, `task.*` — `TASK_ID`/`TASKID`.

---

### Ошибка 5: Нет прав на действие, но ошибка не обрабатывается

**Проблема:** `tasks.task.complete` от наблюдателя → ошибка `Access denied`, но код молча продолжает.

**Решение:**
```php
$res = CRest::call('tasks.task.complete', ['taskId' => $id]);
if (isset($res['error'])) {
    // Логируем или уведомляем
    error_log('Task complete error: ' . $res['error_description']);
}
```

---

### Ошибка 6: Выбирают все поля через `select => ['*']`

**Проблема:** `tasks.task.list` с `*` возвращает огромные объёмы данных (включая описание, UF-поля), лимит 50 записей + таймаут.

**Решение:** Указывать только нужные поля: `'select' => ['ID', 'TITLE', 'STATUS', 'DEADLINE']`
