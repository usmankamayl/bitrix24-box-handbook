# Модуль 9.4: Публикация в Bitrix24.Market

## Теория

### Что такое Bitrix24.Market

**Bitrix24.Market** — это официальный магазин приложений для Bitrix24, где разработчики публикуют свои приложения, а пользователи устанавливают их на порталы.

**Преимущества публикации:**
- Доступ к миллионам пользователей Bitrix24
- Монетизация (платные приложения, подписки)
- Маркетинговая поддержка от Bitrix
- Доверие пользователей (официальная площадка)

---

### Типы публикации

#### 1. **Локальное приложение (Private App)**

Приложение для одного портала (твоего или клиента).

**Особенности:**
- Не публикуется в Маркете
- Устанавливается через dev.bitrix24.ru → "Добавить приложение"
- Используется для внутренних интеграций
- Не требует модерации

**Когда использовать:**
- Интеграция с 1С для конкретного клиента
- Внутренние инструменты компании
- Тестирование перед публикацией в Маркет

---

#### 2. **Публичное приложение (Public App)**

Приложение, опубликованное в Bitrix24.Market для всех пользователей.

**Особенности:**
- Проходит модерацию (1–3 дня)
- Требует заполнения карточки приложения
- Доступно всем пользователям Bitrix24
- Может быть бесплатным или платным

**Требования:**
- HTTPS для всех URL
- Политика конфиденциальности
- Контакты поддержки
- Рабочая функциональность
- Описание на русском и английском

---

#### 3. **Коробочное приложение (On-premise App)**

Приложение для коробочных версий Bitrix24.

**Особенности:**
- Устанавливается вручную администратором
- Нет OAuth (используется Incoming Webhook)
- Полный доступ к API коробки

---

### Регистрация приложения в Bitrix24.Market

#### Шаг 1: Создание приложения

1. Переходишь на https://dev.bitrix24.ru/marketplace/
2. Нажимаешь "Создать приложение"
3. Выбираешь тип:
   - **Внешнее** — работает на твоем сервере
   - **Встраиваемое** — отображается в интерфейсе Bitrix24

#### Шаг 2: Настройка параметров

```
Название: Мой интегратор CRM
Описание: Автоматическая синхронизация с 1С
Redirect URI: https://your-domain.com/oauth-callback.php
Scope: crm,task,user,placement
Install URL: https://your-domain.com/install.php
```

**Параметры:**

- **Redirect URI** — URL для OAuth-редиректа после авторизации
- **Scope** — права доступа (CRM, задачи, пользователи и т.д.)
- **Install URL** — URL, который вызывается при установке приложения
- **Menu URL** — URL главной страницы приложения (если встраиваемое)

#### Шаг 3: Получение ключей

После создания получаешь:

```
CLIENT_ID: local.abc123xyz
CLIENT_SECRET: secret_key_here
```

### OAuth 2.0 для публичных приложений

#### Установка приложения (flow)

```
Пользователь нажимает "Установить" в Маркете
         ↓
Bitrix24 перенаправляет на Install URL
         ↓
Приложение получает code (авторизационный код)
         ↓
Приложение делает запрос на /oauth/token/
         ↓
Получает access_token и refresh_token
         ↓
Сохраняет токены в БД для этого портала
         ↓
Перенаправляет пользователя обратно в Bitrix24
```

#### Код установки (install.php)

```php
<?php
$code = $_GET['code'] ?? null;
$domain = $_GET['domain'] ?? null;

if (!$code) {
    die('Authorization code not found');
}

// Обмениваем код на токены
$tokenUrl = "https://oauth.bitrix.info/oauth/token/";
$params = [
    'grant_type' => 'authorization_code',
    'client_id' => 'local.abc123xyz',
    'client_secret' => 'secret_key_here',
    'code' => $code,
    'redirect_uri' => 'https://your-domain.com/install.php'
];

$ch = curl_init($tokenUrl . '?' . http_build_query($params));
curl_setopt($ch, CURLOPT_RETURNTRANSFER, true);
$response = curl_exec($ch);
curl_close($ch);

$tokens = json_decode($response, true);

if (isset($tokens['access_token'])) {
    // Сохраняем в БД
    saveTokens($domain, $tokens['access_token'], $tokens['refresh_token'], $tokens['member_id']);
    
    // Перенаправляем обратно
    header('Location: https://' . $domain . '/marketplace/app/' . $tokens['member_id'] . '/');
    exit;
}
?>
```

### Заполнение карточки приложения

#### Основная информация

**Название (RU/EN):**
- Короткое и понятное (макс. 50 символов)
- Пример: "Интеграция с 1С" / "1C Integration"

**Краткое описание (RU/EN):**
- Одно предложение (макс. 100 символов)
- Пример: "Автоматическая синхронизация заказов и клиентов между Bitrix24 и 1С"

**Полное описание (RU/EN):**
- 3–5 абзацев
- Что делает приложение
- Какие проблемы решает
- Ключевые функции
- Требования (если есть)

**Категория:**
- CRM
- Автоматизация
- Телефония
- Отчеты
- Интеграции
- Другое

### Модерация приложения

#### Что проверяет модератор

1. **Работоспособность:**
   - Приложение устанавливается без ошибок
   - Все заявленные функции работают
   - Нет критических багов

2. **Описание:**
   - Соответствует реальности
   - Нет спама и недостоверной информации
   - Переведено на русский и английский

3. **Безопасность:**
   - HTTPS для всех URL
   - Нет подозрительных скоупов (например, не просишь `user` для простого виджета)
   - Нет вредоносного кода

4. **Пользовательский опыт:**
   - Понятный интерфейс
   - Нет битых ссылок
   - Корректная работа с данными

---

#### Типичные причины отказа

| Причина | Как исправить |
|---------|---------------|
| HTTP вместо HTTPS | Настрой SSL-сертификат |
| Приложение падает при установке | Проверь код install.php |
| Описание не соответствует функционалу | Обнови описание или функционал |
| Нет политики конфиденциальности | Создай страницу с политикой |
| Скриншоты низкого качества | Сделай скриншоты 1200×800 |
| Приложение требует ручной настройки | Добавь инструкцию в описание |

### Монетизация приложения

#### Модели монетизации

**1. Разовая оплата (One-time)**
- Пользователь платит один раз
- Приложение работает бессрочно
- Пример: $99 за приложение

**2. Подписка (Subscription)**
- Пользователь платит ежемесячно/ежегодно
- Приложение работает пока активна подписка
- Пример: $10/месяц

**3. Freemium**
- Базовая версия бесплатна
- Расширенные функции — платные
- Оплата через приложение (in-app purchase)

**4. Платные обновления**
- Базовая версия бесплатна
- Обновления — платные (раз в год)

---

#### Интеграция платежей

Для платных приложений используешь **Bitrix24.Market API**:

```php
// Проверка статуса подписки
$subscriptionStatus = CRest::call('app.subscription.get', [
    'member_id' => $member_id
]);

if ($subscriptionStatus['result']['STATUS'] === 'trial') {
    // Пробный период
} elseif ($subscriptionStatus['result']['STATUS'] === 'paid') {
    // Оплачено
} else {
    // Подписка не активна
}
```

## Вопросы для собеседования

### Q1: Чем отличается локальное приложение от публичного?

**Ответ:**
- **Локальное** — для одного портала, устанавливается вручную через dev.bitrix24.ru, не требует модерации, используется для внутренних интеграций.
- **Публичное** — публикуется в Маркете, доступно всем пользователям, проходит модерацию, требует карточки приложения и политики конфиденциальности.

---

### Q2: Как опубликовать приложение в Маркете?

**Ответ:**
1. Создаешь приложение на dev.bitrix24.ru/marketplace
2. Настраиваешь параметры (Redirect URI, Scope, Install URL)
3. Разрабатываешь и тестируешь на тестовом портале
4. Заполняешь карточку: название, описание, скриншоты, цена
5. Отправляешь на модерацию
6. Проходишь проверку (1–3 дня)
7. Приложение публикуется в Маркете

---

### Q3: Что проверяет модератор при публикации?

**Ответ:**
- Работоспособность приложения (устанавливается и работает)
- Соответствие описания функционалу
- HTTPS для всех URL
- Наличие политики конфиденциальности
- Качество скриншотов
- Отсутствие вредоносного кода

---

### Q4: Как работает OAuth для публичных приложений?

**Ответ:**
1. Пользователь нажимает "Установить" → Bitrix24 перенаправляет на Install URL с параметром `code`
2. Приложение обменивает `code` на `access_token` и `refresh_token` через `/oauth/token/`
3. Сохраняет токены в БД для этого портала
4. Использует `access_token` для вызовов REST API
5. Когда токен истекает — обновляет через `refresh_token`

## Частые ошибки

### Ошибка 1: Приложение не устанавливается

**Причина:** Неправильный Install URL или ошибка в коде.

**Решение:** Проверь логи на сервере, убедись что install.php отвечает HTTP 200.

### Ошибка 2: OAuth-токены не сохраняются

**Причина:** Не передается параметр `code` или неправильный `redirect_uri`.

**Решение:** Проверь параметры в dev.bitrix24.ru — redirect_uri должен точно совпадать с URL install.php.

### Ошибка 3: Приложение отклонено модератором

**Причина:** Недостаточно информации в описании или баги.

**Решение:** Читай комментарий модератора, исправляй, отправляй снова.

### Ошибка 4: Не работает проверка подписки

**Причина:** Метод `app.subscription.get` доступен только для платных приложений.

**Решение:** Используй только если приложение платное или freemium.
