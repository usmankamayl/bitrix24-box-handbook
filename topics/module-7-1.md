# Модуль 7.1: Структура CRM: Лиды, Сделки, Контакты, Компании

## Теория

### Основные сущности Bitrix24 CRM

Bitrix24 CRM построена вокруг четырех основных сущностей, которые связаны между собой и отражают типичный цикл продаж:

#### 1. **Лиды (Leads)**
Лид — это потенциальный клиент, начальный этап взаимодействия с компанией.

**Особенности:**
- Лид может быть преобразован в Сделку или Контакт
- Используется для сбора информации о потенциальных клиентах
- Может быть связан с несколькими сделками
- Содержит базовую информацию: ФИО, телефон, email, источник

**Типичный жизненный цикл:**
```
Новый лид → Квалификация → Сделка/Отказ → Закрыто
```

#### 2. **Сделки (Deals)**
Сделка — это конкретная коммерческая возможность, согласованное действие по продаже.

**Особенности:**
- Сделка должна быть связана с Компанией или Контактом
- Имеет стадию, вероятность закрытия, сумму
- Может быть привязана к Лиду (источник)
- Может содержать несколько произведений (товары/услуги)

**Основные поля:**
- `title` — название сделки
- `stage_id` — стадия сделки (в воронке)
- `probability` — вероятность закрытия (%)
- `sum` — сумма сделки
- `company_id` — ID связанной компании
- `contact_ids` — ID связанных контактов

#### 3. **Контакты (Contacts)**
Контакт — это физическое лицо, с которым работает компания.

**Особенности:**
- Может быть сотрудником компании
- Может быть связан с одной или несколькими сделками
- Хранит личную информацию (ФИО, должность, контакты)
- Может быть связан с Лидом (если лид был преобразован)

**Основные поля:**
- `name` — полное имя
- `phone` — номер телефона
- `email` — email адрес
- `company_id` — ID компании, в которой работает
- `job_title` — должность

#### 4. **Компании (Companies)**
Компания — это юридическое лицо или организация.

**Особенности:**
- Центральная сущность, к которой привязываются контакты и сделки
- Хранит реквизиты организации
- Может содержать несколько контактов
- Может быть связана с несколькими сделками

**Основные поля:**
- `title` — название компании
- `phone` — телефон компании
- `email` — email компании
- `web` — веб-сайт
- `industry` — отрасль

### Связи между сущностями

```
┌─────────────────┐
│     Лид (Lead)  │
└────────┬────────┘
         │ преобразуется в
         ▼
    ┌────────────────────────────────────────┐
    │   ┌──────────────┐      ┌──────────┐  │
    │   │ Контакт      │      │ Сделка   │  │
    │   │ (Contact)    │◄─────►(Deal)    │  │
    │   └──────┬───────┘      └────┬─────┘  │
    │          │ работает в        │        │
    │          │                   │        │
    │          └───────►┌──────────┴─┐     │
    │                   │ Компания   │     │
    │                   │ (Company)  │     │
    │                   └────────────┘     │
    └────────────────────────────────────────┘
```

**Типичный сценарий:**
1. Поступает Лид (потенциальный клиент)
2. После квалификации создается Контакт (ФИО, должность)
3. Уточняется компания Контакта, создается или берется существующая Компания
4. Открывается первая Сделка
5. По мере продвижения Сделка переходит по стадиям

### REST API - Основные методы

#### Работа с Лидами
```php
// Получить лид
GET /crm.lead.get?id={leadId}

// Создать лид
POST /crm.lead.add
{
    "fields": {
        "TITLE": "Название лида",
        "NAME": "Имя",
        "PHONE": "79991234567",
        "EMAIL": "example@mail.com",
        "SOURCE_ID": "WEB"
    }
}

// Обновить лид
POST /crm.lead.update
{
    "id": 123,
    "fields": {
        "TITLE": "Новое название"
    }
}

// Список лидов с фильтром
GET /crm.lead.list?filter[>=DATE_CREATE]=2024-01-01
```

#### Работа со Сделками
```php
// Создать сделку
POST /crm.deal.add
{
    "fields": {
        "TITLE": "Название сделки",
        "STAGE_ID": "C1:1",  // Стадия в воронке
        "COMPANY_ID": 456,
        "CONTACT_IDS": [123],
        "OPPORTUNITY": 50000,  // Сумма сделки
        "PROBABILITY": 80
    }
}

// Переместить сделку на другую стадию
POST /crm.deal.update
{
    "id": 789,
    "fields": {
        "STAGE_ID": "C1:3"  // Следующая стадия
    }
}

// Получить список сделок определенной компании
GET /crm.deal.list?filter[COMPANY_ID]=456
```

#### Работа с Контактами
```php
// Создать контакт
POST /crm.contact.add
{
    "fields": {
        "NAME": "Иван",
        "LAST_NAME": "Петров",
        "PHONE": "79991234567",
        "EMAIL": "ivan@mail.com",
        "COMPANY_ID": 456,
        "JOB_TITLE": "Менеджер по продажам"
    }
}

// Получить контакты компании
GET /crm.contact.list?filter[COMPANY_ID]=456
```

#### Работа с Компаниями
```php
// Создать компанию
POST /crm.company.add
{
    "fields": {
        "TITLE": "ООО Рога и Копыта",
        "PHONE": "79991234567",
        "EMAIL": "info@mail.com",
        "WEB": "https://example.com",
        "INDUSTRY": "IT"
    }
}

// Получить компанию
GET /crm.company.get?id=456
```

### Воронки и Стадии

**Что такое воронка?**
Воронка (Pipeline) — это набор стадий, через которые проходит Сделка. Каждая воронка может быть кастомизирована под специфику бизнеса.

**ID стадий:**
- `C1:1`, `C1:2`, `C1:3` — стадии воронки "Продажи"
- `C2:1`, `C2:2` — стадии воронки "Поддержка"
- `C3:1` — стадии кастомных воронок

**Поля стадии:**
- `STAGE_ID` — ID стадии в формате `ВОРОНКА:ПОЗИЦИЯ`
- `DATE_MODIFY` — когда сделка была перемещена
- `PROBABILITY` — вероятность закрытия на этой стадии

### Пользовательские поля (Custom Fields)

Каждая из четырех сущностей может иметь пользовательские поля:

```php
// Получить пользовательские поля контакта
GET /crm.contact.fields

// Результат содержит стандартные и кастомные поля:
{
    "NAME": { "type": "text", ... },
    "PHONE": { "type": "phone", ... },
    "UF_CRM_CONTACT_CUSTOM": { "type": "text", ... }  // Кастомное поле
}
```

**Типы кастомных полей:**
- `text` — текст
- `textarea` — многострочный текст
- `url` — ссылка
- `enumeration` — выпадающий список
- `date` — дата
- `datetime` — дата и время
- `boolean` — да/нет
- `user` — пользователь системы

### Частые ошибки и best practices

**❌ Ошибка 1: Создание Сделки без связи**
Сделка должна быть связана минимум с Компанией или Контактом. Несвязанная сделка — потеря данных.

```php
// ❌ ПЛОХО
POST /crm.deal.add
{
    "fields": {
        "TITLE": "Сделка"
        // Нет COMPANY_ID или CONTACT_IDS
    }
}

// ✅ ХОРОШО
POST /crm.deal.add
{
    "fields": {
        "TITLE": "Сделка",
        "COMPANY_ID": 123,  // Обязательно указываем компанию
        "CONTACT_IDS": [456]  // Или контакты
    }
}
```

**❌ Ошибка 2: Некорректная стадия**
ID стадии должен быть в формате `ВОРОНКА:ПОЗИЦИЯ`. Неверный формат приведет к ошибке.

```php
// ❌ ПЛОХО
"STAGE_ID": "1"  // Неполный ID

// ✅ ХОРОШО
"STAGE_ID": "C1:1"  // Полный ID воронки и стадии
```

**❌ Ошибка 3: Дублирование Контактов и Компаний**
Перед созданием новой сущности нужно проверить, не существует ли она уже.

```php
// ✅ ХОРОШО: сначала ищем, потом создаем
GET /crm.contact.list?filter[EMAIL]=ivan@mail.com
// Если не найдена → создаем
POST /crm.contact.add
```

**✅ Best Practice 1: Используйте трансакции для связанных данных**
Если нужно создать Компанию, Контакт и Сделку, используйте batch-запросы:

```php
POST /batch
{
    "requests": [
        { "method": "crm.company.add", "params": { "fields": {...} } },
        { "method": "crm.contact.add", "params": { "fields": {...} } },
        { "method": "crm.deal.add", "params": { "fields": {...} } }
    ]
}
```

**✅ Best Practice 2: Валидируйте данные перед отправкой**
Проверяйте формат номеров телефонов, email адресов, сумм денег.

**✅ Best Practice 3: Обрабатывайте ошибки правильно**
- Проверяйте, существует ли сущность перед обновлением
- Обрабатывайте случаи, когда сущность удалена
- Логируйте ошибки для отладки

## Вопросы для собеседования

### Q1: Что такое Лид и Сделка в Bitrix24? Какова разница?
**A:** 
- **Лид** — это потенциальный клиент на начальном этапе (начальные данные о контакте)
- **Сделка** — это конкретная коммерческая возможность с суммой, сроками и стадией
- Лид может быть преобразован в Сделку, но это не одно и то же
- Несколько лидов могут перейти в одну сделку

### Q2: Как связаны Контакт, Компания и Сделка?
**A:**
- Сделка должна быть связана с минимум одной Компанией или Контактом
- Контакт работает в Компании (COMPANY_ID)
- Сделка может быть привязана к одной Компании и нескольким Контактам
- Это отражает реальный бизнес-процесс: Сделка ведется с Компанией, но общение происходит с Контактом (человеком)

### Q3: Что такое стадия сделки и как она используется?
**A:**
- Стадия — это этап в жизненном цикле сделки (например, "Переговоры", "Подготовка контракта")
- ID стадии имеет формат `ВОРОНКА:ПОЗИЦИЯ` (например, `C1:3`)
- При перемещении сделки на новую стадию обновляется `STAGE_ID` и `DATE_MODIFY`
- Разные воронки могут иметь разные стадии в зависимости от типа бизнеса

### Q4: Какие основные REST API методы для работы с CRM?
**A:**
- `crm.lead.add/update/delete/get/list` — управление лидами
- `crm.deal.add/update/delete/get/list` — управление сделками
- `crm.contact.add/update/delete/get/list` — управление контактами
- `crm.company.add/update/delete/get/list` — управление компаниями
- `/batch` — пакетные запросы для группировки операций

### Q5: Как избежать дублирования контактов и компаний?
**A:**
- Перед созданием нового контакта нужно проверить существующие по email или телефону
- Использовать фильтры в `crm.contact.list` и `crm.company.list`
- Если контакт найден, обновить его (UPDATE) вместо создания нового (ADD)
- Это улучшает качество данных и предотвращает потерю информации

### Q6: Какие типы пользовательских полей поддерживает CRM?
**A:**
- `text`, `textarea` — текстовые поля
- `url` — поле с ссылкой
- `enumeration` — выпадающий список (с предустановленными значениями)
- `date`, `datetime` — даты
- `boolean` — галочка да/нет
- `user` — выбор пользователя из системы
- Кастомные поля имеют префикс `UF_CRM_` (User Field)

### Q7: Как правильно создать сделку с минимальными данными?
**A:**
```
Минимально необходимые поля:
- TITLE — название сделки
- STAGE_ID — стадия (например, C1:1)
- COMPANY_ID или CONTACT_IDS — связь с компанией или контактом
- OPPORTUNITY (опционально) — сумма сделки

Пример: 
POST /crm.deal.add
{
    "fields": {
        "TITLE": "Новая сделка",
        "STAGE_ID": "C1:1",
        "COMPANY_ID": 123
    }
}
```

### Q8: Какие данные содержит стандартный Контакт?
**A:**
- Имя и фамилия (NAME, LAST_NAME)
- Email и телефоны (EMAIL, PHONE, PHONE_MOBILE)
- Должность (JOB_TITLE)
- Компания, в которой работает (COMPANY_ID)
- Дата создания и последнего изменения (DATE_CREATE, DATE_MODIFY)
- Ответственный пользователь (ASSIGNED_BY_ID)
- Источник (SOURCE_ID) — откуда пришел контакт

### Q9: Какие воронки есть в стандартной Bitrix24?
**A:**
- **C1** — воронка "Продажи" (стадии 1, 2, 3 и т.д. для типичного цикла продаж)
- **C2** — воронка "Поддержка" (для работы с уже существующими клиентами)
- **C3+** — кастомные воронки, которые можно создать под специфику бизнеса

### Q10: Как получить все сделки конкретной компании?
**A:**
```
GET /crm.deal.list?filter[COMPANY_ID]=123

Результат будет содержать массив сделок, привязанных к этой компании.
Можно добавить сортировку, фильтры по стадии, сумме и т.д.:

GET /crm.deal.list?filter[COMPANY_ID]=123&filter[STAGE_ID]=C1:3&order[SUM]=desc
```
