# Модуль 10.3: Email-маркетинг и рассылки (Bitrix24)

## Теория

### CRM-маркетинг в Bitrix24

**CRM-маркетинг** — инструмент массовой и сегментной рассылки писем, SMS и рекламных кампаний из Bitrix24. Расположен в разделе **CRM → Маркетинг**.

**Основные понятия:**

| Понятие | Описание |
|---------|----------|
| **Сегмент** | Динамическая или статическая выборка контактов, компаний, лидов для рассылки |
| **Кампания** | Отдельная рассылка (письмо, SMS, реклама) с датой отправки и статистикой |
| **Рассылка** | Конкретное письмо, отправленное сегменту |
| **Черный список** | Адреса, отписавшиеся или с "hard bounce" — не получают рассылок |

**Типы каналов CRM-маркетинга:**
- Email-рассылка
- SMS-рассылка
- Робоколы
- Веб-пуш уведомления
- Рекламная аудитория (Facebook, Google, Яндекс, VK)

---

### Сегменты

**Сегмент** — выборка получателей по критериям.

**Виды сегментов:**
- **Статический** — фиксированный список ID сущностей
- **Динамический** — пересчитывается перед каждой отправкой (фильтр по полям CRM)

**Источники сегмента:**
- Контакты
- Компании
- Лиды
- Сделки (берутся связанные контакты/компании)

**Фильтрация:**
Сегмент строится по полям сущности: стадия сделки, город, ответственный, дата создания, пользовательские поля (UF_*).

В коробочной версии сегменты хранятся в таблице `b_sender_mailing_chain` / `b_sender_contact_list` модуля **sender**.

### Отправка email из карточки CRM: crm.message.add

Метод **`crm.message.add`** отправляет email сообщение от имени пользователя портала контакту/лиду/компании. Письмо сохраняется в истории дела (timeline).

```php
$result = CRest::call('crm.message.add', [
    'fields' => [
        'ENTITY_TYPE_ID' => 3,        // 1 — лид, 3 — контакт, 4 — компания, 2 — сделка
        'ENTITY_ID' => 123,           // ID контакта
        'SUBJECT' => 'Предложение по проекту',
        'MESSAGE' => 'Здравствуйте, <b>Иван</b>!<br>Отправляю вам КП.',
        'FROM' => 'manager@company.com', // Адрес подключённого почтового ящика
    ]
]);
```

**Важно:**
- Email-адрес получателя берётся из multifield `EMAIL` сущности (первый валидный)
- Отправка идёт через почтовый ящик, подключённый в Bitrix24 (CRM → Ещё → Настройки → Почта)
- Письмо появляется в timeline сущности
- Метод подходит для **транзакционных** писем (КП, счёт, уведомление), но НЕ для массовых рассылок — для них используют CRM-маркетинг или внешние сервисы

**Ограничения:**
- Нет встроенной персонализации (подстановку полей делаешь сам)
- Нет трекинга открытий
- Лимиты REST: ~2 запроса/сек — для сотен писем нужна очередь + `batch`

---

### Почтовые события и шаблоны (связь с модулем 3.3)

В **коробочной версии** отправка писем работает через почтовые события:

```php
CEvent::Send('NEW_USER_MESSAGE', 's1', [
    'EMAIL_TO' => 'user@example.com',
    'SUBJECT' => 'Тема',
    'MESSAGE' => 'Текст письма',
]);
```

**Почтовое событие** — тип письма (регистрация, сброс пароля, заказ). **Шаблон** — HTML/текст с макросами `#EMAIL_TO#`, `#MESSAGE#` и др.

В **облачном Bitrix24** почтовые события недоступны — все письма идут через REST (`crm.message.add`, `im.notify` и т.п.) или через инфраструктуру CRM-маркетинга.

### Модуль Sender (коробочная версия)

**Sender** — модуль email/SMS-рассылок в коробочной версии. Ключевые классы:

| Класс | Назначение |
|-------|------------|
| `\Bitrix\Sender\MailingTable` | Кампания (рассылка) |
| `\Bitrix\Sender\MailingChainTable` | Письмо внутри кампании |
| `\Bitrix\Sender\GroupTable` | Сегмент (группа получателей) |
| `\Bitrix\Sender\PostingTable` | Отправка (постинг) — статус, статистика |
| `\Bitrix\Sender\ContactTable` | Получатели |
| `\Bitrix\Sender\BlackListTable` | Черный список |

**Пример: создание рассылки программно:**

```php
use Bitrix\Sender\MailingTable;
use Bitrix\Sender\GroupTable;

$group = GroupTable::add([
    'NAME' => 'Активные клиенты',
]);

$mailing = MailingTable::add([
    'NAME' => 'Осенняя акция',
    'ACTIVE' => 'Y',
    'STATUS' => 'new',
]);

$chain = \Bitrix\Sender\MailingChainTable::add([
    'MAILING_ID' => $mailing->getId(),
    'NAME' => 'Письмо 1',
    'SUBJECT' => 'Скидка 20% на все товары',
    'MESSAGE' => '<p>Только до конца недели!</p>',
    'MESSAGE_TYPE' => 'html',
    'EMAIL_FROM' => 'sales@company.com',
    'STATUS' => 'send',
]);
```

### Работа с адресами: multifield EMAIL

Email-адреса контактов/лидов/компаний хранятся в поле **`EMAIL`** типа **multifield** — массив значений с типами.

```json
"EMAIL": [
    {"ID": "456", "VALUE_TYPE": "WORK", "VALUE": "work@client.com"},
    {"ID": "457", "VALUE_TYPE": "HOME", "VALUE": "home@client.com"}
]
```

**Типы VALUE_TYPE:** `WORK`, `HOME`, `MOBILE`, `MAILING`, `OTHER`.

**Важно для рассылок:** `VALUE_TYPE = 'MAILING'` — специальный тип для маркетинговых писем. Также полезен флаг `VALUE_TYPE` при выборе основного email.

**REST-методы для multifield:**
- `crm.duplicate.findbycomm` — поиск дублей по email/телефону
- `crm.contact.list` с `select: ['EMAIL']` — чтение адресов

**Адреса (юридические) — `crm.address.*`:** это реквизиты контактов/компаний (страна, город, улица) — НЕ путать с email-адресами.

```php
// Поиск контакта по email
$dups = CRest::call('crm.duplicate.findbycomm', [
    'type' => 'EMAIL',
    'values' => ['client@example.com']
]);
```

### Трекинг открытий и кликов

**Открытия:** в HTML-письмо вставляется невидимый пиксель `<img src="https://track.example.com/pixel.php?id=123" width="1" height="1">`. Когда почтовый клиент загружает картинку — фиксируется открытие.

**Клики:** ссылки оборачиваются через редирект `https://track.example.com/click.php?to=...&id=123`.

**В Bitrix24:**
- CRM-маркетинг автоматически добавляет трекинг в рассылки
- Статистика доступна в карточке кампании: доставлено / открыто / кликнуло / отписалось / bounce
- В облаке статистику через REST можно получить методами `crm.channel.*` / отчетами маркетинга (ограниченно)

**Отписки (unsubscribe):**
- В каждое письмо добавляется ссылка `#UNSUBSCRIBE_LINK#`
- Отписавшийся попадает в черный список и больше не получает рассылок
- Обязательно по законодательству (CAN-SPAM, GDPR, 152-ФЗ)

### Интеграция с внешними сервисами рассылок

Для серьезного email-маркетинга Bitrix24 интегрируют с внешними сервисами:

| Сервис | Особенности |
|--------|-------------|
| **Unisender** | Популярен в СНГ, есть готовая интеграция |
| **Mailchimp** | Мировой стандарт, REST API v3 |
| **SendPulse** | Email + push + SMS |
| **DashaMail** | Российский, дешёвый |

**Архитектура интеграции (типовая):**

```
Bitrix24 (контакты)                    Внешний сервис
      |                                      |
      |-- crm.contact.list (сегмент) ----->  importContacts API
      |                                      |
      |-- Событие OnCrmContactUpdate ----->  syncContact API
      |                                      |
      |<-- Webhook: открытия, bounce ----   statistics API
```

**Пример синхронизации контакта в Mailchimp:**

```php
$ch = curl_init('https://us1.api.mailchimp.com/3.0/lists/LIST_ID/members/' . md5(strtolower($email)));
curl_setopt_array($ch, [
    CURLOPT_USERPWD => 'anystring:API_KEY',
    CURLOPT_CUSTOMREQUEST => 'PUT',
    CURLOPT_POSTFIELDS => json_encode([
        'email_address' => $email,
        'status' => 'subscribed',
        'merge_fields' => ['FNAME' => $name]
    ]),
    CURLOPT_RETURNTRANSFER => true,
]);
curl_exec($ch);
```

## Вопросы для собеседования

### Q1: Чем отличается `crm.message.add` от рассылки через CRM-маркетинг?

**Ответ:**
- `crm.message.add` — отправка одного письма из карточки CRM (транзакционное). Письмо сохраняется в timeline, но нет трекинга, персонализации, управления отписками.
- CRM-маркетинг — массовая рассылка с сегментами, шаблонами, трекингом открытий/кликов, черным списком и статистикой.

Для «написать клиенту КП» используешь `crm.message.add`, для «разослать акцию 5000 контактам» — CRM-маркетинг или внешний сервис.

---

### Q2: Как получить все email-адреса контакта через REST?

**Ответ:**

```php
$contact = CRest::call('crm.contact.get', ['id' => 123]);
$emails = $contact['result']['EMAIL']; // массив multifield

foreach ($emails as $e) {
    echo $e['VALUE'] . ' (' . $e['VALUE_TYPE'] . ')';
}
```

Поле `EMAIL` — multifield: массив `VALUE` + `VALUE_TYPE` (WORK, HOME, MAILING и др.).

---

### Q3: Как найти контакт по email-адресу?

**Ответ:**
Через `crm.duplicate.findbycomm`:

```php
$result = CRest::call('crm.duplicate.findbycomm', [
    'type' => 'EMAIL',
    'values' => ['client@example.com']
]);
$contactIds = $result['result']['CONTACT'] ?? [];
```

Это быстрее и надёжнее, чем фильтровать `crm.contact.list` — multifield нельзя использовать как фильтр в `list`.

---

### Q4: Что такое модуль Sender в коробочной версии?

**Ответ:**
Модуль `sender` — движок рассылок в коробочной версии Bitrix24. Реализует:
- Кампании (`MailingTable`) и письма внутри них (`MailingChainTable`)
- Сегменты (`GroupTable`)
- Отправки с трекингом (`PostingTable`)
- Черный список отписавшихся (`BlackListTable`)

Код рассылок CRM-маркетинга в облаке тоже построен на sender, но скрыт за интерфейсом.

---

### Q5: Как работает трекинг открытий писем?

**Ответ:**
В HTML-письмо вставляется прозрачный пиксель `<img src=".../pixel.php?id=UNIQUE_ID" width="1" height="1">`. Когда получатель открывает письмо и почтовый клиент загружает картинку — сервер трекинга фиксирует открытие.

Ограничения:
- Если клиент блокирует картинки — открытие не засчитается
- Некоторые почтовики (Gmail) проксируют картинки — трекинг работает, но IP/гео искажаются
- Apple Mail Privacy Protection искусственно завышает открытия

---

### Q6: Как организовать отписку от рассылки?

**Ответ:**
1. В письмо добавляется уникальная ссылка `https://your-site.com/unsubscribe.php?email=...&token=...`
2. По клику адрес заносится в черный список (`BlackListTable` в коробке / `crm.address` черный список в облаке)
3. Перед отправкой рассылки адреса черного списка исключаются из сегмента

Ссылка отписки **обязательна** по закону (CAN-SPAM, 152-ФЗ, GDPR).

---

### Q7: Как массово отправить письма через REST без падения по лимитам?

**Ответ:**
- Используй `batch` — до 50 `crm.message.add` в одном запросе
- Между batch — пауза 0.5–1 сек (лимит ~2 запроса/сек)
- Для больших объёмов — очередь на своей стороне (CRON + таблица задач)
- Альтернатива — внешний сервис рассылок (Unisender, Mailchimp), который спроектирован под массовую отправку и даёт трекинг

---

### Q8: Что нужно учесть при интеграции с Mailchimp/Unisender?

**Ответ:**
- Двусторонняя синхронизация: Bitrix24 → сервис (контакты, сегменты) и сервис → Bitrix24 (статистика, отписки через вебхуки)
- Маппинг полей: `EMAIL` multifield → email в сервисе, `NAME`/`LAST_NAME` → merge fields
- Обработка bounce и отписок: адрес надо исключить и в Bitrix24 тоже (черный список)
- Дедупликация: проверка через `crm.duplicate.findbycomm` перед импортом
- Rate limits внешнего API — батч-эндпоинты

## Частые ошибки

### Ошибка 1: Письмо не отправляется через `crm.message.add`

**Причина:** Не подключён почтовый ящик в Bitrix24 или указан неверный `FROM`.

**Решение:** Проверь в CRM → Настройки → Почта, что ящик подключён. `FROM` должен точно совпадать с адресом ящика.

### Ошибка 2: Письмо уходит, но получатель не тот

**Причина:** `crm.message.add` берёт первый валидный email из multifield `EMAIL` — а там может быть старый/неправильный адрес.

**Решение:** Перед отправкой проверяй `EMAIL` контакта. Если адресов несколько — лучше хранить "маркетинговый" email с `VALUE_TYPE = 'MAILING'`.

### Ошибка 3: Массовая отправка падает с 503

**Причина:** Лимиты REST (~2 запроса/сек). Цикл `foreach` без пауз сотнями вызывает `crm.message.add`.

**Решение:** Используй `batch` (50 вызовов за запрос) + `usleep(500000)` между батчами. Для тысяч писем — очередь через CRON.

### Ошибка 4: Фильтрую контакты по EMAIL в crm.contact.list — пустой результат

**Причина:** Поле `EMAIL` — multifield, его нельзя использовать в `filter` `crm.contact.list`.

**Решение:** Используй `crm.duplicate.findbycomm` для поиска по email, или выгружай все контакты и фильтруй на своей стороне.

### Ошибка 5: Отписавшиеся всё равно получают письма

**Причина:** Самописная рассылка не проверяет черный список.

**Решение:** Перед отправкой проверяй адрес против черного списка (в коробке — `BlackListTable`, в облаке — список исключений CRM-маркетинга). Храни собственный черный список при интеграции с внешними сервисами.

### Ошибка 6: Письма попадают в спам

**Причина:** Нет SPF/DKIM/DMARC для домена отправителя, нет ссылки отписки, подозрительный контент.

**Решение:** Настрой SPF/DKIM для домена, добавь ссылку отписки, используй подтверждённый ящик отправителя, разогревай репутацию домена постепенно.
