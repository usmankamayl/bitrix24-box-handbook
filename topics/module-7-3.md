# Модуль 7.3: Бизнес-процессы и роботы в Bitrix24

## Теория

### Что такое бизнес-процессы в Bitrix24?

**Бизнес-процессы (БП)** — это автоматизированные последовательности действий, которые запускаются при определенных условиях в CRM. Они позволяют автоматизировать рутинные операции, согласования, уведомления и другие процессы.

В Bitrix24 есть два основных механизма автоматизации:
1. **Роботы** — простые автоматические действия на стадиях воронки
2. **Бизнес-процессы** — сложные сценарии с ветвлением, условиями и параллельными задачами

### Роботы (Automation Rules)

**Роботы** — это правила автоматизации, привязанные к конкретным стадиям сделки, лида или другой сущности CRM.

#### Типы роботов:

1. **Системные роботы** (встроенные):
   - Изменить стадию
   - Создать дело
   - Отправить письмо
   - Отправить SMS
   - Webhook
   - Создать документ
   - Изменить ответственного
   - Установить значения полей

2. **Пользовательские роботы** (через REST API):
   - Интеграция с внешними системами
   - Кастомная логика обработки

#### Когда запускаются роботы:

- **При входе на стадию** — когда сделка попадает на эту стадию
- **При выходе со стадии** — перед переходом на следующую стадию
- **На стадии** — пока сделка находится на стадии (по расписанию)

### Триггеры (Triggers)

**Триггеры** — это условия, которые автоматически перемещают сделку между стадиями при выполнении определенных условий.

#### Примеры триггеров:

- При создании дела переместить на стадию "Встреча назначена"
- При получении оплаты переместить в "Успешно реализовано"
- При изменении поля переместить на стадию
- При отсутствии активности N дней переместить в "Холодные"

### Бизнес-процессы (Business Processes)

**Бизнес-процессы** — более сложные сценарии автоматизации с:
- Ветвлением (условия if/else)
- Параллельными задачами
- Согласованиями
- Задержками и таймаутами
- Циклами

#### Элементы бизнес-процесса:

1. **Действия** — операции (создать задачу, отправить письмо)
2. **Условия** — проверки (если поле = значение)
3. **Ветвления** — разделение потока на несколько веток
4. **Задержки** — паузы на определенное время
5. **Циклы** — повторение действий

### REST API для работы с автоматизацией

#### Работа с роботами

```php
// Получить список роботов на стадии сделки
CRest::call('bizproc.robot.list', [
    'DOCUMENT_TYPE' => ['crm', 'CCrmDocumentDeal', 'DEAL']
]);

// Добавить робота
CRest::call('bizproc.robot.add', [
    'CODE' => 'set_responsible',
    'HANDLER' => 'https://your-domain.com/robot-handler.php',
    'AUTH_USER_ID' => 1,
    'NAME' => 'Сменить ответственного',
    'PROPERTIES' => [
        'responsible' => [
            'Name' => 'Новый ответственный',
            'Type' => 'user'
        ]
    ]
]);
```

#### Работа с бизнес-процессами

```php
// Запустить бизнес-процесс для сделки
CRest::call('bizproc.workflow.start', [
    'TEMPLATE_ID' => 123,
    'DOCUMENT_ID' => ['crm', 'CCrmDocumentDeal', 456],
    'PARAMETERS' => [
        'responsible_id' => 10,
        'comment' => 'Запуск согласования'
    ]
]);

// Получить список запущенных БП
CRest::call('bizproc.workflow.instances', [
    'DOCUMENT_ID' => ['crm', 'CCrmDocumentDeal', 456]
]);

// Завершить бизнес-процесс
CRest::call('bizproc.workflow.terminate', [
    'WORKFLOW_ID' => 'abc123',
    'STATUS' => 'Terminated',
    'MESSAGE' => 'Процесс отменен'
]);
```

#### Работа с триггерами

```php
// Список триггеров для воронки
CRest::call('crm.automation.trigger.list', [
    'ENTITY_TYPE_ID' => 2, // 1-лид, 2-сделка, 3-контакт, 4-компания
    'CATEGORY_ID' => 0
]);

// Добавить триггер
CRest::call('crm.automation.trigger.add', [
    'ENTITY_TYPE_ID' => 2,
    'CATEGORY_ID' => 0,
    'CODE' => 'ACTIVITY_CREATED',
    'NAME' => 'При создании дела',
    'TARGET_STATUS_ID' => 'C2:NEW',
    'APPLY_RULES' => [
        [
            'field' => 'ACTIVITY_TYPE',
            'operator' => '=',
            'value' => '2' // Звонок
        ]
    ]
]);
```

### Webhook роботы

**Webhook** — один из самых мощных инструментов автоматизации. Позволяет вызвать внешний API при наступлении события.

```php
// Обработчик webhook на внешнем сервере
// Bitrix24 отправляет POST запрос с данными сделки

$data = json_decode(file_get_contents('php://input'), true);

$dealId = $data['document_id'][2];
$fields = $data['properties'];

// Ваша логика обработки
// Например, отправка данных в 1C, создание заказа в интернет-магазине

// Возвращаем результат
echo json_encode([
    'success' => true,
    'message' => 'Данные обработаны'
]);
```

## Вопросы для собеседования

### 1. В чем разница между роботами и бизнес-процессами?

**Ответ:**

**Роботы:**
- Простые действия
- Привязаны к стадиям воронки
- Линейная логика (последовательность действий)
- Быстрая настройка через UI
- Подходят для 90% задач автоматизации

**Бизнес-процессы:**
- Сложные сценарии
- Могут запускаться вручную или по событию
- Ветвление, условия, параллельные задачи
- Визуальный дизайнер процессов
- Для сложных согласований и многоэтапных процессов

### 2. Какие типы триггеров существуют в Bitrix24?

**Ответ:**

1. **ACTIVITY_CREATED** — создано дело (звонок, встреча, письмо)
2. **ACTIVITY_COMPLETED** — дело завершено
3. **FIELD_CHANGED** — изменено поле
4. **RESPONSIBLE_CHANGED** — изменен ответственный
5. **INACTIVITY_PERIOD** — нет активности N дней
6. **DEADLINE_EXPIRED** — истек срок задачи
7. **DOCUMENT_VIEWED** — документ просмотрен
8. **INVOICE_PAID** — счет оплачен

### 3. Как создать пользовательского робота через REST API?

**Ответ:**

Шаги:
1. Зарегистрировать робота через `bizproc.robot.add`
2. Указать URL обработчика (`HANDLER`)
3. Определить входные параметры (`PROPERTIES`)
4. Реализовать обработчик, который принимает данные и возвращает результат

```php
// Регистрация робота
CRest::call('bizproc.robot.add', [
    'CODE' => 'send_to_1c',
    'HANDLER' => 'https://my-app.com/robot/send-to-1c',
    'AUTH_USER_ID' => 1,
    'NAME' => 'Отправить в 1С',
    'PROPERTIES' => [
        'sync_mode' => [
            'Name' => 'Режим синхронизации',
            'Type' => 'select',
            'Options' => [
                'full' => 'Полная',
                'partial' => 'Частичная'
            ],
            'Required' => 'Y',
            'Default' => 'full'
        ]
    ],
    'RETURN_PROPERTIES' => [
        'success' => [
            'Name' => 'Успешно',
            'Type' => 'bool'
        ],
        'external_id' => [
            'Name' => 'ID в 1С',
            'Type' => 'string'
        ]
    ]
]);
```

### 4. Что приходит в webhook при срабатывании робота?

**Ответ:**

```json
{
  "auth": {
    "access_token": "...",
    "domain": "company.bitrix24.ru"
  },
  "document_id": ["crm", "CCrmDocumentDeal", "123"],
  "document_type": ["crm", "CCrmDocumentDeal", "DEAL"],
  "properties": {
    "field1": "value1",
    "field2": "value2"
  },
  "event_token": "abc123"
}
```

### 5. Как правильно обрабатывать ошибки в роботах?

**Ответ:**

```php
// Возвращаем структурированный ответ
if ($error) {
    echo json_encode([
        'success' => false,
        'error' => 'ERROR_CODE',
        'error_description' => 'Подробное описание ошибки',
        'return_values' => [
            'error_details' => 'Дополнительная информация'
        ]
    ]);
    exit;
}

// При успехе
echo json_encode([
    'success' => true,
    'return_values' => [
        'result_field' => 'значение'
    ]
]);
```

**Best practices:**
- Всегда возвращать JSON с полем `success`
- Логировать все запросы и ответы
- Таймаут обработчика должен быть < 30 секунд
- Использовать очереди для длительных операций

### 6. Как работают задержки в бизнес-процессах?

**Ответ:**

Задержки позволяют приостановить выполнение процесса на определенное время:

```php
// В бизнес-процессе можно использовать элемент "Задержка"
// Типы задержек:

1. Фиксированная дата/время:
   - До 2024-12-31 15:00

2. Относительная (от текущего момента):
   - Через 1 день
   - Через 2 часа

3. Относительная (от поля сущности):
   - До даты закрытия сделки
   - За 1 день до дедлайна

4. Условная (до наступления события):
   - До изменения поля
   - До создания дела
```

**Важно:** Задержки работают в фоновом режиме через агентов Bitrix24. Не блокируют выполнение других процессов.

### 7. Можно ли остановить или отменить запущенный бизнес-процесс?

**Ответ:**

Да, через `bizproc.workflow.terminate`:

```php
CRest::call('bizproc.workflow.terminate', [
    'WORKFLOW_ID' => 'abc123xyz',
    'STATUS' => 'Terminated',
    'MESSAGE' => 'Процесс отменен администратором'
]);
```

**Статусы завершения:**
- `Terminated` — принудительно завершен
- `Completed` — успешно завершен
- `Errors` — завершен с ошибками

### 8. Как отладить робота или бизнес-процесс?

**Ответ:**

1. **Логирование в обработчике:**
```php
file_put_contents('/tmp/robot.log', 
    date('Y-m-d H:i:s') . ' ' . json_encode($_POST) . "\n", 
    FILE_APPEND
);
```

2. **Просмотр журнала выполнения:**
   - CRM → Настройки → Автоматизация → История выполнения
   - Там видно все запущенные роботы, их статус и ошибки

3. **Webhook для отладки:**
   - Используйте webhook.site или requestbin.com
   - Отправляйте туда данные из робота для проверки структуры

4. **REST API для получения логов:**
```php
CRest::call('bizproc.workflow.instances', [
    'DOCUMENT_ID' => ['crm', 'CCrmDocumentDeal', 123]
]);
```

### 9. Какие ограничения есть у роботов и бизнес-процессов?

**Ответ:**

**Технические ограничения:**
- Таймаут webhook — 30 секунд
- Максимум 50 роботов на одной стадии
- Лимит REST API вызовов (зависит от тарифа)
- Бизнес-процессы не могут вызываться из других БП (только через код)

**Функциональные ограничения:**
- Роботы не видят действия других роботов на той же стадии
- Невозможно откатить изменения робота
- Триггеры работают только при движении по воронке

**Best practices для обхода ограничений:**
- Используйте очереди (RabbitMQ, Redis) для длительных операций
- Кешируйте данные, чтобы снизить количество REST запросов
- Разбивайте сложную логику на несколько стадий

### 10. В каких случаях лучше использовать триггеры вместо роботов?

**Ответ:**

**Триггеры:**
✅ Автоматическое движение по воронке
✅ Реакция на простые условия (создано дело, оплачен счет)
✅ Без дополнительных действий (только смена стадии)

**Роботы:**
✅ Нужны действия (отправка письма, создание задачи)
✅ Сложная логика с проверками
✅ Интеграция с внешними системами

**Пример:**
```
Триггер: При создании звонка → переместить в "Контакт установлен"
Робот на стадии "Контакт установлен": Отправить письмо с презентацией
```
