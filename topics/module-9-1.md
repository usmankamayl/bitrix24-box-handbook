# Модуль 9.1: Типы приложений Bitrix24

## Теория

### Что такое приложение Bitrix24

**Приложение Bitrix24** — это интеграция или расширение функционала портала, которое:
- взаимодействует с Bitrix24 через **REST API** или **вебхуки**
- может иметь собственный интерфейс (встраиваемый iframe)
- может работать как полностью внешний сервис
- публикуется через **Bitrix24.Market** или устанавливается локально

---

### Основные типы приложений

#### 1. **Встраиваемое приложение (Embedded / Local App)**

Приложение, которое работает **внутри интерфейса Bitrix24** как iframe.

**Особенности:**
- Отображается как отдельная страница в левом меню или внутри карточки CRM
- Имеет доступ к `BX24.js` — JavaScript API
- Видит текущего пользователя и контекст (ID сделки, ID лида и т.д.)
- Требует хостинг с **HTTPS**

**Примеры использования:**
- Кастомная форма в карточке сделки
- Дашборд с аналитикой по CRM
- Интеграция с внешним сервисом, отображающаяся в интерфейсе

**Как работает:**
```
Пользователь открывает страницу в Bitrix24
         ↓
Bitrix24 загружает iframe с URL приложения
         ↓
iframe получает параметры: AUTH_ID, DOMAIN, LANG, PLACEMENT_OPTIONS
         ↓
Приложение делает запросы к REST API через BX24.js или с сервера
```

---

#### 2. **Внешнее приложение (External App)**

Приложение, которое работает **полностью на внешнем сервере** и взаимодействует с Bitrix24 только через REST API.

**Особенности:**
- Нет встроенного интерфейса в Bitrix24
- Использует OAuth 2.0 для авторизации
- Может работать в фоне (cron-задачи, обработчики событий)
- Имеет доступ ко всем данным, на которые выданы права

**Примеры использования:**
- Синхронизация данных между Bitrix24 и 1С
- Импорт лидов из внешнего источника
- Автоматическая генерация отчетов и отправка на email

**Как работает:**
```
Внешнее приложение
         ↓
Запрос к Bitrix24 REST API с access_token
         ↓
Bitrix24 возвращает данные (лиды, сделки, контакты)
         ↓
Приложение обрабатывает и сохраняет
```

---

#### 3. **Виджет (Widget)**

Виджет — это **упрощенный тип приложения**, который размещается в конкретной зоне интерфейса Bitrix24 через **Placement API**.

**Особенности:**
- Ограниченный размер и функционал
- Размещается в определенной "точке" интерфейса (placement)
- Быстрая разработка — минимум кода
- Может быть частью более крупного приложения

**Примеры использования:**
- Кнопка "Отправить в Telegram" в карточке сделки
- Вкладка "Дополнительные данные" в лиде
- Панель с рекомендациями в контакте

---

#### 4. **Бизнес-процесс активити (Custom Activity)**

Кастомный шаг для бизнес-процессов и роботов Bitrix24.

**Особенности:**
- Появляется в конструкторе бизнес-процессов как отдельный блок
- Получает параметры от предыдущих шагов
- Возвращает результат для следующих шагов
- Зарегистрирован через `bizproc.activity.add`

**Примеры использования:**
- "Отправить SMS через внешний шлюз"
- "Создать документ в Google Docs"
- "Проверить клиента по базе ФНС"

---

#### 5. **Чат-бот (Chatbot)**

Приложение для автоматизации общения в чатах и открытых линиях Bitrix24.

**Особенности:**
- Использует **ImBot API**
- Может отвечать на сообщения, создавать лиды, запускать бизнес-процессы
- Требует регистрации через `imbot.register`

---

### Сравнительная таблица

| Тип | Интерфейс в B24 | Авторизация | Контекст | Использование |
|-----|-----------------|-------------|----------|---------------|
| **Встраиваемое** | iframe | OAuth / AUTH_ID | Знает текущую сущность | Формы, дашборды |
| **Внешнее** | Нет | OAuth 2.0 | Нет контекста | Синхронизация, фоновые задачи |
| **Виджет** | iframe (placement) | AUTH_ID | Контекст placement | Кнопки, доп. панели |
| **Активити** | Конструктор БП | Incoming webhook | Параметры БП | Автоматизация |
| **Чат-бот** | Чат | OAuth + Bot API | Диалог | Ответы на сообщения |

### Скоупы (права доступа)

При регистрации приложения нужно указать **скоупы** — разрешения на доступ к данным.

**Основные скоупы:**

- `crm` — доступ к CRM (лиды, сделки, контакты, компании)
- `task` — задачи и проекты
- `user` — пользователи и структура компании
- `im` — мессенджер и чат
- `disk` — диск и файлы
- `calendar` — календари
- `telephony` — телефония
- `bizproc` — бизнес-процессы
- `placement` — размещение виджетов
- `entity` — хранилище данных (Entity)

**Пример регистрации с несколькими скоупами:**
```
Scope: crm,task,user,placement
```

---

### Жизненный цикл приложения

#### 1. Разработка
- Создаешь приложение в **Bitrix24.Market** или локально
- Получаешь `CLIENT_ID` и `CLIENT_SECRET`
- Настраиваешь redirect URI и разрешения

#### 2. Тестирование
- Устанавливаешь на тестовый портал (cloud.bitrix24.ru или коробка)
- Проверяешь работу REST API и интерфейса
- Отладка через логи и console.log

#### 3. Публикация
- Отправляешь на модерацию в Bitrix24.Market
- Указываешь описание, скриншоты, видео
- Проходишь модерацию (обычно 1–3 дня)

#### 4. Установка пользователями
- Пользователь находит приложение в Маркете
- Нажимает "Установить" → соглашается на права
- Приложение получает токены и начинает работу

#### 5. Обновление
- Загружаешь новую версию в Маркет
- У пользователей обновляется автоматически

---

### Режимы работы приложения

#### **Серверное (backend-only)**
- Нет интерфейса
- Обработчики событий, cron-задачи, webhooks
- Пример: синхронизация CRM с ERP

#### **Клиентское (frontend-only)**
- Только iframe-интерфейс
- Все запросы через `BX24.js` → прямые вызовы REST API
- Пример: дашборд со статистикой

#### **Гибридное (full-stack)** ⭐ чаще всего
- iframe-интерфейс + серверный backend
- Клиентская часть через `BX24.js`
- Серверная часть через REST API с OAuth
- Пример: виджет в сделке + обработчик события обновления

## Вопросы для собеседования

### Q1: Чем отличается встраиваемое приложение от внешнего?

**Ответ:**
- **Встраиваемое** — работает внутри интерфейса Bitrix24 как iframe, имеет доступ к контексту (текущая сделка, лид), использует `BX24.js` для взаимодействия с UI.
- **Внешнее** — полностью на сервере разработчика, нет UI в Bitrix24, работает только через REST API с OAuth.

Пример встраиваемого: форма в карточке сделки.
Пример внешнего: синхронизация данных с 1С.

---

### Q2: Что такое виджет и чем он отличается от приложения?

**Ответ:**
**Виджет** — это упрощенный тип приложения, который размещается в конкретной зоне интерфейса через **Placement API**. Виджет ограничен по размеру и функционалу, тогда как приложение может быть более сложным и иметь несколько placement-точек.

Пример: кнопка "Отправить в WhatsApp" в сделке — это виджет. Приложение "Интеграция с WhatsApp" может включать этот виджет + обработчики событий + настройки.

---

### Q3: Как приложение получает доступ к данным Bitrix24?

**Ответ:**
1. **OAuth 2.0** — для внешних приложений. Пользователь авторизуется → приложение получает `access_token` и `refresh_token` → использует их для запросов к REST API.
2. **AUTH_ID** — для встраиваемых приложений. Bitrix24 передает временный токен в параметрах iframe → приложение использует его для запросов.
3. **Incoming webhook** — для простых интеграций. Bitrix24 генерирует постоянный URL с ключом → приложение делает запросы на этот URL.

---

### Q4: Какие скоупы нужны для работы с лидами и сделками?

**Ответ:**
Для работы с лидами и сделками нужен скоуп `crm`. Если нужны дополнительные данные:
- `user` — для информации о пользователях
- `task` — если нужно создавать задачи из сделок
- `bizproc` — если нужно запускать бизнес-процессы

Пример регистрации:
```
Scope: crm,user,task
```

---

### Q5: Как работает Placement API?

**Ответ:**
**Placement API** позволяет разместить виджет приложения в конкретной точке интерфейса Bitrix24. Точки называются **плейсментами** (placements).

Популярные плейсменты:
- `CRM_DEAL_DETAIL_TAB` — вкладка в карточке сделки
- `CRM_LEAD_DETAIL_TOOLBAR` — панель инструментов в лиде
- `CALL_CARD` — карточка звонка

Приложение регистрирует placement через `placement.bind`, указывает URL обработчика → когда пользователь открывает сделку, Bitrix24 загружает iframe с виджетом.

---

### Q6: Что такое AUTH_ID и как его использовать?

**Ответ:**
**AUTH_ID** — это временный токен доступа, который Bitrix24 передает встраиваемому приложению при загрузке iframe.

**Как использовать:**
1. Приложение получает `AUTH_ID` из URL параметров iframe
2. Сохраняет его (обычно в localStorage или передает на сервер)
3. Использует для вызова REST API:
   ```javascript
   BX24.callMethod('crm.lead.get', {id: 123}, function(result) {
       console.log(result.data());
   });
   ```

Срок жизни: ~1 час. Если истек — нужно обновить страницу или использовать `refresh_token` (если сохранили при установке).

---

### Q7: Как работает внешнее приложение без интерфейса?

**Ответ:**
Внешнее приложение работает полностью на сервере разработчика и взаимодействует с Bitrix24 только через REST API.

**Пример flow:**
1. Пользователь устанавливает приложение → Bitrix24 отправляет OAuth-токены на сервер
2. Приложение сохраняет `access_token` и `refresh_token` в БД
3. Cron-задача на сервере запускается каждые 15 минут
4. Приложение вызывает `crm.lead.list` для получения новых лидов
5. Обрабатывает данные и сохраняет в свою БД

**Обработчики событий:**
- Регистрируешь webhook через `event.bind` на событие `onCrmLeadAdd`
- Когда создается лид → Bitrix24 отправляет POST на URL приложения
- Приложение обрабатывает данные

---

### Q8: Какие ограничения есть у встраиваемых приложений?

**Ответ:**
1. **HTTPS обязателен** — iframe загружается только по HTTPS
2. **CSP-заголовки** — нельзя использовать inline-скрипты без `nonce`
3. **Размер iframe** — ограничен интерфейсом Bitrix24
4. **Срок жизни AUTH_ID** — ~1 час, потом нужно обновить
5. **Cookie-блокировки** — в Safari и Firefox могут быть проблемы с third-party cookies

---

### Q9: Как создать бизнес-процесс активити?

**Ответ:**
1. Регистрируешь приложение в Bitrix24
2. Вызываешь метод `bizproc.activity.add`:
   ```php
   CRest::call('bizproc.activity.add', [
       'CODE' => 'SEND_SMS',
       'NAME' => 'Отправить SMS',
       'DESCRIPTION' => 'Отправка SMS через Twilio',
       'HANDLER' => 'https://your-domain.com/activity-handler.php',
       'RETURN_PROPERTIES' => [...],
       'PROPERTIES' => [...]
   ]);
   ```
3. Создаешь обработчик `activity-handler.php`, который принимает параметры и выполняет логику
4. Возвращаешь результат через `bizproc.activity.complete`

Активити появится в конструкторе бизнес-процессов.

---

### Q10: Как опубликовать приложение в Bitrix24.Market?

**Ответ:**
1. Создаешь приложение в **dev.bitrix24.ru/marketplace**
2. Настраиваешь параметры (название, описание, скоупы, redirect URI)
3. Разрабатываешь и тестируешь на тестовом портале
4. Заполняешь карточку приложения:
   - Описание на русском и английском
   - Скриншоты (минимум 3, размер 1200×800)
   - Видео-демо (опционально)
   - Категория
   - Цена (бесплатно или платная подписка)
5. Отправляешь на модерацию
6. Проходишь проверку (1–3 дня)
7. Приложение публикуется в Маркете

**Требования к публикации:**
- HTTPS для всех URL
- Политика конфиденциальности (Privacy Policy URL)
- Контакты поддержки
- Корректная работа всех заявленных функций

## Частые ошибки

### Ошибка 1: Приложение не загружается в iframe

**Причина:** HTTP вместо HTTPS или неправильные CSP-заголовки.

**Решение:**
```php
header('Content-Security-Policy: frame-ancestors https://*.bitrix24.ru https://*.bitrix24.com');
```

### Ошибка 2: AUTH_ID истекает

**Причина:** AUTH_ID живет ~1 час.

**Решение:** Сохраняй `refresh_token` при установке и обновляй `access_token` на сервере.

### Ошибка 3: Виджет не появляется в карточке сделки

**Причина:** Placement не зарегистрирован или неправильный код плейсмента.

**Решение:**
```php
CRest::call('placement.bind', [
    'PLACEMENT' => 'CRM_DEAL_DETAIL_TAB',
    'HANDLER' => 'https://your-domain.com/widget.php',
    'TITLE' => 'Мой виджет'
]);
```

### Ошибка 4: Внешнее приложение не получает события

**Причина:** Не зарегистрирован обработчик события или недоступен URL.

**Решение:** Проверь через `event.get` — зарегистрированы ли обработчики. Убедись, что URL отвечает HTTP 200.
