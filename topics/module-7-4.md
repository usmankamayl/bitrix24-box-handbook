# Модуль 7.4: Воронки продаж и стадии сделок в Bitrix24

## Теория

### Что такое воронка продаж?

**Воронка продаж (Sales Pipeline)** — это визуализация этапов, через которые проходит клиент от первого контакта до завершения сделки. В Bitrix24 воронка представлена набором стадий, по которым перемещаются сделки.

### Структура воронки

```
Лид → Квалификация → Предложение → Переговоры → Согласование → Закрытие
```

Каждая воронка состоит из:
- **Стадий (Stages)** — шаги продажи
- **Правил перехода** — условия движения между стадиями
- **Автоматизации** — роботы и триггеры на каждой стадии
- **Аналитики** — отчеты по конверсии

### Типы воронок в Bitrix24

#### 1. Воронки сделок (Deal Categories)

**Воронка по умолчанию** — стандартная воронка для всех сделок.

**Дополнительные воронки** — можно создавать отдельные воронки для:
- Разных направлений бизнеса (опт/розница)
- Разных продуктов (товары/услуги)
- Разных каналов продаж (онлайн/офлайн)

```php
// Каждая воронка имеет уникальный CATEGORY_ID
// CATEGORY_ID = 0 — воронка по умолчанию
// CATEGORY_ID > 0 — дополнительные воронки
```

#### 2. Туннели продаж

**Туннель** — последовательность воронок, когда сделка автоматически переходит из одной воронки в другую.

Пример: `Лиды → Квалификация → Основная продажа → Постпродажное обслуживание`

### Стадии сделок

#### Структура стадии

Каждая стадия имеет:
- **ID** — уникальный идентификатор (например, `C1:NEW`, `C1:PREPARATION`)
- **Название** — отображаемое имя
- **Цвет** — для визуализации в канбане
- **Семантика** — тип стадии (процесс/успех/провал)
- **Сортировку** — порядок отображения

#### Формат ID стадии

```
C{CATEGORY_ID}:{STATUS_ID}
```

Примеры:
- `C0:NEW` — стадия "Новая" в воронке по умолчанию (0)
- `C1:WON` — стадия "Успешно" в воронке 1
- `C2:LOSE` — стадия "Провалено" в воронке 2

#### Семантика стадий

1. **Process (P)** — рабочие стадии
   - Сделка в работе
   - Можно редактировать
   - Учитывается в прогнозах

2. **Success (S)** — успешное завершение
   - Сделка выиграна
   - Обычно `WON` или `SUCCESS`
   - Учитывается в выручке

3. **Failure (F)** — провал
   - Сделка проиграна
   - Обычно `LOSE` или `FAILED`
   - Анализ причин отказа

### REST API для работы с воронками

#### Получение списка воронок

```php
// Получить все воронки сделок
$result = CRest::call('crm.dealcategory.list');

// Результат:
[
    [
        'ID' => '0',
        'NAME' => 'Общая воронка',
        'SORT' => 500,
        'IS_LOCKED' => 'N'
    ],
    [
        'ID' => '1',
        'NAME' => 'Корпоративные клиенты',
        'SORT' => 600,
        'IS_LOCKED' => 'N'
    ]
]
```

#### Создание новой воронки

```php
$result = CRest::call('crm.dealcategory.add', [
    'fields' => [
        'NAME' => 'VIP клиенты',
        'SORT' => 700
    ]
]);

// Возвращает ID новой воронки
// ['ID' => 2]
```

#### Обновление воронки

```php
CRest::call('crm.dealcategory.update', [
    'id' => 1,
    'fields' => [
        'NAME' => 'Корпоративные продажи (B2B)',
        'SORT' => 650
    ]
]);
```

#### Удаление воронки

```php
CRest::call('crm.dealcategory.delete', [
    'id' => 1
]);
```

⚠️ **Внимание:** При удалении воронки все сделки из нее перемещаются в воронку по умолчанию!

### REST API для работы со стадиями

#### Получение стадий воронки

```php
// Все стадии конкретной воронки
$result = CRest::call('crm.dealcategory.stage.list', [
    'id' => 0 // CATEGORY_ID
]);

// Результат:
[
    [
        'STATUS_ID' => 'NEW',
        'NAME' => 'Новая',
        'SORT' => 10,
        'COLOR' => '#39A8EF',
        'SEMANTICS' => 'process'
    ],
    [
        'STATUS_ID' => 'PREPARATION',
        'NAME' => 'Подготовка документов',
        'SORT' => 20,
        'COLOR' => '#FFA900',
        'SEMANTICS' => 'process'
    ],
    [
        'STATUS_ID' => 'WON',
        'NAME' => 'Успешно реализовано',
        'SORT' => 100,
        'COLOR' => '#06D800',
        'SEMANTICS' => 'success'
    ]
]
```

#### Создание новой стадии

```php
$result = CRest::call('crm.dealcategory.stage.add', [
    'fields' => [
        'ENTITY_ID' => 'DEAL_STAGE_0', // DEAL_STAGE_{CATEGORY_ID}
        'STATUS_ID' => 'CUSTOM_STAGE',
        'NAME' => 'Дополнительная проверка',
        'SORT' => 25,
        'COLOR' => '#FF6B00',
        'SEMANTICS' => 'process'
    ]
]);
```

#### Обновление стадии

```php
CRest::call('crm.dealcategory.stage.update', [
    'id' => 'C0:NEW',
    'fields' => [
        'NAME' => 'Первичный контакт',
        'COLOR' => '#2FC6F6',
        'SORT' => 5
    ]
]);
```

#### Удаление стадии

```php
CRest::call('crm.dealcategory.stage.delete', [
    'id' => 'C0:CUSTOM_STAGE'
]);
```

⚠️ **Внимание:** Нельзя удалить финальные стадии (`WON`, `LOSE`)!

### Работа со стадиями сделки

#### Получение текущей стадии сделки

```php
$deal = CRest::call('crm.deal.get', [
    'id' => 123
]);

$stageId = $deal['STAGE_ID']; // Например, "C0:PREPARATION"
$categoryId = $deal['CATEGORY_ID']; // Например, 0
```

#### Перемещение сделки на другую стадию

```php
CRest::call('crm.deal.update', [
    'id' => 123,
    'fields' => [
        'STAGE_ID' => 'C0:WON' // Переместить в "Успешно"
    ]
]);
```

#### Перемещение между воронками

```php
// Перемещение сделки из одной воронки в другую
CRest::call('crm.deal.update', [
    'id' => 123,
    'fields' => [
        'CATEGORY_ID' => 1, // Новая воронка
        'STAGE_ID' => 'C1:NEW' // Стадия в новой воронке
    ]
]);
```

⚠️ **Важно:** При смене воронки обязательно указывать `STAGE_ID` из новой воронки!

### История перемещений по стадиям

Bitrix24 автоматически сохраняет историю всех перемещений сделки.

```php
// Получить историю изменений сделки
$timeline = CRest::call('crm.timeline.list', [
    'filter' => [
        'ENTITY_ID' => 123,
        'ENTITY_TYPE' => 'deal'
    ],
    'order' => ['ID' => 'DESC']
]);

// В истории будут записи типа "Смена стадии":
// "Сделка перемещена: Новая → Подготовка документов"
```

### Аналитика по воронке

#### Подсчет сделок на каждой стадии

```php
$stages = CRest::call('crm.dealcategory.stage.list', ['id' => 0]);

foreach ($stages['result'] as $stage) {
    $count = CRest::call('crm.deal.list', [
        'filter' => [
            'CATEGORY_ID' => 0,
            'STAGE_ID' => 'C0:' . $stage['STATUS_ID']
        ],
        'select' => ['ID']
    ]);
    
    echo $stage['NAME'] . ': ' . count($count['result']) . " сделок\n";
}
```

#### Конверсия между стадиями

```php
// Сколько сделок перешло с стадии A на стадию B
$deals = CRest::call('crm.deal.list', [
    'filter' => [
        'CATEGORY_ID' => 0,
        '>BEGINDATE' => '2024-01-01',
        '<BEGINDATE' => '2024-12-31'
    ],
    'select' => ['ID', 'STAGE_ID', 'CLOSEDATE']
]);

// Анализируем историю каждой сделки
```

### Канбан и список

Bitrix24 предоставляет два основных представления воронки:

1. **Канбан (Kanban)** — карточки сделок по колонкам-стадиям
2. **Список (List)** — табличное представление

Оба представления используют одни и те же данные стадий.

## Вопросы для собеседования

### 1. Что такое CATEGORY_ID и как он связан со стадиями?

**Ответ:**

`CATEGORY_ID` — это идентификатор воронки продаж.

- `0` — воронка по умолчанию (всегда существует)
- `1, 2, 3...` — дополнительные воронки

Стадии привязаны к воронке через формат `C{CATEGORY_ID}:{STATUS_ID}`:
- `C0:NEW` — стадия "NEW" в воронке 0
- `C1:NEW` — стадия "NEW" в воронке 1

При создании новой воронки автоматически создаются стандартные стадии:
- `NEW` (Новая)
- `PREPARATION` (Подготовка документов)
- `WON` (Успешно)
- `LOSE` (Провалено)

### 2. Можно ли переместить сделку между разными воронками?

**Ответ:**

Да, через обновление полей `CATEGORY_ID` и `STAGE_ID`:

```php
CRest::call('crm.deal.update', [
    'id' => 123,
    'fields' => [
        'CATEGORY_ID' => 2, // Новая воронка
        'STAGE_ID' => 'C2:NEW' // Стадия из новой воронки
    ]
]);
```

**Важные моменты:**
- ⚠️ Стадия должна существовать в новой воронке
- ⚠️ Роботы старой воронки перестанут работать
- ⚠️ История остается, но привязана к старым стадиям
- ✅ Все поля сделки сохраняются

### 3. Что такое семантика стадии и зачем она нужна?

**Ответ:**

**Семантика (SEMANTICS)** определяет тип стадии:

1. **`process` (P)** — рабочая стадия:
   - Сделка активна
   - Учитывается в прогнозах
   - Можно редактировать

2. **`success` (S)** — успех:
   - Сделка выиграна
   - Учитывается в выручке
   - Влияет на конверсию

3. **`failure` (F)** — провал:
   - Сделка проиграна
   - Анализ причин отказа
   - Не учитывается в выручке

**Зачем нужна:**
- Автоматические отчеты (выручка, конверсия)
- Фильтры "Активные сделки"
- Логика роботов и триггеров
- Цветовая индикация в интерфейсе

### 4. Можно ли создать стадию с произвольным STATUS_ID?

**Ответ:**

Да, но с ограничениями:

```php
CRest::call('crm.dealcategory.stage.add', [
    'fields' => [
        'ENTITY_ID' => 'DEAL_STAGE_0',
        'STATUS_ID' => 'MY_CUSTOM_STAGE', // ✅ Можно любой
        'NAME' => 'Моя стадия',
        'SEMANTICS' => 'process'
    ]
]);
```

**Правила:**
- ✅ Латиница, цифры, подчеркивание
- ✅ Максимум 50 символов
- ❌ Не должен совпадать с существующими в этой воронке
- ❌ Нельзя использовать системные: `WON`, `LOSE`, `NEW` (если уже есть)

**Best practice:** Использовать префикс, например `CUSTOM_*` или `MY_*`

### 5. Как получить все сделки, находящиеся в активных стадиях?

**Ответ:**

Через семантику `process`:

```php
// Способ 1: Получить все process-стадии, затем фильтровать
$stages = CRest::call('crm.dealcategory.stage.list', ['id' => 0]);
$processStages = [];
foreach ($stages['result'] as $stage) {
    if ($stage['SEMANTICS'] === 'process') {
        $processStages[] = 'C0:' . $stage['STATUS_ID'];
    }
}

$deals = CRest::call('crm.deal.list', [
    'filter' => [
        'CATEGORY_ID' => 0,
        'STAGE_ID' => $processStages
    ]
]);

// Способ 2: Исключить финальные стадии
$deals = CRest::call('crm.deal.list', [
    'filter' => [
        'CATEGORY_ID' => 0,
        '!STAGE_SEMANTIC_ID' => ['S', 'F'] // Не успех и не провал
    ]
]);
```

### 6. Что происходит при удалении воронки?

**Ответ:**

При вызове `crm.dealcategory.delete`:

1. **Сделки автоматически перемещаются** в воронку по умолчанию (CATEGORY_ID = 0)
2. **Стадии пересчитываются:**
   - Если сделка была на `C1:NEW`, она станет `C0:NEW`
   - Если стадии нет в воронке по умолчанию, сделка переходит в `C0:NEW`
3. **Роботы и триггеры удаляются**
4. **История сохраняется**, но ссылки на старые стадии становятся неактивными

**Нельзя удалить:**
- ❌ Воронку по умолчанию (CATEGORY_ID = 0)
- ❌ Заблокированную воронку (IS_LOCKED = 'Y')

### 7. Как программно переместить сделку на следующую стадию?

**Ответ:**

Нужно знать текущую стадию и определить следующую по сортировке:

```php
// Получить текущую сделку
$deal = CRest::call('crm.deal.get', ['id' => 123]);
$currentStage = $deal['STAGE_ID']; // Например, "C0:NEW"
$categoryId = $deal['CATEGORY_ID'];

// Получить все стадии воронки
$stages = CRest::call('crm.dealcategory.stage.list', ['id' => $categoryId]);

// Отсортировать по SORT
usort($stages['result'], function($a, $b) {
    return $a['SORT'] <=> $b['SORT'];
});

// Найти текущую и взять следующую
$currentIndex = null;
foreach ($stages['result'] as $index => $stage) {
    if ('C' . $categoryId . ':' . $stage['STATUS_ID'] === $currentStage) {
        $currentIndex = $index;
        break;
    }
}

if ($currentIndex !== null && isset($stages['result'][$currentIndex + 1])) {
    $nextStage = 'C' . $categoryId . ':' . $stages['result'][$currentIndex + 1]['STATUS_ID'];
    
    // Переместить
    CRest::call('crm.deal.update', [
        'id' => 123,
        'fields' => ['STAGE_ID' => $nextStage]
    ]);
}
```

### 8. Можно ли изменить порядок стадий?

**Ответ:**

Да, через поле `SORT`:

```php
// Переместить стадию "Подготовка документов" выше
CRest::call('crm.dealcategory.stage.update', [
    'id' => 'C0:PREPARATION',
    'fields' => [
        'SORT' => 5 // Было 20, стало 5
    ]
]);
```

**Как работает SORT:**
- Стадии отображаются по возрастанию `SORT`
- Обычно шаг 10: 10, 20, 30...
- Можно использовать дробные: 15, 25, 35...

**Best practice:** Оставляйте запас между значениями для вставки новых стадий.

### 9. Как получить статистику по конверсии воронки?

**Ответ:**

Конверсия = (Количество сделок на стадии N+1) / (Количество сделок на стадии N)

```php
$stages = CRest::call('crm.dealcategory.stage.list', ['id' => 0]);
$stagesData = [];

foreach ($stages['result'] as $stage) {
    $stageId = 'C0:' . $stage['STATUS_ID'];
    
    $deals = CRest::call('crm.deal.list', [
        'filter' => ['STAGE_ID' => $stageId],
        'select' => ['ID']
    ]);
    
    $stagesData[] = [
        'name' => $stage['NAME'],
        'count' => count($deals['result'])
    ];
}

// Расчет конверсии
for ($i = 0; $i < count($stagesData) - 1; $i++) {
    $conversion = ($stagesData[$i]['count'] > 0) 
        ? ($stagesData[$i + 1]['count'] / $stagesData[$i]['count']) * 100 
        : 0;
    
    echo $stagesData[$i]['name'] . ' → ' . $stagesData[$i + 1]['name'] . ': ';
    echo round($conversion, 2) . "%\n";
}
```

### 10. Какие ограничения есть при работе с воронками?

**Ответ:**

**Технические ограничения:**
- Максимум 50 воронок на портал (зависит от тарифа)
- Максимум 50 стадий в одной воронке
- Нельзя удалить воронку по умолчанию (ID=0)
- Нельзя удалить финальные стадии (WON, LOSE)

**Функциональные ограничения:**
- Автоматизация (роботы/триггеры) настраивается отдельно для каждой воронки
- При переносе сделки между воронками роботы не переносятся
- История хранит ссылки на старые стадии (могут быть неактуальны)

**Best practices:**
- Не создавайте слишком много стадий (оптимально 5-10)
- Используйте семантику правильно
- Называйте стадии понятно и кратко
- Планируйте воронки до запуска (переделка сложна)
