# Модуль 5.4: Личный кабинет клиента (уровень senior)

## Теория

### Что входит в ЛК

Личный кабинет интернет-магазина — это не один компонент, а набор:

- **История заказов** — `sale.personal.order.list` (список с фильтрами, пагинацией, статусами).
- **Детали заказа** — `sale.personal.order.detail` — товары, отгрузки, оплаты, повтор заказа, отмена, печать.
- **Профиль покупателя** — `sale.personal.profile` — ФИО, адрес, телефон; профили по `PERSON_TYPE_ID`.
- **Подписки/отложенное** — отложенные товары (`DELAY` в корзине), подписка на поступление.
- **Персональные данные** — `main.profile` — смена пароля, email, имя.

Senior-уровень — не «поставил компонент и всё», а:

1. Понимает как работает авторизация и владение данными (кто чей заказ видит).
2. Умеет кастомизировать шаблоны и класс компонента без правки ядра.
3. Знает `PersonType`, `UserProps`, `OrderProps` — как связаны.
4. Понимает повтор заказа (Copying) и отмену (`Order::cancel`/`CSaleOrder::CancelOrder`).

### Модель данных

```
b_sale_order           — заказы (USER_ID → b_user)
b_sale_order_props_value — значения свойств заказа (ORDER_ID, ORDER_PROPS_ID)
b_sale_order_props     — сами свойства (NAME, CODE, PERSON_TYPE_ID, IS_PROFILE_*)
b_sale_user_props      — сохранённые профили пользователя (USER_ID, PERSON_TYPE_ID)
b_sale_person_type     — типы плательщика (физлицо/юрлицо)
```

Важные связи:

- **PersonType** — «кто покупает»: физлицо, юрлицо, ИП. От типа зависит набор свойств заказа.
- **UserProps** — сохранённые адреса/реквизиты покупателя. `IS_PROFILE_*` флаги на свойстве определяют, попадёт ли оно в профиль.
- **OrderProps** — свойства *конкретного заказа* (доставка, комментарий). При оформлении копируются из профиля или вводятся заново.

### Авторизация и разграничение доступа

- `sale.personal.order.list` показывает заказы **только текущего `USER_ID`** — `Order::getList` с фильтром `USER_ID = $USER->GetID()`.
- `sale.personal.order.detail` проверяет `$order->getUserId() === $USER->GetID()` — иначе 403.
- **Анонимный заказ** (USER_ID=NULL): уходит к залогиненному через `CSaleUserAccount`/`Sale\Fuser` — мердж fuser при авторизации (см. 5.2).
- **REST/AJAX свои эндпоинты** — не забудь `check_bitrix_sessid()` + `USER->IsAuthorized()` — иначе левая учётка увидит чужой заказ.

### Кастомизация без правки ядра

- **Шаблон** — копируем `.default` в свой, правим HTML/JS. Доступ к данным через `$arResult`.
- **ResultModifier** — `result_modifier.php` в шаблоне: дополняет `$arResult` до рендера.
- **Класс компонента** — наследуем `CBitrixPersonalOrderListComponent` и переопределяем `executeComponent()`/`prepareOrder()`. Регистрируем в `.description.php` с другим именем.
- **Эпилог `component_epilog.php`** — код, который работает даже при кешированном шаблоне — для подгрузки актуальных цен.

### Повтор заказа

```php
$order = \Bitrix\Sale\Order::load($orderId);
// копируем корзину в текущую
$newBasket = $basket->copy($order->getBasket());
// или CSaleOrder::RepeatOrder() legacy-вариант
```

- Проверка: `USER_ID` текущий = USER_ID заказа — нельзя повторять чужой.
- Цены пересчитываются **заново** — старая цена может быть недействительна (акция закончилась).
- Товары с `CAN_BUY = 'N'` или `QUANTITY = 0` — исключаются или помечаются в ответе.

### Отмена заказа

- `CSaleOrder::CancelOrder($orderId, 'Y', 'причина')` — legacy.
- D7: `$order->setField('CANCELED', 'Y'); $order->setField('REASON_CANCELED', $reason); $order->save();`
- Отмена **не равна возврату оплаты** — вернуть деньги надо отдельно через PS handler `refund()`.

### Частые ошибки

1. «Сделай ЛК» → новичок делает список через `CSaleOrder::GetList` без `USER_ID` фильтра — утечка чужих заказов.
2. Правят шаблон в `/bitrix/components/bitrix/sale.personal.order.list/` — стирается обновлением.
3. Повтор заказа без проверки `USER_ID` — можно повторить чужой.
4. Детали заказа через `$_GET['ID']` без проверки владельца — IDOR-уязвимость.
5. Собственная страница ЛК без `!$USER->IsAuthorized()` редиректа — анонимы видят пустую таблицу.
