# Модуль 8.3: Пакетные запросы (batch) и производительность

## 📚 Теория

### Что такое пакетные запросы (batch)?

Пакетные запросы (batch requests) — это способ выполнить несколько API-запросов в одном HTTP-запросе к Bitrix24. Это критически важно для производительности при работе с REST API, так как:

1. **Снижение количества операций**:
   - Вместо 100 отдельных HTTP-запросов — 1 пакетный запрос
   - Значительно меньше сетевых затрат
   - Быстрее выполнение

2. **Снижение лимитов**:
   - REST API имеет лимиты на количество запросов
   - Batch-запросы считаются как 1 запрос, внутри которого 100+ операций

3. **Улучшение надежности**:
   - Если сеть нестабильна, пакетный запрос надежнее
   - Одна ошибка не влияет на весь пакет

### Синтаксис batch-запроса

**Простой пример:**
```php
$requests = [
    'lead_1' => [
        'method' => 'crm.lead.get',
        'params' => ['ID' => 123]
    ],
    'lead_2' => [
        'method' => 'crm.lead.get',
        'params' => ['ID' => 456]
    ],
    'deal_1' => [
        'method' => 'crm.deal.get',
        'params' => ['ID' => 789]
    ]
];

$response = $bitrix24->batch($requests);
// $response['result']['result'] содержит результаты всех запросов
```

### Структура batch-запроса

```php
// Формат request: название => параметры запроса
$batch = [
    'unique_key_1' => [
        'method' => 'crм.entity.action',
        'params' => ['param1' => 'value1', ...]
    ],
    'unique_key_2' => [
        'method' => 'crm.entity.other_action',
        'params' => ['param2' => 'value2', ...]
    ]
];

// Каждый ключ уникален и используется для идентификации результата
```

### Обработка результатов batch-запроса

```php
$result = $client->batch([
    'first' => ['method' => 'crm.lead.list', 'params' => [...]],
    'second' => ['method' => 'crm.deal.get', 'params' => [...]],
]);

// Структура ответа:
// [
//     'result' => [
//         'result' => [
//             'first' => { результат первого запроса },
//             'second' => { результат второго запроса }
//         ]
//     ],
//     'time' => { время выполнения }
// ]

// Доступ к результатам:
$leadList = $result['result']['result']['first']; // Результаты лидов
$dealInfo = $result['result']['result']['second']; // Информация о сделке
```

### Ограничения batch-запросов

1. **Максимум операций в пакете**: обычно 50-100 операций за раз
2. **Время выполнения**: весь пакет должен выполниться в разумное время
3. **Размер payload**: не должен быть слишком большим
4. **Порядок выполнения**: не гарантируется в определенном порядке внутри пакета
5. **Зависимости**: если результат одного запроса нужен для другого, batch не поможет

### Когда использовать batch?

✅ **Используй batch, если:**
- Нужно получить информацию о нескольких лидах/сделках
- Нужно создать несколько объектов CRM одновременно
- Нужно обновить множество контактов с одинаковыми данными
- Нужно получить статистику по нескольким лидам

❌ **НЕ используй batch, если:**
- Результат одного запроса нужен для выполнения другого (используй halt)
- Нужна строгая последовательность операций
- Запросы зависят друг от друга (например, создать лид, получить его ID, создать сделку)

### Условное выполнение в batch (halt)

Иногда нужно остановить выполнение пакета, если один из запросов не удался. Используйте `halt`:

```php
$batch = [
    'create_lead' => [
        'method' => 'crm.lead.add',
        'params' => ['fields' => ['NAME' => 'Test']]
    ],
    'get_lead' => [
        'method' => 'crm.lead.get',
        'params' => ['ID' => '$result[create_lead][ID]'], // Используй результат из создания
        'halt' => 0 // 0 = продолжить, 1 = остановить при ошибке
    ]
];
```

### Оптимизация при работе с большим количеством данных

**Проблема:** Нужно обновить 10000 лидов.

**Неправильно:**
```php
foreach ($leads as $lead) {
    $client->call('crm.lead.update', ['ID' => $lead['ID'], 'fields' => [...]]);
}
// 10000 отдельных запросов = медленно и неэффективно
```

**Правильно:**
```php
// Разбиваем на пакеты по 50 записей
$chunks = array_chunk($leads, 50);
foreach ($chunks as $chunk) {
    $batch = [];
    foreach ($chunk as $i => $lead) {
        $batch["update_$i"] = [
            'method' => 'crm.lead.update',
            'params' => ['ID' => $lead['ID'], 'fields' => [...]]
        ];
    }
    $client->batch($batch);
}
// Вместо 10000 запросов — 200 batch-запросов
```

### Типичные ошибки при использовании batch

1. **Слишком много операций в одном пакете**
   - Лимит: обычно 50-100 операций
   - Решение: разбить на несколько пакетов

2. **Неправильное имя метода в batch**
   ```php
   // ❌ Неправильно:
   'method' => 'lead.get' // Забыли крм.
   
   // ✅ Правильно:
   'method' => 'crm.lead.get'
   ```

3. **Неправильная структура params**
   - Все параметры должны быть в 'params', а не на корневом уровне

4. **Попытка использовать результат другого запроса без halt**
   - Batch выполняется параллельно, порядок не гарантирован
   - Используйте отдельные запросы или halt

## 📋 Вопросы для собеседования

### Вопрос 1: Что такое batch-запрос и почему его использовать?

**Ответ:**
Batch-запрос — это метод выполнения нескольких API-операций в одном HTTP-запросе. 

**Преимущества:**
- Снижение количества HTTP-запросов (вместо 100 запросов — 1 batch)
- Экономия трафика и времени сетевого взаимодействия
- Соблюдение лимитов API (batch считается 1 запросом, но содержит много операций)
- Улучшение производительности при работе с большим количеством данных

**Когда использовать:**
- Получение информации о множестве лидов/сделок за раз
- Массовое обновление данных
- Импорт большого количества объектов

### Вопрос 2: Как структурируется batch-запрос?

**Ответ:**
```php
$batch = [
    'уникальный_ключ_1' => [
        'method' => 'crm.lead.get',
        'params' => ['ID' => 123]
    ],
    'уникальный_ключ_2' => [
        'method' => 'crm.deal.list',
        'params' => [...]
    ]
];

$response = $client->batch($batch);
$results = $response['result']['result']; // Результаты по ключам
```

**Важные моменты:**
- Каждая операция имеет уникальный ключ
- Ключ используется для получения результата этой операции
- Результаты возвращаются в массиве под теми же ключами

### Вопрос 3: Сколько операций можно выполнить в одном batch?

**Ответ:**
Обычно лимит составляет 50-100 операций в одном batch-запросе (точный лимит зависит от плана Bitrix24).

**Если нужно больше:**
```php
$chunks = array_chunk($operations, 50);
foreach ($chunks as $chunk) {
    // Выполнить batch для каждого чанка
    $response = $client->batch($chunk);
}
```

### Вопрос 4: Как использовать результат одного запроса в другом внутри batch?

**Ответ:**
Используйте ссылку на результат другого запроса в виде строки `$result[ключ]`:

```php
$batch = [
    'create_lead' => [
        'method' => 'crm.lead.add',
        'params' => ['fields' => ['NAME' => 'New Lead']]
    ],
    'create_deal' => [
        'method' => 'crm.deal.add',
        'params' => [
            'fields' => [
                'TITLE' => 'Deal for Lead',
                'CONTACT_ID' => '$result[create_lead][ID]' // Используй ID лида
            ]
        ]
    ]
];
```

**Важно:** Когда вы ссылаетесь на результат другого запроса, нужно установить `'halt' => 1` в зависимом запросе, чтобы он не выполнялся до получения результата.

### Вопрос 5: Какая разница между batch и отдельными запросами с точки зрения лимитов?

**Ответ:**
- **Отдельные запросы**: каждый считается за 1 запрос. 100 запросов = 100 операций в лимите
- **Batch-запрос**: весь пакет считается за 1 запрос независимо от количества операций в нем

**Пример лимитов:**
- Лимит: 500 запросов в сутки
- 100 отдельных запросов к лидам — 100 из 500 лимита потрачено
- 1 batch-запрос с 100 операциями — только 1 из 500 лимита потрачено

Это критически важно для массовой обработки данных.

### Вопрос 6: Когда batch-запрос неэффективен?

**Ответ:**
- Когда есть зависимость между операциями (результат одного нужен для другого)
- Когда нужна строгая последовательность выполнения
- Когда обработка ошибок требует прерывания операций
- Когда нужна поддержка транзакций (откат всех изменений при ошибке)

В этих случаях используйте отдельные запросы или halt-механизм.

### Вопрос 7: Как обработать ошибку в batch-запросе?

**Ответ:**
```php
$result = $client->batch($batch);

if (isset($result['error'])) {
    // Ошибка batch-запроса целиком
    echo "Ошибка batch: " . $result['error'];
} else {
    $results = $result['result']['result'];
    
    // Проверяем каждый результат
    foreach ($results as $key => $data) {
        if (isset($data['error'])) {
            echo "Ошибка в $key: " . $data['error'];
        } else {
            // Успешный результат
            $id = $data['result'] ?? $data['ID'] ?? null;
        }
    }
}
```

### Вопрос 8: Как импортировать 10000 лидов эффективно?

**Ответ:**
```php
$leads = [/* 10000 лидов */];

// Разбиваем на пакеты по 50 лидов
foreach (array_chunk($leads, 50) as $chunk) {
    $batch = [];
    
    foreach ($chunk as $i => $lead) {
        $batch["lead_$i"] = [
            'method' => 'crm.lead.add',
            'params' => [
                'fields' => [
                    'NAME' => $lead['name'],
                    'PHONE' => [['VALUE' => $lead['phone']]],
                    'EMAIL' => [['VALUE' => $lead['email']]]
                ]
            ]
        ];
    }
    
    $response = $client->batch($batch);
    
    // Обработка результатов
    foreach ($response['result']['result'] as $key => $result) {
        if (!isset($result['error'])) {
            $leadId = $result['result'];
            echo "Лид $leadId создан\n";
        }
    }
}
```

### Вопрос 9: Какой оптимальный размер batch-пакета?

**Ответ:**
- **Рекомендуется**: 30-50 операций за раз
- **Максимум**: обычно 50-100 (зависит от плана)
- **Очень маленькие**: 5-10 (если операции сложные или тяжелые)

**Почему не максимум?**
- Smaller batches = более быстрое выполнение
- Меньше риск timeout
- Легче обрабатывать ошибки
- Лучше для мониторинга прогресса

### Вопрос 10: Как отследить прогресс при импорте большого количества данных?

**Ответ:**
```php
$total = count($leads);
$processed = 0;
$batchSize = 50;

foreach (array_chunk($leads, $batchSize) as $chunk) {
    $batch = [];
    
    foreach ($chunk as $i => $lead) {
        // ... формирование batch
    }
    
    $response = $client->batch($batch);
    $processed += count($chunk);
    
    $percentage = round(($processed / $total) * 100, 2);
    echo "Обработано: $processed/$total ($percentage%)\n";
    
    // Или сохранить в логи/БД
    error_log("Import progress: $percentage%");
}

echo "Импорт завершен!\n";
```
